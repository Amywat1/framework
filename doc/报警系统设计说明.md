# 报警系统设计说明

**版本**：v1.0
**状态**：简单示例实现已落地并通过 sim 验证
**适用范围**：M8 洗车机控制软件报警/安全域
**架构基线**：`软件框架设计说明.md` v2.3 的安全域骨架；`domain-design.md` v0.7 仅作概念参考
**关键词**：报警分级、安全态聚合、事件驱动、Ports & Adapters、AUTO_STATIC 自清除

---

## 1. 设计目标与核心理念

报警系统负责把硬件异常转化为分级报警，聚合出整机安全姿态，驱动停机/降级并对外投影上报。

**核心理念：等级与安全态是两条独立的轴**

| | 报警等级（`alarm_level_t`） | 安全态（`safety_state_t`） |
|---|---|---|
| 回答的问题 | 「这一条故障多严重、怎么清除」 | 「当前所有活跃故障合起来机器能否运行」 |
| 性质 | 静态目录属性（写死在定义表） | 动态聚合结果（随活跃集实时变化） |
| 归属 | 单条报警实例 | 整机姿态 |
| 消费者 | 上报、日志、（将来）服务完成评估 | 执行机构/设备 FSM（emergency_handler、device_fsm） |

安全态是「聚合 + 解耦」层：执行机构只消费安全态、不感知具体报警码与等级；报警目录怎么扩，安全反应代码不动。聚合语义（LOCKOUT 在首条 CRITICAL 触发时置位、末条 CRITICAL 清除时才解除）收口在 `safety_fsm`，下游不必各自维护「还剩几条 critical」。

## 2. 分层归属与依赖方向

```
adapters/machine/m8/m8_alarm_adapt   ← 硬件信号→报警码（机型适配）
        │ ports/safety/alarm_binding_port（trigger/clear）
        ▼
domain/safety/alarm_core             ← 报警权威事实源（活跃集 + 等级聚合）
        │ 发布 EVT_ALARM_TRIGGERED / EVT_ALARM_CLEARED
        ▼
domain/safety/safety_fsm             ← 安全态推导（OK/WARNING/LOCKOUT）
        │ 发布 EVT_SAFETY_LOCKOUT / WARNING / CLEARED
        ▼
application/orchestrators/
  emergency_handler（已有）           ← LOCKOUT → 停输出 + abort
  device_fsm（已有）                  ← LOCKOUT → 设备转 FAULT
  safety_supervisor（新增）           ← 写 dev_ctx 安全态/报警码
        │
        ▼
service/dev_ctx → report_aggregator → 云上报 / CLI 查询
```

依赖严格单向：`adapters/machine` 只依赖 `ports/safety` 与 `domain/model`（共享类型），不直接 include `domain/safety` 实现；`domain/safety` 不依赖任何 adapter；`domain` 不写 dev_ctx，由 application 层的 `safety_supervisor` 投影。

## 4. 数据模型

`domain/model/alarm_code.h`：

```c
/* 等级：数值越大越严重，聚合时取最高 */
typedef enum { ALARM_LEVEL_MINOR = 0, ALARM_LEVEL_MAJOR, ALARM_LEVEL_CRITICAL } alarm_level_t;

/* 清除方式：本期仅 AUTO_STATIC（条件消失自动清除） */
typedef enum { ALARM_CLEAR_AUTO_STATIC = 0 } alarm_clear_t;

/* 报警码：高 8 位模块 ID（0x02 设备 / 0x04 安全）+ 低位编号 */
typedef enum {
    ALARM_CODE_NONE                = 0x000000U,
    ALARM_CODE_SIDE_BRUSH_OVERLOAD = 0x020001U,
    ALARM_CODE_FAN_FAULT           = 0x020002U,
    ALARM_CODE_ESTOP               = 0x040001U,
} alarm_code_t;

/* 报警定义（静态配置项） */
typedef struct {
    uint32_t      code;
    alarm_level_t level;
    alarm_clear_t clear;
    const char   *desc;
} alarm_def_t;
```

`domain/model/safety_types.h`：

```c
typedef enum { SAFETY_STATE_OK = 0, SAFETY_STATE_WARNING, SAFETY_STATE_LOCKOUT } safety_state_t;
```

等级 → 安全态映射：CRITICAL→LOCKOUT，MAJOR→WARNING，MINOR 或无活跃报警→OK。

## 5. 核心模块详述

### 5.1 alarm_core — 报警核心引擎（domain/safety）

报警的**权威事实源**。内部状态：

```c
static const alarm_def_t s_alarm_defs[] = {
    { ALARM_CODE_ESTOP,               ALARM_LEVEL_CRITICAL, ALARM_CLEAR_AUTO_STATIC, "急停按钮触发" },
    { ALARM_CODE_SIDE_BRUSH_OVERLOAD, ALARM_LEVEL_MAJOR,    ALARM_CLEAR_AUTO_STATIC, "侧刷电机过载" },
    { ALARM_CODE_FAN_FAULT,           ALARM_LEVEL_MINOR,    ALARM_CLEAR_AUTO_STATIC, "风机报警反馈" },
};
static bool            s_active[ALARM_DEF_COUNT];  /* 活跃集，与定义表同下标 */
static pthread_mutex_t s_mutex;                    /* 保护活跃集 */
```

接口：

| 接口 | 行为 |
|------|------|
| `alarm_core_trigger(code)` | 查表（未知码 `SW_ERR_PARAM`+告警）；持锁置位；**仅状态翻转时**发 `EVT_ALARM_TRIGGERED`（param=码）。重复触发幂等 |
| `alarm_core_clear(code)` | 同上，翻转为清除时发 `EVT_ALARM_CLEARED`。重复清除幂等 |
| `alarm_core_safety_state()` | 持锁扫描活跃集取最高等级 → 派生安全态 |
| `alarm_core_top_code()` | 持锁返回最高等级的活跃报警码，无则 `ALARM_CODE_NONE` |
| `alarm_core_init()` | 清零活跃集，把 `{trigger, clear}` 注册进 `alarm_binding_port`（自注册） |

并发：`trigger/clear` 在 io_poll 线程调用，查询在 dispatch 线程调用，互斥锁保护活跃集。

### 5.2 alarm_binding_port — 报警绑定端口（ports/safety）

入向端口（adapter→domain），让机型适配器把「报警激活/清除」推入域内而不直接依赖 `domain/safety`：

```c
typedef struct {
    sw_err_t (*trigger)(uint32_t alarm_code);
    sw_err_t (*clear)(uint32_t alarm_code);
} alarm_binding_ops_t;
void alarm_binding_register(const alarm_binding_ops_t *ops);
const alarm_binding_ops_t *alarm_binding_get_ops(void);
```

注册/获取实现统一放在 `ports/port_registry.c`（与其它端口同范式）。端口由 `alarm_core_init()` 自注册，sim/真机两套构建都生效，无需改 wiring。

### 5.3 safety_fsm — 安全状态机（domain/safety）

把整机安全姿态从报警目录解耦。仅在 dispatch 线程访问，内部态无锁：

```c
static safety_state_t s_state = SAFETY_STATE_OK;

static void on_alarm_changed(const event_t *evt) {
    safety_state_t next = alarm_core_safety_state();  /* 向权威源查最高级 */
    if (next == s_state) return;                      /* 无跃迁不广播 */
    s_state = next;
    /* LOCKOUT→EVT_SAFETY_LOCKOUT；WARNING→EVT_SAFETY_WARNING；OK→EVT_SAFETY_CLEARED */
}
```

订阅 `EVT_ALARM_TRIGGERED` 与 `EVT_ALARM_CLEARED`（同一 handler），任一报警变化都重算聚合态，**仅安全态跃迁时**发 `EVT_SAFETY_*`。

### 5.4 m8_alarm_adapt — 机型报警绑定（adapters/machine/m8）

M8 专属「硬件信号→报警码」映射 + 轮询边沿检测：

```c
static const m8_alarm_map_t s_alarm_map[] = {
    { M8_SIG_ESTOP,               ALARM_CODE_ESTOP },
    { M8_SIG_SIDE_BRUSH_OVERLOAD, ALARM_CODE_SIDE_BRUSH_OVERLOAD },
    { M8_SIG_FAN_ALARM,           ALARM_CODE_FAN_FAULT },
};
static bool s_last_active[...];  /* 边沿检测基线，仅 io_poll 线程访问 */
```

- `m8_alarm_adapt_poll()`：对每个映射读 `m8_signal_is_active()`（已防抖稳定态），与上轮比较，**仅电平翻转时**调端口 `trigger`/`clear`。
- `m8_alarm_adapt_init()`：校验绑定端口已注册（fail-fast），复位边沿基线。
- 只依赖 `ports/safety/alarm_binding_port.h` + `domain/model/alarm_code.h` + `m8_sensor.h`。

### 5.5 safety_supervisor — 安全监督器（application）

domain 不写状态快照，由它代写 dev_ctx：

```c
on_safety(evt): EVT_SAFETY_LOCKOUT/WARNING/CLEARED → dev_ctx_set_safety_state(...)
on_alarm(evt):  EVT_ALARM_* → top = alarm_core_top_code();
                dev_ctx_set_alarm_state(top != NONE, top)
```

`EVT_ALARM_CLEARED` 时不靠事件载荷判断「是否还有别的报警」，而是回查 `alarm_core_top_code()`，保证 dev_ctx 与活跃集一致。

## 6. 事件流与线程模型

报警全链路跨两个线程：

| 阶段 | 线程 | 动作 |
|------|------|------|
| 采样+边沿检测+激活/清除 | **io_poll** | `m8_signal_filter_tick()`（防抖）→ `m8_alarm_adapt_poll()`（边沿）→ `alarm_core_trigger/clear`（改活跃集，发 EVT_ALARM） |
| 安全态推导+下游反应+投影 | **event_dispatch** | safety_fsm 收 EVT_ALARM→发 EVT_SAFETY；emergency_handler/device_fsm/safety_supervisor 收 EVT_SAFETY |

- `EVT_ALARM_*` 走普通优先级队列；`EVT_SAFETY_*` 与 ESTOP 走**高优先级队列**，dispatch 循环优先排空高优队列，保证 LOCKOUT 抢先处理。
- 在事件 handler 内发布新事件（safety_fsm 在 EVT_ALARM handler 里发 EVT_SAFETY）是合法链式入队。
- 跨线程共享数据只有 alarm_core 活跃集（互斥锁）与 dev_ctx（自带互斥锁）；safety_fsm 内部态仅 dispatch 线程访问，无锁。

## 7. 装配与初始化顺序

`core/bootstrap/bootstrap.c` 的 `bootstrap_init_application()`：

```c
alarm_core_init();        /* ① 先注册绑定端口 */
safety_fsm_init();        /* ② 订阅 EVT_ALARM_* */
safety_supervisor_init(); /* ③ 订阅 EVT_SAFETY_*/EVT_ALARM_* */
m8_alarm_adapt_init();    /* ④ 校验端口已注册（依赖①） */
emergency_handler_init(); /* 已有：订阅 EVT_SAFETY_LOCKOUT */
device_fsm_init();        /* 已有：订阅 EVT_SAFETY_LOCKOUT */
```

轮询挂钩在 `m8_sensor.c` 的 io_poll 线程循环：防抖完成后再做报警边沿检测，顺序关键。

## 9. 示例报警集与硬件映射

报警源取自 `config/machine/m8_io_table.h` 的真实 DI：

| 报警码 | DI 信号 | 等级 | 安全态 | 行为 |
|--------|---------|------|--------|------|
| 0x040001 | `ESTOP` 急停按钮 | CRITICAL | LOCKOUT | emergency_handler 停输出+abort；RUN/COMPLETE 态 device_fsm 转 FAULT |
| 0x020001 | `SIDE_BRUSH_OVERLOAD` 侧刷过载 | MAJOR | WARNING | 仅记录+上报，不停机 |
| 0x020002 | `FAN_ALARM` 风机报警反馈 | MINOR | OK | 仅记录+上报 |

信号经 `m8_signal_table` 绑定 hal_sensor 通道做防抖；清除方式统一 AUTO_STATIC——DI 复位即自动清除（M8 全数字量天然适配）。

WSL sim 构建（`BUILD_SIM=ON`）零警告（`-Werror`），8 个单元/场景测试全绿无回归。运行时经 sim 控制台注入信号，验证三等级 + 聚合升降级 + 自动清除：

| 操作 | 报警 | 安全态 | top code |
|------|------|--------|---------|
| 风机(MINOR) | TRIGGERED 0x020002 | OK | 0x020002 |
| +侧刷过载(MAJOR) | TRIGGERED 0x020001 | WARNING | 0x020001 |

| 释放急停 | CLEARED 0x040001 | 回落 WARNING | 0x020001 |

## 11. 边界与预留扩展点

本期为简单示例，以下按约定预留（代码注释已标注）：

| 项 | 现状 | 原因/后续 |
|----|------|-----------|
| `ports/safety/safety_action_port.h`（复位/failsafe 动作） | 未实现 | AUTO_STATIC 自动清除，本期不需手动复位 |
| A 类模拟量阈值检测 | 未实现 | M8 无模拟量信号 |
| device_fsm 扩 OperationalMode（MANUAL/SELF_CHECK/RECOVERING） | 未做 | 与报警闭环无关 |
| 服务完成评估（blocks_next_service，MAJOR 跑完再评估） | 未做 | 后续按「最大服务完成原则」补 |
| WARNING 态驱动动作 | 仅上报，无执行机构消费 | 等 HMI/降级策略接入 |
| 报警 DI 极性 | 侧刷过载/风机暂设高电平有效 | 按现场实际接线确认 |
