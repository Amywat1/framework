# 报警系统设计说明

**版本**：v2.0
**状态**：已落地并通过 sim 验证
**适用范围**：M8 洗车机控制软件报警/安全域
**架构基线**：`软件框架设计说明.md` v2.3 安全域骨架
**关键词**：报警分级、安全态聚合、事件驱动、Ports & Adapters、X-macro 单表、自包含滤波

---

## 1. 设计目标与核心理念

报警系统把硬件异常转化为分级报警，聚合出整机安全姿态，驱动停机/降级并对外投影上报。

**核心理念：等级与安全态是两条独立的轴**

| | 报警等级（`alarm_level_t`） | 安全态（`safety_state_t`） |
|---|---|---|
| 回答的问题 | 「这一条故障多严重、怎么清除」 | 「当前所有活跃故障合起来机器能否运行」 |
| 性质 | 静态目录属性 | 动态聚合结果（随活跃集实时变化） |
| 消费者 | 上报、日志、服务完成评估 | 执行机构/设备 FSM |

安全态是「聚合 + 解耦」层：执行机构只消费安全态，不感知具体报警码与等级；报警目录怎么扩，安全反应代码不动。

---

## 2. 分层归属与依赖方向

```
adapters/machine/m8/m8_alarm_adapt   ← 原始 DI 读取 + 自包含防抖 + 边沿检测 + 报警码映射
        │ ports/safety/alarm_binding_port（trigger / clear / load_catalog）
        ▼
domain/safety/alarm_core             ← 报警权威事实源（目录 + 活跃集 + 等级聚合）
        │ 发布 EVT_ALARM_TRIGGERED / EVT_ALARM_CLEARED
        ▼
domain/safety/safety_fsm             ← 安全态推导（OK / WARNING / LOCKOUT）
        │ 发布 EVT_SAFETY_LOCKOUT / WARNING / CLEARED
        ▼
application/orchestrators/
  emergency_handler                  ← LOCKOUT → 停输出 + abort
  device_fsm                         ← LOCKOUT → 设备转 FAULT
  safety_supervisor                  ← 写 dev_ctx 安全态/报警码
        │
        ▼
service/dev_ctx → report_aggregator → 云上报 / CLI 查询
```

依赖严格单向：`adapters/machine` 只依赖 `ports/safety` 与 `domain/model`（共享类型），不直接 include `domain/safety` 实现；`domain/safety` 不依赖任何 adapter。

## 4. 数据模型

```c
/* domain/model/alarm_code.h */
typedef enum { ALARM_LEVEL_MINOR = 0, ALARM_LEVEL_MAJOR, ALARM_LEVEL_CRITICAL } alarm_level_t;
typedef enum { ALARM_CLEAR_AUTO_STATIC = 0, ALARM_CLEAR_LATCHED } alarm_clear_t;
typedef enum { ALARM_CODE_NONE = 0U } alarm_code_t;

typedef struct {
    uint32_t      code;                 /* 6 位十进制：大类*100000 + 编号*100 + 性质 */
    alarm_level_t level;
    alarm_clear_t clear;
    char          desc[ALARM_DESC_MAX];
} alarm_def_t;

/* 大类常量（ALM_C_*）*/
#define ALM_C_POWER 1U  /* 动力硬件 */
#define ALM_C_SENSE 2U  /* 感知硬件 */
#define ALM_C_ACT   3U  /* 执行元件 */
#define ALM_C_CTRL  4U  /* 控制硬件 */
#define ALM_C_SW    9U  /* 逻辑/软件 */

/* 故障性质常量（ALM_N_*）*/
#define ALM_N_OTHER     0U  /* 其他/指令 */
#define ALM_N_OVERLOAD  1U  /* 过载/过流 */
#define ALM_N_COMM_LOST 2U  /* 通讯丢失 */
#define ALM_N_HW_FAULT  3U  /* 硬件故障 */
#define ALM_N_SIG_ERR   4U  /* 信号异常 */
#define ALM_N_TIMEOUT   5U  /* 动作超时 */
#define ALM_N_PRESSURE  6U  /* 压力异常 */
#define ALM_N_LEVEL     7U  /* 液位异常 */
#define ALM_N_SAFETY    9U  /* 安全触发 */

/* domain/model/safety_types.h */
typedef enum { SAFETY_STATE_OK = 0, SAFETY_STATE_WARNING, SAFETY_STATE_LOCKOUT } safety_state_t;
```

等级 → 安全态映射：CRITICAL→LOCKOUT，MAJOR→WARNING，MINOR/无报警→OK。

## 5. 核心模块详述

### 5.1 alarm_core — 报警核心引擎（domain/safety）

报警的**权威事实源**，内部维护两张表：

```
s_catalog[ALARM_CATALOG_MAX]   报警定义（由 load_catalog 写入）
s_active[ALARM_CATALOG_MAX]    活跃集（与定义表同下标；互斥锁保护）
```

接口：

| 接口 | 行为 |
|------|------|
| `alarm_core_trigger(code)` | 查表（未知码 SW_ERR_PARAM）；持锁置位；**仅状态翻转时**发 EVT_ALARM_TRIGGERED。重复触发幂等 |
| `alarm_core_clear(code)` | LATCHED 报警直接忽略（返回 SW_OK）；AUTO_STATIC 报警翻转为清除时发 EVT_ALARM_CLEARED。重复清除幂等 |
| `alarm_core_reset_alarms()` | 强制清除所有活跃报警（含 LATCHED），发一次 EVT_ALARM_CLEARED 触发安全态重聚合。由 CMD_RESET_FAULT 调用 |
| `alarm_core_load(defs, count)` | 整表替换目录，同时清空活跃集；仅 init 阶段（poll 前）调用 |
| `alarm_core_safety_state()` | 持锁扫描活跃集，取最高等级 → 派生安全态 |
| `alarm_core_top_code()` | 持锁返回最高等级活跃报警码，无则 ALARM_CODE_NONE |
| `alarm_core_init()` | 注册 alarm_binding_port（含 load_catalog）；目录初始为空 |

并发：`trigger/clear` 在 io_poll 线程调用，查询在 dispatch 线程，互斥锁保护活跃集。

### 5.2 alarm_binding_port — 报警绑定端口（ports/safety）

入向端口（adapter→domain），让机型适配器与 domain 交互而不直接 include 实现：

```c
typedef struct {
    sw_err_t (*trigger)(uint32_t alarm_code);
    sw_err_t (*clear)(uint32_t alarm_code);
    sw_err_t (*load_catalog)(const alarm_def_t *defs, unsigned count);
} alarm_binding_ops_t;
```

`load_catalog` 由 `m8_alarm_adapt_init()` 在首次 poll 前调用，注入编译期静态目录。

### 5.3 safety_fsm — 安全状态机（domain/safety）

订阅 `EVT_ALARM_TRIGGERED/CLEARED`，每次收到均向 `alarm_core` 查询聚合安全态，**仅安全态跃迁时**发 `EVT_SAFETY_*`，不产生事件风暴：

```c
static void on_alarm_changed(const event_t *evt) {
    safety_state_t next = alarm_core_safety_state();
    if (next == s_state) return;   /* 无跃迁 */
    s_state = next;
    /* LOCKOUT→EVT_SAFETY_LOCKOUT；WARNING→EVT_SAFETY_WARNING；OK→EVT_SAFETY_CLEARED */
}
```

### 5.4 m8_alarm_adapt — 机型报警绑定（adapters/machine/m8）

**配置与实现分离**：报警配置数据放 `config/machine/m8_alarm_table.h`，实现逻辑在 `m8_alarm_adapt.c`。

`config/machine/m8_alarm_table.h` 定义 M8 部件编号宏（`ALM_SENSE_*`、`ALM_CTRL_*` 等）和 X-macro 总表，报警码三段均有命名：

```c
/* config/machine/m8_alarm_table.h */
#define ALM_SENSE_ESTOP          17U
#define ALM_SENSE_SIDE_BRUSH_OVL 11U
#define ALM_CTRL_FAN_VFD          3U
// ...

#define M8_HW_ALARM_TABLE(X) \
    X(M8_IO_DI_ESTOP,               true,  1U, 3U, \
      ALM_C_SENSE, ALM_SENSE_ESTOP,           ALM_N_SAFETY,   \
      ALARM_LEVEL_CRITICAL, ALARM_CLEAR_AUTO_STATIC, "急停按钮触发") \
    X(M8_IO_DI_SIDE_BRUSH_OVERLOAD, false, 3U, 3U, \
      ALM_C_SENSE, ALM_SENSE_SIDE_BRUSH_OVL,  ALM_N_OVERLOAD, \
      ALARM_LEVEL_MAJOR,    ALARM_CLEAR_LATCHED,     "侧刷电机过载") \
    X(M8_IO_DI_FAN_ALARM,           false, 3U, 3U, \
      ALM_C_CTRL,  ALM_CTRL_FAN_VFD,          ALM_N_HW_FAULT, \
      ALARM_LEVEL_MINOR,    ALARM_CLEAR_AUTO_STATIC, "风机报警反馈")
```

`m8_alarm_adapt.c` include `m8_alarm_table.h` 后展开三套数据：

- `s_alarm_defs[]`：`alarm_def_t` 数组，传给 `load_catalog`
- `s_cfg[]`：引脚/极性/防抖配置，供 `poll` 使用
- `M8_HW_ALARM_COUNT`：编译期确定的报警源数量

`m8_alarm_adapt_poll()` 直接读原始 DI（`hal_io_port.di_read()`），内部独立防抖（每路独立计数器），不依赖 `m8_sensor`，与 `m8_signal_filter_tick()` 无顺序依赖。

`m8_alarm_adapt_init()` 工作：
1. 通过 `load_catalog` 注入完整报警目录
2. 预热滤波：读取当前 DI 值，将计数器填至饱和，消除上电延迟

依赖：`ports/safety/alarm_binding_port` + `ports/hal/hal_io_port` + `config/machine/m8_alarm_table.h`。

### 5.5 safety_supervisor — 安全监督器（application）

domain 不写状态快照，由它代写 dev_ctx：

```c
on_safety(evt): EVT_SAFETY_LOCKOUT/WARNING/CLEARED → dev_ctx_set_safety_state(...)
on_alarm(evt):  EVT_ALARM_* → top = alarm_core_top_code();
                dev_ctx_set_alarm_state(top != NONE, top)
```

`EVT_ALARM_CLEARED` 时回查 `alarm_core_top_code()`，保证 dev_ctx 与活跃集一致。

## 6. 事件流与线程模型

| 阶段 | 线程 | 动作 |
|------|------|------|
| 采样 + 独立防抖 + 边沿检测 + 激活/清除 | **io_poll** | `m8_alarm_adapt_poll()` → `alarm_core_trigger/clear`（改活跃集，发 EVT_ALARM） |
| 安全态推导 + 下游反应 + 投影 | **event_dispatch** | `safety_fsm` 收 EVT_ALARM → 发 EVT_SAFETY；`emergency_handler/device_fsm/safety_supervisor` 收 EVT_SAFETY |
| 人工复位（命令通路） | **event_dispatch** | `CMD_RESET_FAULT` → `command_guard` 放行（FAULT 态或 WARNING+IDLE 态）→ EVT_CMD_RESET_FAULT → `device_fsm` 调用 `alarm_core_reset_alarms()` + 视情况转 IDLE |

- EVT_ALARM_* 走普通优先级队列；EVT_SAFETY_* 走**高优先级队列**，dispatch 循环优先排空，保证 LOCKOUT 抢先处理。
- `m8_signal_filter_tick()` 与 `m8_alarm_adapt_poll()` 在同一 io_poll 线程中顺序调用，两者相互独立，无防抖共享。

## 7. 装配与初始化顺序

`bootstrap_init_application()`：

```c
alarm_core_init();        /* ① 注册 alarm_binding_port，目录初始为空 */
safety_fsm_init();        /* ② 订阅 EVT_ALARM_* */
safety_supervisor_init(); /* ③ 订阅 EVT_SAFETY_* / EVT_ALARM_* */
m8_alarm_adapt_init();    /* ④ load_catalog 注入目录（依赖①），预热滤波 */
emergency_handler_init();
device_fsm_init();
```

④ 必须在 ① 之后、poll 线程启动前完成。

## 8. 状态投影与上报

`service/dev_ctx` 三字段（仅 `safety_supervisor` 可写）：

```c
safety_state_t safety_state;   /* OK / WARNING / LOCKOUT */
bool           has_alarm;      /* 是否有活跃报警 */
uint32_t       alarm_code;     /* 最高等级活跃报警码 */
```

`report_aggregator` 周期从 dev_ctx 快照聚合上报；CLI `state` 命令也显示这三项。

## 10. 新增报警指引

**新增硬件 DI 报警：**

| 步骤 | 文件 | 说明 |
|------|------|------|
| 1（新引脚时）| `config/machine/m8_io_table.h` | 加 `DRV_IO_DI_DEF` 行 |
| 2 | `config/machine/m8_signal_table.h/.c` | 加信号 ID + 防抖配置（供应用层使用） |
| 3 | `config/machine/m8_alarm_table.h` | `M8_HW_ALARM_TABLE` 加一行 |

步骤 3 的一行使用命名常量，同时覆盖：DI 引脚、极性、报警专用防抖参数、报警码（`ALM_C_*` + 部件编号宏 + `ALM_N_*`）、等级、清除方式、描述。若是新部件，需在同文件对应大类下先加部件编号宏。

**新增软件逻辑报警：**

在检测到故障的位置直接调用：
```c
alarm_binding_get_ops()->trigger(ALARM_CODE_MAKE(ALM_C_CTRL, ALM_CTRL_GANTRY_VFD, ALM_N_COMM_LOST));
alarm_binding_get_ops()->clear(ALARM_CODE_MAKE(ALM_C_CTRL, ALM_CTRL_GANTRY_VFD, ALM_N_COMM_LOST));
```
并在 `m8_alarm_table.h` 中为该报警补充目录条目（或在 `m8_alarm_adapt.c` 另建软件报警表并合并注入）。

`safety_fsm`、`safety_supervisor`、`emergency_handler`、`device_fsm` 一律**不需要改**。
