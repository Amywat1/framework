## 1. 设计目标与核心理念

报警子系统把硬件/流程/通讯异常转化为**可分级、可清除、可查询**的活跃报警实例，并通过事件总线驱动安全姿态与运行模式收敛。

### 1.1 设计目标

- **单一事实源**：活跃报警列表、会话 journal、pending 域事件均由 `alarm_registry` 维护。
- **端口隔离**：项目 detector 经 `alarm_binding_port` 触发/清除，不直接 `#include` registry 实现。
- **异步广播**：registry pending 队列经 `alarm_event_bridge_drain()` 转为 `EVT_ALARM_*`。
- **姿态投影**：`safety_posture` 订阅报警事件，发布 `EVT_SAFETY_LOCKOUT/NOMINAL`。
- **与运行模式解耦**：等级/响应策略在报警域；模式转移由 `op_mode_bridge` 消费安全/洗车事件（见命令网关文档 §5.4）。

### 1.2 四条独立轴

| 轴 | 回答问题 | 权威模块 |
|----|----------|----------|
| 报警等级 `alarm_level_t` | 严重度/统计 | `alarm_def_t`（静态目录） |
| 响应策略 `response_strategy_t` | 本单是否须立即停 | `alarm_def_t` |
| 安全姿态 `safety_posture_t` | 是否 LOCKOUT | `safety_posture` 聚合 |
| 运行模式 `operational_mode_t` | 允许哪些命令 | `operational_mode`（见命令网关文档） |

**禁止**用 level 单独驱动全部下游；消费者应读 `response_strategy` 与 registry 查询接口。

### 1.3 端到端事件链

```text
  项目 detector / HAL
        │ alarm_binding_port.trigger/clear
        ▼
  alarm_registry（活跃列表 + pending 队列）
        │ alarm_event_bridge_drain()（周期或 dispatch 后）
        ▼
  EVT_ALARM_TRIGGERED / CLEARED / BATCH_CLEARED
        ├─► safety_posture → EVT_SAFETY_LOCKOUT / NOMINAL
        └─► op_mode_bridge  → op_mode_on_*（见命令网关 §5.4）

  命令路径（正交）：
  side_effect_router RESET_FAULT → alarm_registry_recover_all()
  operational_mode START_WASH    → alarm_registry_has_blocking_active()
```

## 2. 分层归属与依赖方向

### 2.1 模块落位

| 层次 | 路径 | 职责 |
|------|------|------|
| **领域聚合** | `domain/safety/alarm_registry/` | catalog、active 池、journal、pending 事件 |
| **类型契约** | `domain/safety/model/alarm_types.h` | 码值、等级、清除策略、实例类型 |
| **姿态类型** | `domain/safety/model/safety_types.h` | `safety_posture_t` |
| **安全姿态** | `domain/safety/safety_posture/` | 订阅 `EVT_ALARM_*`，发布 `EVT_SAFETY_*` |
| **事件桥** | `application/alarm_event_bridge.*` | pending → `EVT_ALARM_*` |
| **入站端口** | `ports/inbound/safety/alarm_binding_port.h` | trigger/clear/load_catalog |
| **出站端口** | `ports/outbound/safety/op_mode_alarm_port.h` | 急停码识别（项目可覆盖弱符号） |
| **端口注册** | `ports/port_registry.c` | `alarm_binding_register` |

### 2.2 依赖方向

```text
projects/*/adapters/alarm（项目侧 detector / HAL）
        │ alarm_binding_port
        ▼
   domain/safety/alarm_registry
        │ pull_events
        ▼
   application/alarm_event_bridge → event_bus
        │
        ├─► domain/safety/safety_posture
        └─► application/op_mode_bridge（运行模式，见命令网关文档）
```

**依赖禁令**：

- `alarm_registry` 不得依赖 MQTT、云端或 `operational_mode`。
- `alarm_event_bridge` 不得解析报警业务语义，只做 kind → event type 映射。
- detector 不得绕过 port 直接写 registry 静态状态。

### 2.3 启动顺序契约

完整启动由 `bootstrap_run()` 编排（见 `runtime/bootstrap/bootstrap.c`）；报警相关阶段如下：

```text
bootstrap_init_infra()
    time_util_init() → event_bus_init() → wiring() → svc_param_init()
    ↓
project_safety_init()                    // 项目钩子，Demo 为空
    ↓
bootstrap_init_application()
    project_machine_setup()
    alarm_registry_init()                  → 注册 alarm_binding_port ops
    safety_posture_init()                  → 订阅 EVT_ALARM_*
    project_alarm_catalog_init()           → load_catalog（项目报警表）
    alarm_event_bridge_init()
    safety_thread_init()                   → 注册线程（尚未 start）
    operational_mode_init()
    command_gateway_init()
    self_check_service_init()
    op_mode_bridge_init()                  → 订阅 WASH/SAFETY/ALARM/HW 等
    ↓
bootstrap_init_adapters()
    ↓
bootstrap_start_threads()
    event_dispatch 线程                    → event_bus_dispatch_loop()
    project_start_threads()                → Demo：alarm_bridge 50ms 周期 drain
    scheduler_start_all()                  → safety_thread + dispatch + 周期任务
```

`safety_posture_init()` 须在 `project_alarm_catalog_init()` 之前；`op_mode_bridge_init()` 须在 `operational_mode_init()` 之后、`scheduler_start_all()` 之前。

## 4. 数据模型

### 4.1 报警定义（alarm_def_t）

| 字段 | 说明 |
|------|------|
| `code` | 6 位报警码（见 `ALARM_CODE_MAKE`） |
| `level` | MINOR / MAJOR / CRITICAL |
| `response` | LOG_ONLY / COMPLETE_THEN_ASSESS / STOP_IMMEDIATELY |
| `clear` | AUTO_STATIC / ON_MOTION / MANUAL_RESET |
| `reeval_group` | ON_MOTION 重评估分组 |
| `immediate_cutout` | Comm 类是否硬切断（项目配置） |

### 4.2 域事件（alarm_domain_event_t）

| kind | 桥接为 |
|------|--------|
| `ALARM_DOMAIN_EVT_TRIGGERED` | `EVT_ALARM_TRIGGERED`（param=code） |
| `ALARM_DOMAIN_EVT_CLEARED` | `EVT_ALARM_CLEARED` |
| `ALARM_DOMAIN_EVT_BATCH_CLEARED` | `EVT_ALARM_BATCH_CLEARED` |

### 4.3 安全姿态（safety_posture_t）

| 值 | 含义 | 推导规则 |
|----|------|----------|
| `SAFETY_POSTURE_NOMINAL` | 无 STOP_IMMEDIATELY 活跃报警 | 默认 |
| `SAFETY_POSTURE_LOCKOUT` | 存在 `response==RESP_STOP_IMMEDIATELY` 的活跃报警 | `alarm_registry_safety_posture()` |

`safety_posture` 在姿态变化时发布 `EVT_SAFETY_LOCKOUT` 或 `EVT_SAFETY_NOMINAL`。

### 4.4 容量常量（编译期）

| 宏 | 默认值 | 说明 |
|----|--------|------|
| `ALARM_CATALOG_MAX` | 64 | 静态目录上限 |
| `ALARM_ACTIVE_MAX` | 32 | 活跃池上限 |
| `ALARM_PENDING_EVENT_MAX` | 32 | pending 队列深度 |
| `ALARM_SESSION_JOURNAL_MAX` | 16 | 洗车会话 journal |

活跃池满时：尝试驱逐最低 MINOR；仍满则插入 overflow 元报警或返回 `SW_ERR_OVERFLOW`。

## 5. 核心模块行为契约

### 5.1 alarm_registry API 摘要

| API | 行为要点 |
|-----|----------|
| `alarm_registry_load_catalog(defs, count)` | 重置 active/pending；自动追加 overflow 元报警定义 |
| `alarm_registry_trigger(code)` | 未知码 `SW_ERR_PARAM`；已 active 幂等 `SW_OK` |
| `alarm_registry_clear(code)` | MANUAL_RESET / ON_MOTION 定义不清除（返回 `SW_OK` 无操作） |
| `alarm_registry_recover_all()` | 清除 MANUAL_RESET 与 ON_MOTION 类；跳过 `estop_skip_fn` 标记的码 |
| `alarm_registry_reevaluate_group(group)` | 清除匹配 ON_MOTION + group 的活跃报警 |
| `alarm_registry_has_blocking_active()` | 存在 level ≥ MAJOR 的活跃报警 |
| `alarm_registry_pull_events(buf, max)` | 批量取出 pending（FIFO） |
| `alarm_registry_on_wash_session_started/ended()` | 控制 session journal |

### 5.2 alarm_event_bridge

| API | 行为 |
|-----|------|
| `alarm_event_bridge_init()` | 当前无订阅，返回 `SW_OK` |
| `alarm_event_bridge_drain()` | 循环 `pull_events` 直至不足一批；映射为 `event_publish` |

**须**在 dispatch 线程或能安全调用 `event_publish` 的上下文中周期执行；registry trigger 本身不自动上总线。

### 5.3 safety_posture

- 订阅：`EVT_ALARM_TRIGGERED`、`EVT_ALARM_CLEARED`、`EVT_ALARM_BATCH_CLEARED`。
- handler 内调用 `alarm_registry_safety_posture()` 重算；变化时发布 SAFETY 类事件。
- 不维护独立报警列表，registry 为唯一事实源。

### 5.4 alarm_binding_port

```c
typedef struct {
    sw_err_t (*trigger)(uint32_t alarm_code);
    sw_err_t (*clear)(uint32_t alarm_code);
    sw_err_t (*load_catalog)(const alarm_def_t *defs, unsigned count);
} alarm_binding_ops_t;
```

实现由 `alarm_registry_init()` 注册；项目 detector 通过 `alarm_binding_get_ops()` 调用。

### 5.5 op_mode_alarm_port

- `op_mode_alarm_port_is_estop(code)`：默认弱符号返回 `false`；项目层强符号覆盖急停码判定。
- 供 `op_mode_bridge` 在 `EVT_ALARM_TRIGGERED/CLEARED` 时识别急停报警（与 `EVT_HW_ESTOP_*` 硬件路径并存）。

## 6. 与命令网关的衔接

| 衔接点 | 说明 |
|--------|------|
| START_WASH 拦截 | `operational_mode` 调用 `alarm_registry_has_blocking_active()` |
| RESET_FAULT | `side_effect_router` 调用 `alarm_registry_recover_all()` |
| 自检 | `self_check_service` 查询 `alarm_registry_safety_posture()` 与 blocking |
| PostWash 评估 | `op_mode_bridge` 在 `EVT_WASH_DONE/ABORTED` 后查 blocking + estop → `op_mode_on_post_wash_assessment` |
| LOCKOUT → EXCEPTION | `op_mode_bridge` 订阅 `EVT_SAFETY_LOCKOUT` → `op_mode_on_critical_alarm()` |

详见 `doc/命令网关设计说明.md` §5.4。

## 8. 扩展指南

### 8.1 新增报警码

1. 在项目 config 追加 `alarm_def_t` 条目。
2. `alarm_registry_load_catalog()` 加载。
3. detector 在合适时机 `trigger` / `clear`。
4. 评估 `response`、`clear`、`reeval_group` 对洗车会话与模式的影响。

### 8.2 新增 consumer

1. 优先订阅 `EVT_ALARM_*` 或 `EVT_SAFETY_*`，勿重复维护活跃列表。
2. 若需同步查询，调用 registry 查询 API（与总线正交）。

### 8.3 禁止的扩展方式

- detector 直接 `#include alarm_registry.c` 或写静态变量。
- 在 `alarm_event_bridge` 内硬编码机型分支。
- 用 `EVT_ALARM_*` param 传递指针或结构体地址。
