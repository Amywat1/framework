# 项目接入架构

## 1. 接入目标

项目接入的目标是把通用框架装配成一个具体设备实例，同时保持框架不依赖项目资产。

## 2. 必备接入点

| 接入点 | 项目职责 |
|--------|----------|
| `wiring` | 注册 storage、HAL、cloud、engine loader 等 provider |
| `project_hooks` | 承接项目生命周期逻辑 |
| target entry | 承接进程级运行时准备并调用 `bootstrap_run()` |
| target runtime | 承接外部 SDK 与 Snack runtime glue |
| machine ops | 实现命令副作用对应的项目动作 |
| alarm catalog | 注册项目报警目录 |
| safety ports | 接入急停、安全输出和安全默认态 |
| HAL binding | 绑定 IO、sensor、VFD、电机和设备控制实例 |
| cloud model | 注册项目物模型 bundle |
| engine IO binding | 绑定方案引擎使用的 signal、axis 和 output |
| config assets | 提供参数、部署配置、方案和 manifest |

## 3. 接入顺序

推荐顺序：

```text
1. 在 target entry 中完成进程级运行时准备，然后调用 bootstrap_run()
2. wiring 只注册 storage、HAL、cloud、engine loader 等 provider
3. project_configure_storage 注入参数/部署配置路径
4. project_configure_hal / project_configure_adapters 下发项目配置
5. project_bind_hal / project_bind_machine / project_bind_alarm_catalog 绑定实例、machine ops 和报警目录
6. project_validate 校验物模型、必需端口、binding 和资产一致性
7. project_init_hal / project_init_adapters 初始化依赖运行上下文的模块
8. project_register_runtime_tasks 注册 report scheduler、HAL poll、alarm bridge 等周期任务
9. project_start_runtime 仅启动无法纳入 scheduler 的项目线程
10. 进行 smoke 验证
```

## 4. 入口与 HAL 边界

真机 `app/target/` 入口只负责 Snack 进程级配置，例如日志级别、应用版本、远程调试端口，然后调用 `bootstrap_run()`。

设备 HAL 或外部 SDK 的真实初始化必须留在 provider `init` 链路内部，由 `wiring()` 注册 provider，再由 `project_configure_hal()` / `project_bind_hal()` 注入参数和实例关系，最后由 `bootstrap` 统一调用对应 `hal_*_init()`。项目层不应在入口手工调用某个 HAL SDK 初始化函数。

## 5. Demo 定位

`demo/` 是最小集成验证，不是完整产品模板。它用于证明 bootstrap、命令、急停、报警和基础 adapter 链路可工作。真机项目应基于相同接入点提供自己的绑定、配置和 provider。
