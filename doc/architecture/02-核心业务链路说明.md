# 核心业务链路说明

## 1. 命令链路

外部命令统一进入设备命令端口，经命令网关裁决后再产生副作用。

```text
Cloud / CLI / Sim
        ↓
device_command_port
        ↓
command_gateway
        ↓
operational_mode
        ↓
side_effect_router
        ↓
machine_ops / wash_orchestrator / safety action
```

命令网关负责判断当前运行模式、安全状态和命令是否合法。具体硬件动作由项目实现的 machine ops 或 HAL provider 承接。

## 2. 洗车链路

洗车流程由配置化方案驱动：

```text
engine program asset
        ↓
program loader
        ↓
wash_orchestrator
        ↓
engine_start / engine_tick
        ↓
engine_io / device_control pattern
        ↓
HAL adapter / project machine
```

框架负责解释方案、表达式求值、模板展开、tick 推进和通用联锁。具体方案文件、轮廓数据来源和执行器映射由项目提供。

## 3. 事件与状态链路

业务事实通过事件总线传播，投影模块生成只读快照：

```text
domain event
        ↓
event_bus
        ↓
application projection / bridge
        ↓
device_context
        ↓
cloud report / CLI / UI / diagnostics
```

写侧事实源仍归领域模块维护，读侧通过 snapshot 降低跨模块查询耦合。

## 4. 安全链路

硬件急停、报警触发和运行模式共同形成安全闭环：

```text
HAL / detector / project binding
        ↓
alarm binding or safety event
        ↓
alarm_registry / safety_posture
        ↓
operational_mode / command_gateway
        ↓
safety output / command deny / deferred stop
```

项目负责 detector 表、报警目录和安全 IO；框架负责报警状态机、安全姿态聚合和命令拦截。
