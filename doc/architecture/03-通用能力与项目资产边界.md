# 通用能力与项目资产边界

## 1. 判定原则

进入通用框架的能力应满足：

- 与具体机型、点位、云产品无强绑定。
- 至少具备跨项目复用价值。
- 可以通过端口、配置、provider 或 helper 表达变化。
- 不要求框架知道项目级编码表或现场部署参数。

不满足这些条件的内容留在项目侧。

## 2. 边界表

| 能力 | 通用框架提供 | 项目侧提供 |
|------|--------------|------------|
| 洗车流程 | 引擎模型、表达式、模板展开、tick 运行时、profile 查询接口 | 洗车方案 JSON、manifest、轮廓数据 provider、具体动作绑定 |
| profile / 轮廓 | 查询接口和表达式内建函数 | 采集算法、分区算法、车辆轮廓资产 |
| 报警 | registry、安全姿态、binding port、detector helper、reeval bridge | 报警目录、报警编码表、DI detector 表、项目重评估绑定 |
| 水路 | `fluid_path` 通用拓扑校验、依赖、执行器对账和阀泵时序 | 完整项目水路拓扑、阀泵点位、工艺命名 |
| HAL | 端口契约、sim 后端、部分通用 provider | 真机 IO 映射、设备地址、极性、实例 binding |
| 云端 | 点位模型、上下行 JSON、校验、变化检测 | 产品物模型表、Topic、凭证、SDK 连接参数 |
| 存储 | 参数、部署配置、方案加载端口和 JSON adapter | 参数默认值、部署文件、项目方案资产 |
| 运行时 | bootstrap、线程注册、周期任务、事件总线 | 项目启动 hooks、项目后台任务 |

## 3. 不应放入框架的内容

- 具体机型的 detector/binding 表。
- 项目级报警编码规范和完整报警目录。
- 完整水路项目拓扑。
- 完整云端物模型表。
- 具体洗车方案模板库资产。
- 具体车辆轮廓扫描算法和识别参数。

## 4. 可沉淀方式

项目能力需要复用时，优先沉淀为：

- 通用端口契约。
- 可配置模型。
- 行为 helper。
- 通用校验器。
- provider 注册机制。

只有抽象后的能力进入框架，项目数据仍留在项目侧。
