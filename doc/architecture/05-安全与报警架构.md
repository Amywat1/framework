# 安全与报警架构

## 1. 目标

安全与报警架构负责把故障检测、报警状态、运行模式和命令裁决连接起来，使设备在异常状态下进入可控姿态。

## 2. 模块分工

| 模块 | 职责 |
|------|------|
| alarm registry | 管理报警定义、活跃实例、触发、清除和重评估 |
| alarm binding port | 为项目 detector、HAL 或业务逻辑提供统一触发入口 |
| detector helper | 将项目采样后的 fault_active 边沿转换成 trigger/clear |
| reeval bridge | 根据生命周期事件触发一组报警重评估 |
| safety posture | 聚合报警和安全事件，输出设备安全姿态 |
| command gateway | 根据安全姿态和运行模式裁决命令 |

## 3. 端到端关系

```text
project detector / HAL event / business condition
        ↓
alarm binding
        ↓
alarm registry
        ↓
safety posture
        ↓
command gateway / operational mode / safety output
```

## 4. 项目边界

项目侧负责：

- 报警目录和报警编码表。
- detector 采样、极性、去抖和绑定关系。
- 项目安全 IO 和安全切断动作。
- 具体哪些 lifecycle 事件需要触发哪些报警重评估。

框架侧负责：

- 通用报警生命周期。
- 通用安全姿态聚合。
- detector 边沿 helper。
- ON_MOTION 类重评估桥接机制。
- 与命令网关和事件总线的通用衔接。
