# 通用洗车运营模型

## 1. 定位

本文给接入项目的实现者和 AI：框架规定的整机运营语义。机型空间、机构、准入条件和工艺资产由项目按文末清单声明，不写入框架。

作业核如何把运营态、订单簿和在洗占用拆开，见 `09-作业核与机型无关运行.md`。命令从哪进来，见 `02-核心业务链路说明.md`。报警等级与 LOCKOUT，见 `05-安全与报警架构.md`。项目把什么留在仓内，见 `03-通用能力与项目资产边界.md`。

## 2. 整机不是「一直在洗」

对外运行模式 8 态。同时在洗几辆不靠模式枚举表达，而靠在洗占用。故障不占独立模式，急停 / 阻断 / LOCKOUT 用旗标。

| 模式 | 含义 |
|------|------|
| `INIT` | 运行模式尚未初始化，未对外服务 |
| `STOPPED` | 停机：未就绪、刚切断或清障完，或仍有禁止接单条件 |
| `RECOVERING` | 恢复中：项目归位，并确认当时没有禁止接单报警 |
| `STANDBY` | 运营待机：可入簿、可放行 |
| `ACTIVE` | 至少一单在洗 |
| `HOLD` | 可选占位：最后一单已结束，等场区清空后再回待机 |
| `CLEARING` | 整机清障 / 排空，停止放行 |
| `SELF_CHECK` | 自检中 |

不变量：`STANDBY` 蕴含总开关开且无急停。MINOR 仅提示，可与正常态共存。

上电完成初始化后进入 `STOPPED`，总开关默认开，可直接恢复；开总开关**不会**自动归位。急停松开**不会**自动进待机。

关总开关拒新单。待机或 `HOLD` 时关闭会落到停机。清障、自检、恢复中拒绝关闭。洗车中允许关闭：不中止当前作业，只拒新单；作业结束后若本应回待机，因不变量会落到停机。关总开关是否清空已入簿订单由项目 profile 决定，默认不清。

## 3. 入簿与放行是两段

`SUBMIT_ORDER` 入簿成功即命令完成，网关不等待开洗。不要把「尚未放行」写成命令失败。

```text
SUBMIT_ORDER 入簿（总开关开、非 INIT、切断已确认；急停拒新单）
        │
        ▼
整机允许放行（STANDBY，或 ACTIVE 且占用未满）
且 项目 is_admit_ready
且 订单簿队首未过期
        │
        ▼
job_admit 放行 → start_job → ACTIVE
        │
        ▼
最后一单正常结束且无禁止接单报警
        │
        ├── hold_after_last_job → HOLD → 项目报场区清空 → STANDBY
        └── 否则 → STANDBY
```

洗完若禁止接单报警仍在：不进 `HOLD`，进停机。未放行单可取消；已放行只能中止作业。

同一 `order_id` 已在簿或在洗时，重复下单幂等成功。订单只在内存，掉电丢弃。放行规则与锁边界见 `09-作业核与机型无关运行.md`。

## 4. 三种停

| 路径 | 命令 / 原因 | 现场结果 |
|------|-------------|----------|
| 中止并清障 | `CLEAR_MACHINE`，或步骤失败等非急停中止（且 profile 要求整机清障） | 进 `CLEARING`，项目收回机构 |
| 急停 | 硬件急停 | 切断输出、进停机、中止在洗、**不自动归位**；已入簿订单保留，拒新单 |
| 全切断 | `STOP_ALL_OUTPUTS` | 切断输出、进停机、清空订单簿、中止在洗、**不清障** |

急停或全切断之后，确认现场再发恢复。恢复成功 = 项目归位做完，且当时没有禁止接单报警。

点动只在停机且未急停。强制忽略限位不是运营手段。

## 5. 报警三档

等级按行为属性定义，不靠序号大小：

| 等级 | 运营后果 |
|------|----------|
| MINOR | 仅提示，不挡开洗 |
| MAJOR | 暂停接单；洗中不打断；洗完若还在则停机 |
| CRITICAL | 立即停机（LOCKOUT） |

清除策略（条件消失、运动后重评、手动复位）与等级正交。项目提供目录和 detector，框架管生命周期与姿态。细节见 `05-安全与报警架构.md`。

没有切断确认反馈的机型，把切断视为已确认；有反馈的机型必须在确认前挡住入簿、点动、自检和恢复。

## 6. 方案编排与闭环

框架解释方案、表达式和 tick，并提供通用方案会话。选哪个方案、工位怎么走、机构怎么排，属于项目。

方案点名的是离散资源启停。贴合、仿形、工位跟随这类持续闭环由项目算法出目标，方案只负责激活和停止。哪些资源走方案、哪些走闭环，必须在项目声明里写清，不要让方案逐步点动本该闭环的轴。

同时在洗上限为 1 的机型通常同一时刻只有一条方案会话（洗车、运营归位、中止归位互斥）。连续多车机型用占用表表达并行，不要把「单会话」当成框架不变量。

## 7. 机型 profile 的产品后果

项目在 bind 时登记容量，框架不出现机型枚举。字段级约定见 `09-作业核与机型无关运行.md`。对产品叙述的影响：

- 同时在洗上限为 1：现场就是一车一洗。
- `hold_after_last_job`：洗完是「等车离开」还是立刻可接下一次。
- 排队上限和订单有效期：入簿满或过期如何失败，与放行条件无关。
- 单车中止是否整机清障：往复单通道通常要收回；连续多车通常只撤该作业。

## 8. 云端遥测不是八态

项目物模型可以把若干模式打成少数布尔量。读遥测时以运行模式为准，不要假设某一个「待机 / 停机 / 归位」点位能一对一还原 8 态。具体点位名由项目物模型生成，不在本文列出。

## 9. 项目必须声明

接入项目用一份形态声明填写下列项，不要把答案写进框架文档。

| 项 | 要回答的问题 |
|----|----------------|
| 形态 | 车动还是机构动；一次几辆；用什么把车固定（若需要） |
| 编号 | 机型、现场柜型（变体）、软件版本如何区分；禁止混用、禁止运行时切换柜型 |
| 空间 | 原点在哪一侧；位置增大朝哪；与车头 / 车尾的关系；升降等轴的数值方向 |
| 机构 | 有哪些运动件；哪些互斥；变体之间哪些能力不同 |
| 方案资源 | 工艺能点名哪些资源；哪些只走闭环或只允许停机点动 |
| 占用 | 待机、在洗、占位、归位时，谁拥有锁止 / 通道 / 刷具 |
| profile | 同时在洗、排队上限、是否 HOLD、关总开关是否清簿、中止是否整机清障、订单有效期 |
| 放行 | `is_admit_ready` 的现场条件；该条件在哪些模式下才成立 |
| 离场 | 若 HOLD：何种传感器 / 限位组合算场区清空 |
| 归位 | `home_device` / `clear_machine` 的机构顺序 |
| 切断 | 有无切断确认反馈 |
| 会话 | 方案会话是否互斥，或多工位如何并行 |
| 遥测 | 物模型如何投影运行模式（只写差异，不抄全表） |

现场店员文（会怎样、按哪个键）留在项目仓，不替代本模型和形态声明。
