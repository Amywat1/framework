# 分层架构与依赖边界

## 1. 分层目标

分层的目标是隔离变化：业务规则稳定，硬件、云端、存储格式、项目绑定和部署配置变化频繁。框架通过依赖方向约束保证业务模块可以复用。

## 2. 依赖方向

允许方向：

```text
adapter / project
        ↓
port / application
        ↓
domain
        ↓
common
```

运行时可以调用各层初始化函数，但不向领域层注入项目规则。

禁止方向：

- `domain` 依赖 `adapters`。
- `domain` 直接访问文件系统、云 SDK、Modbus 地址或 IO 编号。
- `ports` 暴露具体 SDK 类型。
- 通用框架目录引用项目名、机型名或项目点位。

## 3. Ports & Adapters

入站方向用于接收外部驱动：

```text
Cloud / CLI / UI / Sim / Test
        ↓
inbound adapter
        ↓
inbound port
        ↓
application
```

出站方向用于访问外部资源：

```text
application / domain
        ↓
outbound port
        ↓
outbound adapter
        ↓
HAL / Storage / Cloud SDK / Project Machine
```

## 4. 项目接入边界

项目侧通过以下方式接入：

- `wiring()` 注册 HAL、storage、cloud、engine loader 等 provider。
- `project_hooks` 填充项目生命周期逻辑。
- binding 表描述 IO、报警、设备实例、云点位等项目资产。
- 配置文件提供部署参数、运行参数和洗车方案。

框架侧只依赖这些接入后的通用端口。
