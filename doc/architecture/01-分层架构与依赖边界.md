# 分层架构与依赖边界

## 1. 分层目标

分层的目标是隔离变化：业务规则稳定，硬件、云端、存储格式、项目绑定和部署配置变化频繁。框架通过依赖方向约束保证业务模块可以复用。

## 2. 依赖方向

允许方向：

```text
adapter / project
        ↓
port / application
        ↓
domain
        ↓
common
```

运行时可以调用各层初始化函数，但不向领域层注入项目规则。

`observability` 是旁路设施，只依赖 `common`，不出现在上面的主链路里：任何层都可
向它发布记录，而它不回调任何层，因此不构成环。

禁止方向：

- `domain` 依赖 `adapters`。
- `domain` 直接访问文件系统、云 SDK、Modbus 地址或 IO 编号。
- `domain` 自建线程或周期任务；时序推进由调用方驱动 tick。
- `domain` 使用动态内存（方案引擎按加载期一次性分配登记豁免）。
- `ports` 暴露具体 SDK 类型。
- `adapters` 承载跨领域编排（bridge / projection / coordinator 属于 `application`）。
- 通用框架目录引用项目名、机型名或项目点位。
- `application` 依赖 `adapters` 或 `services`。
- `services` 依赖 `adapters` 或 `application`。
- `observability` 依赖 `common` 之外的任何层。

以上各条由 `scripts/check_arch_boundary.sh` 自动检查，不依赖人工 review。

### 2.1 各层允许的出向依赖

规则同时约束上层目录的出向依赖，避免出现目录级双向依赖：

| 层 | 允许依赖 |
|----|----------|
| `common` | 无（含外部格式库；点位表模型不依赖 cJSON） |
| `domain` | `common`、`ports`、`runtime`（仅 event_bus） |
| `ports` | `common`、`domain` |
| `runtime` | `common`（event_bus / scheduler）；bootstrap 作为装配器可依赖各层 |
| `services` | `common`、`domain`、`ports` |
| `application` | `common`、`domain`、`ports`、`runtime` |
| `adapters` | 以上各层 |
| `observability` | `common` |

云端物模型是 `domain/cloud/` 下的子域，不再是顶层目录。这样归置后，「domain 不
解析序列化格式」（R9b）自动覆盖它——约束由层归属决定，而不再取决于目录名是否
恰好叫 `cloud`。

序列化按层剥离，共三处：

| 位置 | 内容 |
|------|------|
| `common/point_table/point_table.h` | 点位表模型与查表，无 cJSON |
| `adapters/outbound/serialization/json/point_table_json.*` | 点位表的 JSON 编解码 |
| `adapters/outbound/cloud/cloud_point_json.*`、`cloud_model_json.*` | 物模型属性 JSON 与 `property_port` 安装 |

`property_port` 的契约参数是 JSON 载荷，实现它必须解析 JSON，故安装动作
（`cloud_model_json_install()`）在适配层，不在 `cloud_model_register()` 内。

上报策略（`report_policy_entry_t`）是 `report_scheduler` 的输入格式，由项目直接
注册到调度器，不经 `cloud_model` 转发——那条路径曾使当时的顶层 `cloud/` 反向依赖
`application/`，而彼时 R1~R10 全部通过，因为它们不约束上层目录的出向依赖。

## 3. Ports & Adapters

入站方向用于接收外部驱动：

```text
Cloud / CLI / UI / Sim / Test
        ↓
inbound adapter
        ↓
inbound port
        ↓
application
```

出站方向用于访问外部资源：

```text
application / domain
        ↓
outbound port
        ↓
outbound adapter
        ↓
HAL / Storage / Cloud SDK / Project Machine
```

## 4. 项目接入边界

项目侧通过以下方式接入：

- `wiring()` 注册 HAL、storage、cloud、engine loader 等 provider。
- `project_hooks` 填充项目生命周期逻辑。
- binding 表描述 IO、报警、设备实例、云点位等项目资产。
- 配置文件提供部署参数、运行参数和洗车方案。

框架侧只依赖这些接入后的通用端口。
