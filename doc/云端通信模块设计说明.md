# 云端通信模块设计说明

**版本**：v3.1  
**状态**：已落地  
**适用范围**：`framework/` 云端通信 + `common/point_table` + `projects/<project>/adapters/cloud/`  
**架构基线**：`doc/软件设计框架说明.md` §8.3、§14  
**关键词**：cloud_link_port、cloud_model 一次注册、cloud_point 元模型、report_scheduler、语义 dispatch

---

## 1. 设计目标与核心理念

云端通信按四层职责划分（v3.1 合并传输与连接）：

| 层 | 模块 | 回答的问题 |
|----|------|------------|
| 链路 | `cloud_link_port` + Snack link adapter | MQTT init/online/send/recv + 连接边沿 |
| 调度 | `report_scheduler` + 项目 `report_policy` | 何时 full / delta |
| 编解码 | `point_table` | id ↔ 值 ↔ JSON（传输无关） |
| 内容+路由 | `cloud_point` + `cloud_model` | 物模型字段、semantic 路由、一次注册 |

**核心理念**：链路、调度、内容三者分离；**路由**横切编解码与业务。

框架 **不得** 在 port 层定义业务上报载荷；物模型 id 与 getter/setter 由项目 `*_cloud_model` 登记，经 `cloud_model_register()` 一次注入 property/report 策略。

**非目标**：离线消息队列、publish 框架级重试、desired/reported 双通道。

---

## 2. 分层与依赖

```text
application/report_scheduler           ← 周期/事件调度（不含物模型 id）
        │ report_policy（cloud_model bundle 注入）
        │ cloud_link_port / report_port
        ▼
ports/outbound/cloud/link/             传输 + 连接边沿
ports/outbound/cloud/report/           上行 publish
ports/inbound/cloud/property_port      下行 property set + 可选 reply
        ▼
adapters/outbound/cloud/providers/     link + report adapter
adapters/inbound/cloud/providers/      recv → property_port
        ▼
framework/cloud/                       cloud_model + cloud_point
        ▼
common/point_table/                    JSON 编解码 + apply_result
        ▼
projects/<project>/adapters/cloud/     X-macro 单表 + *_cloud_register
```

依赖禁令：

- `point_table` 不感知 semantic、MQTT、command_port。
- `cloud_point` 不含具体 sts/cmd 业务含义。
- `report_scheduler` 不含物模型 id 列表。
- inbound/outbound adapter 不得各自 init MQTT（唯一 owner：`snack_cloud_link_adapter`）。

## 4. 数据模型

### 4.1 云端点位条目

```c
typedef struct {
    point_table_entry_t      base;        /* id / type / get / set */
    cloud_point_access_t     access;      /* RO / RW / WO */
    cloud_point_semantic_t   semantic;    /* TELEMETRY / DEVICE_CMD / ... */
    cloud_report_policy_t    report_policy;
    cmd_type_t               cmd_type;    /* DEVICE_CMD 专用 */
    cloud_service_fn_t       service;     /* CLOUD_SERVICE 专用 */
} cloud_point_entry_t;
```

编解码直接复用 `base`，无需双表转换。

### 4.2 物模型注册包

```c
typedef struct {
    const cloud_point_entry_t    *entries;
    size_t                        count;
    const report_policy_entry_t  *report_policies;
    size_t                        policy_count;
    cloud_property_reply_fn_t     property_reply;  /* 可选，Snack 注入 */
} cloud_model_bundle_t;
```

### 4.3 下行结果契约

```c
typedef struct {
    size_t    total_keys;
    size_t    applied;
    size_t    rejected;
    size_t    skipped_get;
    sw_err_t  first_error;
    char      first_error_id[POINT_ID_MAX];
} point_apply_result_t;
```

## 5. 核心行为

### 5.1 链路层

- `cloud_link_port.init()`：唯一 MQTT init 入口（deploy 凭证），由 `project_adapters_init()` 调用。
- `cloud_link_port.is_online()` / `poll()`：在线查询与边沿事件。
- inbound recv → `property_port`；outbound send ← `report_adapter` / reply。

### 5.2 连接与 dev_ctx

- `cloud_link_port.poll()` 由 `report_scheduler` 周期任务调用，发布 `EVT_CLOUD_*`。
- `dev_ctx.cloud_connected` 读穿 `cloud_link_port.is_online()`。

### 5.3 下行 dispatch

| semantic | 行为 |
|----------|------|
| TELEMETRY | 拒绝写 |
| DEVICE_CMD | 写 1 → `command_port.inject(cmd_type)`；写 0 忽略 |
| CLOUD_SERVICE | 调 `entry->service` |
| MANUAL_ACT | 调 `entry->base.set`（内部走 manual_guard） |

### 5.4 上报调度

- 周期策略：`periodic_task`（与 link poll、watcher 合并为同一任务）。
- 事件策略：`event_subscribe`。
- M8 报警 delta id 在 `m8_cloud_register.c` 的 `report_policy` 中注入。

### 5.5 wiring 顺序

```text
wiring():  snack_cloud_link_adapter_register()
           snack_cloud_report_adapter_register()
           snack_cloud_command_adapter_register()
           m8_cloud_register()
bootstrap: cloud_model_start_scheduler()（project_report_scheduler_init）
project_adapters_init():
           cloud_model_validate_and_watch()
           cloud_link_get_ops()->init()
```

## 7. 扩展指南

### 7.1 新增物模型点位

1. 在 `m8_cloud_points.h` 增加一行 X-macro。
2. 实现 get 或 service/set（DEVICE_CMD 只需填 `cmd_type`）。
3. 上电 `cloud_model_validate_and_watch()` 自动校验。

### 7.2 新增 provider

实现 `cloud_link_ops_t` + inbound property adapter + outbound report adapter；项目侧提供 `*_cloud_register()` bundle，无需 bind 转发层。

## 8. Phase 4 增强能力

### 8.1 ON_CHANGE 变更上报

- 点位 `report_policy = CLOUD_REPORT_ON_CHANGE`。
- `cloud_point_watcher_poll()` 在 `report_scheduler` 周期任务中执行。
- 检测到变更 → `EVT_CLOUD_POINT_DIRTY`（`param` = 点位表索引）。

### 8.2 get 失败策略

```c
cloud_point_set_get_fail_policy(CLOUD_POINT_GET_FAIL_OMIT);   /* 默认 */
cloud_point_set_get_fail_policy(CLOUD_POINT_GET_FAIL_ABORT);
cloud_point_set_get_fail_policy(CLOUD_POINT_GET_FAIL_NULL);
```

### 8.3 下行应答（可选）

- `property_port.reply_property_set`：由 bundle 注入（M8 使用 `snack_cloud_property_reply`）。
- deploy 配置 `topicPropertyReply`；未配置则静默跳过。
- 已删除独立 `property_reply_port`。

### 8.4 类型扩展

| 类型 | 说明 |
|------|------|
| `POINT_TYPE_FLOAT` | JSON number |
| 枚举 | 映射为 `POINT_TYPE_INT`，在物模型/console 对齐取值 |
