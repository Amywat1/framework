# 云端通信模块设计说明

**版本**：v2.0  
**状态**：已落地  
**适用范围**：`framework/` 云端通信 + `projects/<project>/adapters/cloud/`  
**架构基线**：`doc/软件设计框架说明.md` §7.2、§8.3、§14  
**关键词**：connection/report 双 port、点位表、上下行拆分、语义分流、事件驱动上报

---

## 1. 设计目标与核心理念

云端通信模块解决三类问题，且彼此解耦：

| 问题 | 归属 | 说明 |
|------|------|------|
| **传什么** | 项目层点位表 | 物模型字段 id、读写语义、与业务逻辑的映射 |
| **怎么编解码** | `common/point_table` | 标识符 ↔ JSON，与 MQTT/云平台无关 |
| **怎么收发** | 框架 inbound/outbound 适配器 | MQTT 连接、Topic、SDK 调用 |

**核心理念：连接、调度、内容三者分离**

| | 连接（connection port） | 调度（report_aggregator） | 内容（项目 builder + 点表） |
|---|---|---|---|
| 回答的问题 | 云端传输层是否在线 | 何时触发全量/增量上报 | JSON 里有哪些字段、值从哪来 |
| 性质 | provider 维护的连接事实 | application 层周期与事件响应 | 项目物模型与 getter/setter |
| 消费者 | dev_ctx 读穿、report_aggregator 前置检查 | report port | MQTT publish |

框架 **不得** 在 port 层定义业务上报载荷（如 `dev_state`、`gantry_pos` 等）；上报 JSON 完全由项目注入的 builder 与点位表决定。

## 2. 分层归属与依赖方向

```text
application/report_aggregator          ← 调度：周期全量、重连 resync、报警增量
        │ connection_port（只读）
        │ report_port（publish_*）
        ▼
adapters/outbound/cloud/providers/     ← connection_adapter：边沿监测 + EVT_CLOUD_*
        │                              ← report_adapter：MQTT publish + builder 回调
        ▼
adapters/runtime/<provider>/           ← SDK 传输（MQTT 连接/收发）

projects/<project>/adapters/cloud/     ← bind + model + 各域 handler
        │
        ▼
common/point_table/                    ← JSON 编解码（传输无关）

adapters/inbound/cloud/providers/      ← 下行 MQTT recv → 项目 bind
        ▼
ports/inbound/command                  ← 仅 device_cmd 语义注入
projects/<project>/adapters/manual/    ← manual_act 语义共用入口
```

依赖禁令：

- `framework/ports/` 不含 SDK 类型、Topic、物模型 id、业务字段 struct。
- `application/` 不构建 JSON、不感知物模型字段名。
- `adapters/` 不实现业务状态机；下行 set handler 内的业务逻辑属于项目层。
- `common/point_table/` 不依赖 cloud adapter，可被 CLI、HTTP 等复用。

## 4. 数据模型

### 4.1 点位表条目（common）

```c
typedef struct {
    const char     *id;      /* 物模型属性标识符 */
    point_type_t    type;    /* BOOL / INT / STRING */
    point_get_fn_t  get;     /* 上行；NULL 表示不可读 */
    point_set_fn_t  set;     /* 下行；NULL 表示只读 */
} point_table_entry_t;
```

### 4.2 connection port

```c
typedef struct {
    bool (*is_connected)(void);
} cloud_connection_ops_t;
```

### 4.3 report port

```c
typedef struct {
    sw_err_t (*publish_properties)(void);
    sw_err_t (*publish_properties_delta)(const char *const *ids, size_t count);
} cloud_report_ops_t;
```

report port **不含** `cloud_report_payload_t` 或任何框架级业务字段。JSON 内容由 wiring 注入的 builder 决定。

### 4.4 项目 builder 签名（注入 adapter）

```c
typedef sw_err_t (*cloud_report_build_fn_t)(char *buf, size_t buf_size);
typedef sw_err_t (*cloud_report_build_delta_fn_t)(const char *const *ids,
                                                   size_t count,
                                                   char *buf, size_t buf_size);
```

## 5. 核心模块详述

### 5.1 connection port — 连接事实

| 行为 | 规则 |
|------|------|
| `is_connected()` | 读 provider 传输层在线状态；未注册 port 时视为离线 |
| 边沿事件 | **仅** `snack_cloud_connection_adapter` 发布 `EVT_CLOUD_CONNECTED` / `DISCONNECTED` |
| 启动时机 | MQTT init 成功后由 `project_adapters_init()` 调用 `snack_cloud_connection_adapter_start()` |
| dev_ctx | `dev_ctx_snapshot()` 读穿 `connection_port`，**不**存连接状态副本 |

### 5.2 report port — 上报发送

| 接口 | 行为 |
|------|------|
| `publish_properties()` | 调用项目全量 builder → MQTT publish |
| `publish_properties_delta(ids, count)` | 调用项目增量 builder；builder 为 NULL 时回退全量 |
| 离线 | adapter 返回 `SW_ERR_COMM`；调用方（report_aggregator）静默跳过 |

### 5.3 report_aggregator — 上报调度

| 触发源 | 动作 |
|--------|------|
| 周期线程（`THD_CLOUD_REPORT_PERIOD_MS`） | `publish_properties()`（连接在线时） |
| `EVT_CLOUD_CONNECTED` | 立即全量 resync |
| `EVT_ALARM_TRIGGERED` / `CLEARED` | `publish_properties_delta()`（报警相关点位） |
| `report_aggregator_request_resync()` | 立即全量（供 `cmd_sync` 等 cloud_service 调用） |

report_aggregator **不得**：维护连接状态、发布 `EVT_CLOUD_*`、构建 JSON、定义物模型字段。

当前框架内置报警增量 id（项目可扩展）：`sts_dev_warning`、`sts_emergency`。

### 5.4 点位表引擎 — 编解码契约

| API | 用途 |
|-----|------|
| `point_table_to_json()` | 全量属性 JSON |
| `point_table_to_json_filtered()` | 按 id 列表增量 JSON |
| `point_table_from_json()` | 下行解析；未知 id / 类型不匹配 / 写只读点位仅告警，同条 JSON 其它属性继续处理 |

点位表约定：

- **只读点位**：`set = NULL`。
- **脉冲命令点位**：写 `1` 触发、写 `0` 无操作；上行 get 可恒返回未触发。
- 引擎不得放入 `adapters/cloud/`。

### 5.5 下行语义分流

扩展物模型时必须先归类：

| 类型 | 典型命名 | 链路 |
|------|----------|------|
| **telemetry** | `sts_*` | 只读；`get` handler |
| **device_cmd** | `cmd_home`、`cmd_custom_stop` | `command_port.inject` → `command_guard` → `device_fsm` |
| **cloud_service** | `cmd_sync` | application 接口（如 `report_aggregator_request_resync`） |
| **manual_act** | `cmd_gantry_fwd` | `manual_action` + `manual_guard` → 机构 API |

**反模式**：把所有 `cmd_*` 一律 inject 进 `command_port`。

### 5.6 事件订阅关系

| 事件 | 生产者 | 消费者 | 用途 |
|------|--------|--------|------|
| `EVT_CLOUD_CONNECTED` | connection_adapter | report_aggregator | 重连全量 resync |
| `EVT_CLOUD_DISCONNECTED` | connection_adapter | — | 日志；上报由连接检查自然跳过 |
| `EVT_ALARM_TRIGGERED` | alarm_core | report_aggregator | 报警增量上报 |
| `EVT_ALARM_CLEARED` | alarm_core | report_aggregator | 报警增量上报 |

## 6. 实现职责边界

以下逻辑固化在框架实现中：

| 实现职责 | 说明 |
|----------|------|
| 连接边沿检测与事件发布 | connection_adapter 唯一负责 |
| 上报调度策略 | 周期全量 + 重连 resync + 报警 delta |
| 离线跳过 | 未连接或未注册 port 时不发送、不刷错误日志 |
| JSON 编解码引擎 | common/point_table |
| MQTT 发送 | report_adapter |

以下行为由项目层决定，框架不得硬编码：

- 物模型字段 id、类型、读写语义
- 各点位 getter/setter 与业务映射
- 全量/增量 JSON 构建（bind 层调用 point_table）
- 手动点动准入规则（`manual_guard`）
- 报警增量应包含哪些 sts_* id（当前框架内置两项，项目扩展时改 report_aggregator 或后续抽取配置）

## 7. 命名与分层约定

| 前缀/模块 | 层级 | 含义 |
|-----------|------|------|
| `point_table_*` | framework common | 通用引擎 |
| `cloud_connection_*` / `cloud_report_*` | framework ports | 出站 port |
| `snack_cloud_*_adapter` | framework provider | Snack MQTT 适配 |
| `<proj>_cloud_*` | project | 项目云端点位与绑定 |
| `<proj>_manual_*` | project | 手动动作与守卫 |
| `sts_*` | 物模型 id（示例） | 只读遥测 |
| `cmd_*` | 物模型 id（示例） | 可写命令或脉冲 |

新增点位：**id 与云平台控制台一致**；C 函数按域命名（`get_sts_*` / `set_cmd_*`），在 `*_cloud_model.c` 登记。

## 8. 扩展指南

### 8.1 新增云平台 provider

1. 在 `adapters/outbound/cloud/providers/<name>/` 实现 connection + report adapter。
2. 在 `adapters/inbound/cloud/providers/<name>/` 实现 command adapter。
3. 项目 `*_cloud_bind` 接口保持不变，仅 wiring 改注册目标。

### 8.2 新增机型

1. 复制 cloud 目录结构，实现各域 handler。
2. 在 `*_cloud_model.c` 登记点位表。
3. wiring 注册 connection + report builder；`project_adapters_init` 启动 command + connection monitor。
4. 手动类点位复用或实现 `<proj>_manual_*`。

### 8.3 新增物模型点位

1. 确定语义类型（telemetry / device_cmd / cloud_service / manual_act）。
2. 在对应域文件实现 `get` / `set`。
3. 在 `*_cloud_model.c` 增加一行 `{ id, type, get, set }`。
4. 脉冲命令复用公共 getter（如 `get_cmd_pulse`）。

### 8.4 仿真与测试

- 单元测试可链接 `common/point_table` 与项目 cloud 源文件，直接调用 `*_cloud_build_properties()`，无需 MQTT SDK。
- 仿真未注册 cloud port 时，report_aggregator 静默跳过上报。
- connection port 未注册时，`dev_ctx.cloud_connected` 读穿为 `false`。
