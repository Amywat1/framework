# 启动契约校验模块设计

**版本**：v1.0  
**状态**：已落地（端口契约 + 资产契约）  
**最后同步代码**：2026-08-19（`runtime/ports/port_contract.*`、`application/asset_contract.*`、引擎环境显式注入）  
**适用范围**：`runtime/ports/port_contract.*`、`application/asset_contract.*`  
**架构基线**：项目声明必需项 + 启动期一次报全  
**关键词**：port_contract、asset_contract、PORT_REQ、ASSET_REQ、project_validate

---

## 1. 设计目标与核心理念

启动契约把「该项目需要哪些端口 / 资产」从框架硬编码改为项目声明，并在硬件初始化与线程启动之前一次校验完毕。

### 1.1 要解决的问题

| 缺失类型 | 无契约时的现场表现 |
|----------|-------------------|
| 端口未注册 | 启动成功，第一次业务调用才失败 |
| 资产未就位（如报警目录空） | 启动成功，`trigger` 静默失败，「设备从不报警」 |

### 1.2 分工

| 模块 | 回答的问题 | 不回答的问题 |
|------|------------|--------------|
| `port_contract` | 函数表是否已注册 | ops 字段是否完备（由各 `*_register` 拒绝） |
| `asset_contract` | 数据是否存在且非空 | 内容是否正确（如点位字段级校验仍由 `cloud_point_validate`） |

框架不内置「哪些必需」：无云项目不应被要求 `PORT_REQ_CLOUD_LINK`；不用方案引擎的项目不应被要求 `ASSET_REQ_ENGINE_IO_CATALOG`。

## 2. 分层归属与依赖方向

| 层次 | 路径 | 职责 |
|------|------|------|
| 端口契约 | `runtime/ports/port_contract.*` | `PORT_REQ_*` 位掩码与 `port_contract_validate` |
| 资产契约 | `application/asset_contract.*` | `ASSET_REQ_*` 位掩码与 `asset_contract_validate` |
| 调用点 | 项目 `project_validate()` | 声明掩码并依次调用两校验 |

```text
project_validate()
    ├─ port_contract_validate(PORT_REQ_*)
    └─ asset_contract_validate(ASSET_REQ_*)   // 须在 bind 之后（报警目录已加载）
```

`asset_contract` 独立成 CMake 目标 `wdf_asset_contract`：探测报警目录、云物模型；引擎 IO 目录由调用方将 `engine_environment_t` 显式传入校验，避免全局单例依赖。

端口注册表本身见 `runtime/ports/port_registry*.c` 与 Demo/Runtime 专篇；本篇只覆盖校验契约。

## 4. 核心行为契约

### 4.1 端口位（当前 14 位）

`PORT_REQ_HAL_IO` … `PORT_REQ_SAFETY`（见 `port_contract.h`）。新增端口在枚举末尾追加，不改既有位值。

| API | 契约 |
|-----|------|
| `port_contract_validate(required)` | `required == 0` → `SW_OK`；否则逐项检查，**全部报出**后再返回；有缺失 → `SW_ERR_NOT_INIT` |
| `port_contract_name(flag)` | 单比特名称；未知 → `"unknown"` |

### 4.2 资产位（当前 3 位）

| 位 | 就位条件 |
|----|----------|
| `ASSET_REQ_ALARM_CATALOG` | `alarm_registry_catalog_count() > 0` |
| `ASSET_REQ_CLOUD_POINT_TABLE` | `cloud_model_point_count() > 0` |
| `ASSET_REQ_ENGINE_IO_CATALOG` | 传入环境有效，且 catalog 非空、signal 或 axis 至少一项非空 |

| API | 契约 |
|-----|------|
| `asset_contract_validate(required, environment)` | 与端口契约相同：一次报全；`0` 跳过；声明 `ASSET_REQ_ENGINE_IO_CATALOG` 时校验传入环境 |
| 调用顺序 | 建议在 `port_contract_validate` 之后；须晚于 bind 阶段 |

## 6. 当前落地状态与扩展指南

| 能力 | 状态 |
|------|------|
| 端口必需位声明与校验 | 已落地 |
| 资产必需位声明与校验 | 已落地 |
| Demo / 真机 wiring 声明掩码 | 项目侧（见 Demo 接入专篇） |

新增端口或资产：

1. 在对应枚举末尾追加位标志。
2. 在 `*_contract.c` 表追加一行探测函数。
3. 补单测覆盖「缺失」与「就位」路径。
4. 不在框架内写死「全项目必选」集合。
