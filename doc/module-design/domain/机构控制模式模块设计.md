# 机构控制模式模块设计

**版本**：v1.7  
**状态**：已落地（单轴运动模式 + 流体路径控制 + 生命周期事件契约）  
**最后同步代码**：2026-08-25  
**适用范围**：`domain/mechanism/`、`domain/mechanism/motor/motor_exec.h`、`domain/ports/outbound/motor/`、`domain/safety/safety_output_hold.*`、`application/bridges/mechanism_bridge.*`  
**架构基线**：Ports & Adapters + 领域模式封装 + 项目侧装配  
**关键词**：mechanism、motor_axis、fluid_path、actuator_events、mechanism_bridge

---

## 1. 设计目标与核心理念

机构控制模式层把通用机构控制行为从具体机型中抽出来，形成可复用的领域模式。它不直接依赖电机执行器实现、IO 板、报警目录或项目命名，只依赖稳定端口、注入配置和项目定义的不透明 ID。

### 1.1 设计目标

- **电机执行解耦**：运动会话只依赖运动词汇（`motor_types.h`）；命令由 `motor_axis` 转发到 `motor_exec`，由 `domain/mechanism/motor` 实现。
- **行为模式复用**：单轴运动与流体路径作为通用 building block。
- **报警语义外置**：模式层不直接触发 `alarm_registry`，只暴露故障回调或发布生命周期事件。
- **项目命名外置**：电机号、路径号、通道号、机构 ID 均由项目层配置。
- **安全快速路径**：能量切断走 `safety_cutout_execute()`。软件侧「别再写输出」走 `safety_output_hold`（急停 DI 电平或软件锁存）；电机 tick 与流体 poll 读同一电平。置位只有 `safety_output_hold_request()`，复位只有 `safety_output_hold_release()`。

### 1.2 核心理念

| 原则 | 规定 |
|------|------|
| domain 不感知实现 | `motor_axis.c` 只 include `motor_exec.h`；项目业务只 include `motor_axis.h` |
| 控制与报警分离 | 运动结局通过 `on_motion_end` 回调交给项目层映射报警或流程分支 |
| 生命周期事件只表达事实 | `actuator_publish_motion_completed()` 不携带报警语义；洗车检查点见 `wash_publish_checkpoint_reached()` |
| 流体路径是单例 | `fluid_path` 维护全局路径/执行器对账状态；时序推进由调用方登记的周期任务驱动 |
| 项目负责装配 | 接线填硬件端口并 `mechanism_bridge_bind`；各机构持有 `motor_axis_t *` |

## 2. 分层归属与依赖方向

### 2.1 模块落位

| 层次 | 路径 | 职责 |
|------|------|------|
| **运行模式类型** | `domain/op_mode/op_mode_types.h` | `operational_mode_t` 枚举，由命令网关定义 |
| **生命周期事件** | `domain/mechanism/model/actuator_events.*` | 发布机构完成、流程检查点事件 |
| **生命周期选项** | `domain/mechanism/patterns/motor_axis.h`（`motion_lifecycle_opts_t`） | 机构 ID 与运动结局回调注入 |
| **单轴运动** | `domain/mechanism/patterns/motor_axis.*` | 单电机正/反向运行、到位运动、故障恢复、状态查询与完成边沿 |
| **流体路径** | `domain/mechanism/patterns/fluid_path.*` | 路径掩码、执行器对账、阀泵时序、急停全关 |
| **电机执行器** | `domain/mechanism/motor/` | 运行状态/互锁/回原状态机与编译期槽池 |
| **电机类型** | `domain/ports/outbound/motor/motor_types.h` | 方向、速度、到位条件、事件、命令结果 |
| **电机命令** | `domain/mechanism/motor/motor_exec.h` | 执行器命令与查询（领域内部 API） |
| **硬件端口** | `domain/ports/outbound/motor/motor_hw_port.h` | 驱动器/编码器/限位函数指针表 |
| **机构桥接** | `application/bridges/mechanism_bridge.*` | 登记电机 tick 与水路 poll；持有轴实例供命令与 poll 共用 |

### 2.2 依赖方向

```text
项目 mechanism / bindings
        │ 接线：cfg + 硬件端口 → mechanism_bridge_bind / add_axis
        ▼
domain/mechanism/patterns          # motor_axis 会话门面（业务只面对此）
        │ motor_exec（内部） / actuator_events
        ▼
domain/ports/outbound/motor + runtime/event_bus
        ▲
        │ 实现
domain/mechanism/motor             # 运行状态/互锁/回原状态机
        │ motor_driver_t / encoder / limit
        ▼
项目 wiring / vendor adapter       # 绑定具体驱动
```

**依赖禁令**：

- `domain/mechanism/patterns` 不得依赖具体 provider、项目报警码、项目机构名。
- `motor_exec` 不得依赖 domain 模式实现。
- `actuator_events` 不得直接调用报警 registry；项目 wiring 可订阅事件后做重评估。
- `fluid_path` 不得绕过注入的 `fluid_path_actuator_ops_t` 直接写 HAL。

## 4. 数据模型与行为契约

### 4.1 lifecycle 选项

```c
typedef struct {
    actuator_id_t           motion_actuator_id;
    motion_process_end_fn_t on_motion_end;
} motion_lifecycle_opts_t;
```

| 字段 | 行为 |
|------|------|
| `motion_actuator_id` | 非 0 时，`motor_axis_poll()` 在进入 IDLE 时发布机构空闲事件 |
| `on_motion_end` | 终止结局回调，载荷为 `motor_event_t`；命令拒令亦合成 FAULT/ESTOP 结局 |

### 4.2 单轴运动 `motor_axis`

适用：龙门、横移、升降等需要正反两个方向的单电机机构；刷子、风机等单向连续机构共用同一 API。

| API | 行为 |
|-----|------|
| `init(self, exec, motor, opts)` | 保存电机执行器句柄与电机索引 |
| `run(dir, speed, spec)` | `speed` 必须大于 0；返回 `motor_cmd_result_t`；`spec == NULL` 为连续运行 |
| 再次 `run()` | 更新目标；执行器按状态收敛；模式层不读状态选命令 |
| `stop()` | 受控停止；不在受理时发空闲事件 |
| `recover()` | 依次 `DRIVER_RESET` → `MODULE_STOP`；返回该命令结果 |
| `state()` | 将执行器运行状态映射为 IDLE / MOVING / FAULT |
| `last_result(out)` | 最近一次终止事件；无结局时返回 false |
| `poll()` | 先按电机号消费执行器事件并回调 `on_motion_end`，若存在未完成意图且已进入 IDLE，再发布 `motion_completed` |
| `home()` | 回原点，方向取执行器配置 `home_dir` |
| `is_settled()` | 已初始化、非 MOVING、且无待消费结局 |
| `position` / `direction` / `fault_code` / `baseline_trusted` / `encoder_healthy` / `current_freq` | 转发执行器查询，轴上不缓存 |
| `zero_encoder` / `confirm_baseline` | 转发编码器清零与基准确认 |

回原优先走 `motor_axis_home()`（方向取配置 `home_dir`，须显式 `FORWARD` 或 `REVERSE`，洗车原点常用 `MOTOR_HOME_DEFAULT_DIR`）；也可对 `limit_mask` 含 `ORIGIN` 下发 `run`。触原点后的编码器清零与 `baseline_trusted` 由电机执行器完成。硬限位可经掩码同时监视 POS/NEG/ORIGIN。位置/方向/故障/基准/编码器查询走 `motor_axis_*`（薄转发，不缓存）；**为何停下**走 `on_motion_end` / `last_result`。经 `motor_axis` 管理的电机应由其 `poll` 独占消费事件。

本轴 FAULT 后能否再 `run`/`home` 由该电机 `confirm_faults` 按故障码决定，不读报警注册表，也不为清障单独扫轴。某码对应位置 1 为需确认：运动命令拒绝，须显式 `recover()`。未置位为可续动：执行器在参数与互锁校验通过后，于本次 `run`/`home` 内做与显式 recover 相同的两步清除再启动。默认位图 0 表示全部可续动。`fatal`、`MOTOR_FAULT_DRIVER_PORT_FATAL`、ESTOP/`output_hold`、看门狗安全态不可被位图放行。`on_motion_end` 对同一故障闩锁去重；`run`/`home`/`recover` 受理后解除闩锁，否则可续动后再同码故障不会第二次回调。

单向连续运行的机构（刷子、风机）直接用 `motor_axis_run()` 传固定方向且 `spec == NULL` 表达，不再单列模式；多机构互斥关系由项目在自己的机构层组合表达，框架不预设槽位上限。

### 4.3 电机执行器停机、换向与事件

- 命令与 tick 用递归互斥量串行化；急停硬件切断与 `safety_output_hold_request()` 不取此锁。终止事件入分槽队列，由 `motor_axis_poll` 消费。
- tick 与运动命令读 `safety_output_hold_is_active()`：有效则切断并锁存 `ESTOP`，拒绝 `run`/`home`。已处于 `FAULT` 的轴被 hold 覆盖时保留 `fault_code`；解除后若仍有故障码或 `fatal` 则回到 `FAULT`，不得留下 `STOPPED`+残留码。按钮松开后抑制仍在，直到 `safety_output_hold_release()`（DI 仍有效时拒绝）。解除后本实例在下一拍 tick 或下一条命令退出 `ESTOP`。看门狗安全态仍走 `motor_executor_reset_watchdog()`，不是急停复位。
- 可续动 FAULT 只在 `run`/`home` 命令路径内清除，tick 停稳后不得自行变为 `STOPPED`。
- 终止事件按电机分槽（`MOTOR_EVENT_SLOT_CAP`），满时只丢该电机最旧事件。由 `motor_axis_poll` 消费；项目业务不要调用 `motor_exec_pop_event*`。
- `stop()` 进入 `STOPPING`：驱动提供 `request_stop` 时先受控停，等到 `!is_running` 或 `stop_timeout_ms`（0 则用 `default_max_time_ms`）后再 `cutoff`；未提供则下一拍直接切断。停止中重复 `stop()` 不重置超时。
- `STOPPING` 期间再次 `run()` 把新目标挂起，等停稳后进入 `WAITING_START`，不在输出未切时改向。
- 运行中换向仍在命令路径立即 `cutoff`，再等 `reversal_stop_ms`。
- `home_dir` 须为 `MOTOR_DIR_FORWARD` 或 `MOTOR_DIR_REVERSE`；零值（`MOTOR_DIR_UNSET`）在装载期拒绝，不再把 `FORWARD` 与未填共用 0。

### 4.4 流体路径 `fluid_path`

流体路径用路径掩码表达目标集合，每拍按目标重算各执行器期望开关，用共路依赖合并同一泵/阀。

```text
fluid_path_set(target_mask)
        │
        ▼
周期 poll（按最新目标对账，不排队）
        ├─ 先关不再需要的泵
        ├─ 立刻开目标需要的阀
        ├─ 泵已停满 pump_stop_delay_ms（或泵仍被其它路径占用）后关阀
        └─ 目标路径阀已开满 valve_open_delay_ms，且同泵非目标阀已关后开泵
```

| 字段/接口 | 行为 |
|-----------|------|
| `FLUID_PATH_PATH_MAX` | 逻辑路径数上限，当前为 32，与 `fluid_path_mask_t` 位宽一致 |
| `fluid_path_def_t` | 描述一个 path 依赖哪些 `(channel, slot)`；`path_idx` 必须唯一且小于 `FLUID_PATH_PATH_MAX` |
| `fluid_path_cfg_t.channel_count` | 通道数，最大 `FLUID_PATH_CHANNEL_MAX` |
| `fluid_path_init(cfg, ops, paths, count)` | 校验路径数、重复 path、空依赖、非法 channel/slot，然后初始化状态并强制全关 |
| `fluid_path_set(mask)` | 设置目标路径集合；若 mask 包含未在拓扑中声明的 path bit，返回 `SW_ERR_PARAM` |
| `fluid_path_enable(mask)` / `fluid_path_disable(mask)` | `set` 的按位糖：并入 / 清掉目标路径 |
| `fluid_path_all_off()` | 请求立刻全关（下一拍跳过阀泵延时），poll 中调用 `all_off()` 并重置状态 |
| `fluid_path_poll(now_ms)` | 抑制有效时强制全关；否则按当前目标对账一次阀泵输出 |
| `fluid_path_is_settled()` | 是否已收敛到目标（无强制关断、输出抑制未置位、各执行器实际输出等于期望） |

`fluid_path` 自身不注册周期任务：领域层不创建线程，`fluid_path_init()` 只做校验与状态初始化。接入项目链接 `wdf_mechanism_bridge` 并调用 `mechanism_bridge_register_tasks()`。未周期调用 `fluid_path_poll()` 时，`set/enable/disable` 请求会停留在 pending 而不生效。推荐周期见 `THD_FLUID_PATH_POLL_PERIOD_MS`。

`fluid_path` 只校验通用拓扑一致性和时序安全，不内置具体机型水路表、DO 引脚表或路径命名。

## 5. 事件与报警边界

| 事件/回调 | 发布方 | 含义 |
|-----------|--------|------|
| `actuator_publish_motion_completed(id)` | `motor_axis_poll()` 在进入 IDLE 时 | 某机构轴已空闲，可由项目层触发 ON_MOTION 重评估 |
| `wash_publish_checkpoint_reached(cp)` | 项目流程或编排层（`domain/wash/wash_events`） | 洗车流程到达项目定义检查点 |
| `on_motion_end(id, ev)` | `motor_axis_poll` 消费终止事件，或命令拒令路径 | 本次运动结局（`motor_event_t`）；勿与空闲事件混同 |

模式层不判断报警等级、清除策略或是否进入异常模式；这些规则留在 `alarm_registry` 与 `operational_mode`。

## 8. 当前边界与扩展指南

### 8.1 已落地边界

- 已落地两类通用模式：单轴运动、流体路径。
- 已落地电机执行端口与 `domain/mechanism/motor` 状态机。
- 已通过 `test_mechanism_patterns` 覆盖核心行为，包括水路拓扑校验、未知路径拒绝、引用计数和非零阀泵延时。
- `fluid_path_poll()` 始终对外可见，单测直接手动推进时序，无需任何测试专用编译定义。

### 8.2 项目侧负责

- 在 composition root 经 `mechanism_bridge_bind` 绑定槽位与硬件端口；业务模块只持有 `motor_axis_t *`，不保存 `motor_exec_t *`。
- 定义 `actuator_id_t`、`wash_checkpoint_id_t`、路径编号和通道映射。
- 将 `on_motion_end`、motion completed（空闲）、checkpoint reached 映射到项目报警目录或重评估策略。
- 决定哪些机构使用单轴运动或流体路径模式，以及多机构互斥关系如何在项目机构层表达。
- 链接 `wdf_mechanism_bridge`：`bind` → `add_axis`（保存返回的 `motor_axis_t *` 做命令与查询）→ `register_tasks()`。命令与 poll 必须用同一轴实例。
- `register_tasks()` 分别登记电机 tick 与水路 poll；其中一拍失败时已成功的那拍保留，下次只补登记失败项。

### 8.3 新增模式

1. 优先复用 `motor_axis` 与 `motion_lifecycle_opts_t`。
2. 若需要新硬件能力，先扩展 outbound port，再实现硬件适配器。
3. 不在模式层写入项目报警码；使用回调或事件把事实交给项目层。
4. 为新增模式补充独立 Unity 单元测试。
