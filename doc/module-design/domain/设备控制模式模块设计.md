# 设备控制模式模块设计

**版本**：v1.2  
**状态**：已落地（单轴运动模式 + 流体路径控制 + 生命周期事件契约）  
**最后同步代码**：2026-08-05（`domain/device_control/model`、`domain/device_control/patterns`、`hal_motor_exec_port`）  
**适用范围**：`domain/device_control/`、`ports/outbound/hal/motor/hal_motor_exec_port.h`  
**架构基线**：Ports & Adapters + 领域模式封装 + 项目侧装配  
**关键词**：device_control、motion_lifecycle、motor_axis、fluid_path、actuator_events

---

## 1. 设计目标与核心理念

设备控制模式层把通用机构控制行为从具体机型中抽出来，形成可复用的领域模式。它不直接依赖 MCC、IO 板、报警目录或项目命名，只依赖稳定端口、注入配置和项目定义的不透明 ID。

### 1.1 设计目标

- **电机执行解耦**：运动模式只依赖 `hal_motor_exec_port`，真实 MCC 或其他电机 SDK 由 provider 适配。
- **行为模式复用**：单轴运动与流体路径作为通用 building block。
- **报警语义外置**：模式层不直接触发 `alarm_registry`，只暴露故障回调或发布生命周期事件。
- **项目命名外置**：电机号、路径号、通道号、机构 ID 均由项目层配置。
- **安全快速路径**：`fluid_path_emergency_off()` 可由安全线程异步请求全关，实际收敛在 poll 中完成。

### 1.2 核心理念

| 原则 | 规定 |
|------|------|
| domain 不感知 SDK | `patterns/` 只 include `hal_motor_exec_port.h`，不 include MCC 头文件 |
| 控制与报警分离 | 运动故障通过 `on_process_fault` 回调交给项目层映射报警 |
| 生命周期事件只表达事实 | `actuator_publish_motion_completed()` / `wash_publish_checkpoint_reached()` 不携带报警语义 |
| 流体路径是单例 | `fluid_path` 维护全局路径/引用计数状态；时序推进由调用方登记的周期任务驱动 |
| 项目负责装配 | 项目 bindings 静态持有 `hal_motor_exec_t`、路径表、通道映射和报警映射 |

## 2. 分层归属与依赖方向

### 2.1 模块落位

| 层次 | 路径 | 职责 |
|------|------|------|
| **运行模式类型** | `domain/op_mode/op_mode_types.h` | `operational_mode_t` 枚举，由命令网关定义 |
| **生命周期事件** | `domain/device_control/model/actuator_events.*` | 发布机构完成、流程检查点事件 |
| **生命周期选项** | `domain/device_control/patterns/motion_lifecycle.h` | 机构 ID 与过程故障回调注入 |
| **单轴运动** | `domain/device_control/patterns/motor_axis.*` | 单电机正/反向运行、到位运动、回原、恢复、状态与位置查询 |
| **流体路径** | `domain/device_control/patterns/fluid_path.*` | 路径掩码、引用计数、阀泵时序、急停全关 |
| **电机端口** | `ports/outbound/hal/motor/hal_motor_exec_port.h` | 电机命令与状态查询抽象 |

### 2.2 依赖方向

```text
项目 mechanism / bindings
        │ 注入 exec、motor index、path table、lifecycle opts
        ▼
domain/device_control/patterns
        │ hal_motor_exec_port / actuator_events
        ▼
ports/outbound/hal/motor + runtime/event_bus
        ▲
        │ provider 适配
adapters/outbound/hal/providers/mcc
```

**依赖禁令**：

- `domain/device_control/patterns` 不得依赖具体 provider、项目报警码、项目机构名。
- `hal_motor_exec_port` 不得依赖 domain 模式实现。
- `actuator_events` 不得直接调用报警 registry；项目 wiring 可订阅事件后做重评估。
- `fluid_path` 不得绕过注入的 `fluid_path_actuator_ops_t` 直接写 HAL。

## 4. 数据模型与行为契约

### 4.1 lifecycle 选项

```c
typedef struct {
    actuator_id_t             motion_actuator_id;
    motion_process_fault_fn_t on_process_fault;
} motion_lifecycle_opts_t;
```

| 字段 | 行为 |
|------|------|
| `motion_actuator_id` | 非 0 时，停止/恢复成功会发布机构完成事件 |
| `on_process_fault` | 运动命令被拒绝时可回调项目层，项目层映射报警 |

### 4.2 单轴运动 `motor_axis`

适用：龙门、横移、升降等需要正反两个方向的单电机机构。

| API | 行为 |
|-----|------|
| `init(self, exec, motor, opts)` | 保存电机执行器句柄与电机索引 |
| `run(dir, speed, spec)` | `speed` 支持挡位或频率；值为 0 时停止；`spec == NULL` 时连续运行，否则调用 `hal_motor_move_to()` |
| 连续运行中再次 `run()` | 调用 `hal_motor_set_speed()` 更新速度或方向，不重启运动生命周期 |
| `stop()` | 调用 `hal_motor_stop()`；命令非拒绝时发布 motion completed |
| `home()` | 调用 `hal_motor_home()`；FAULT 状态拒绝 |
| `recover(step)` | 调用 `hal_motor_recover()`；命令非拒绝时发布 motion completed |
| `state()` | 将 `hal_motor_phase_t` 映射为 IDLE/MOVING/STOPPING/FAULT |

单向连续运行的机构（刷子、风机）直接用 `motor_axis_run()` 传固定方向且 `spec == NULL` 表达，不再单列模式；多机构互斥关系由项目在自己的机构层组合表达，框架不预设槽位上限。

### 4.4 流体路径 `fluid_path`

流体路径用路径掩码表达目标集合，用引用计数合并多个路径对同一泵/阀的依赖。

```text
fluid_path_set(target_mask)
        │
        ▼
周期 poll
        ├─ 关闭不再需要的路径：先停泵 → 等 pump_stop_delay_ms → 关阀
        └─ 打开新增路径：先开阀 → 等 valve_open_delay_ms → 开泵
```

| 字段/接口 | 行为 |
|-----------|------|
| `FLUID_PATH_PATH_MAX` | 逻辑路径数上限，当前为 32，与 `fluid_path_mask_t` 位宽一致 |
| `fluid_path_def_t` | 描述一个 path 依赖哪些 `(channel, slot)`；`path_idx` 必须唯一且小于 `FLUID_PATH_PATH_MAX` |
| `fluid_path_cfg_t.channel_count` | 通道数，最大 `FLUID_PATH_CHANNEL_MAX` |
| `fluid_path_init(cfg, ops, paths, count)` | 校验路径数、重复 path、空依赖、非法 channel/slot，然后初始化状态并强制全关 |
| `fluid_path_set(mask)` | 设置目标路径集合；若 mask 包含未在拓扑中声明的 path bit，返回 `SW_ERR_PARAM` |
| `fluid_path_enable(mask)` / `fluid_path_disable(mask)` | 按位增删目标路径；未在拓扑中声明的 bit 返回 `SW_ERR_PARAM` |
| `fluid_path_all_off()` | 请求全关，poll 中调用 `all_off()` 并重置状态 |
| `fluid_path_emergency_off()` | 无锁原子置位，供安全热路径请求快速全关 |
| `fluid_path_poll(now_ms)` | 推进一次时序状态机，**须由调用方登记为周期任务** |
| `fluid_path_is_settled()` | 是否已收敛到目标（无强制关断、时序空闲、目标达成） |

`fluid_path` 自身不注册周期任务：领域层不创建线程，`fluid_path_init()` 只做校验与状态初始化。未周期调用 `fluid_path_poll()` 时，`set/enable/disable` 请求会停留在 pending 而不生效。推荐周期见 `THD_FLUID_PATH_POLL_PERIOD_MS`。

`fluid_path` 只校验通用拓扑一致性和时序安全，不内置具体机型水路表、DO 引脚表或路径命名。

## 5. 事件与报警边界

| 事件/回调 | 发布方 | 含义 |
|-----------|--------|------|
| `actuator_publish_motion_completed(id)` | 运动模式 stop/recover 成功路径 | 某机构动作完成，可由项目层触发 ON_MOTION 重评估 |
| `wash_publish_checkpoint_reached(cp)` | 项目流程或编排层 | 洗车流程到达项目定义检查点 |
| `on_process_fault(is_positive_dir, fault)` | `motor_axis_run()` 命令拒绝路径 | 项目层可按方向与 fault 映射报警码 |

模式层不判断报警等级、清除策略或是否进入异常模式；这些规则留在 `alarm_registry` 与 `operational_mode`。

## 8. 当前边界与扩展指南

### 8.1 已落地边界

- 已落地两类通用模式：单轴运动、流体路径。
- 已落地电机执行端口与 MCC provider 适配器。
- 已通过 `test_device_control_patterns` 覆盖核心行为，包括水路拓扑校验、未知路径拒绝、引用计数和非零阀泵延时。
- `fluid_path_poll()` 始终对外可见，单测直接手动推进时序；测试目标通过 `FLUID_PATH_UNIT_TEST` 剥离与周期任务相关的装配。

### 8.2 项目侧负责

- 为每个机构静态分配/持有 `hal_motor_exec_t` 和电机索引。
- 定义 `actuator_id_t`、`wash_checkpoint_id_t`、路径编号和通道映射。
- 将 `on_process_fault`、motion completed、checkpoint reached 映射到项目报警目录或重评估策略。
- 决定哪些机构使用单轴运动或流体路径模式，以及多机构互斥关系如何在项目机构层表达。
- 把 `fluid_path_poll()` 登记为周期任务。

### 8.3 新增模式

1. 优先复用 `hal_motor_exec_port` 与 `motion_lifecycle_opts_t`。
2. 若需要新硬件能力，先扩展 outbound port，再实现 provider。
3. 不在模式层写入项目报警码；使用回调或事件把事实交给项目层。
4. 为新增模式补充独立 Unity 单元测试。
