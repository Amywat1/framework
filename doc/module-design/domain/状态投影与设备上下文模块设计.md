# 状态投影与设备上下文模块设计

**版本**：v1.0  
**状态**：已落地（snapshot + projection + dev_ctx 组合读模型；bootstrap 自动接入待项目选择）  
**最后同步代码**：2026-07-12（`domain/telemetry/snapshot`、`application/*_projection`、`services/dev_ctx`）  
**适用范围**：`domain/telemetry/snapshot/`、`application/operational_projection.*`、`application/safety_projection.*`、`application/wash_projection.*`、`services/dev_ctx/`  
**架构基线**：事件驱动投影 + 线程安全只读快照 + 组合设备上下文  
**关键词**：telemetry、snapshot、projection、dev_ctx、read model、event_bus

---

## 1. 设计目标与核心理念

状态投影层把分散在运行模式、报警、安全姿态、洗车会话和云连接中的状态收敛成可查询的只读快照。写侧仍由各领域聚合维护事实源，读侧只保存事件驱动的投影副本，供云端上报、CLI、UI 或诊断读取。

### 1.1 设计目标

- **读写分离**：领域聚合是事实源，snapshot 是只读缓存。
- **线程安全读取**：每个 snapshot 内部用互斥锁保护，调用方拿到结构体副本。
- **事件驱动刷新**：projection 订阅事件后从事实源拉取最新状态，不在事件载荷中传递复杂结构。
- **组合视图统一**：`dev_ctx_snapshot()` 聚合 operational / safety / wash / cloud 状态。
- **不承载业务决策**：snapshot 只表达状态，命令裁决仍在 `operational_mode` / `command_gateway`。

### 1.2 数据流

```text
领域事实源
  ├─ operational_mode
  ├─ alarm_registry / safety_posture
  └─ wash_orchestrator / wash events
        │ publish event
        ▼
event_bus dispatch
        │ projection handler
        ▼
domain/telemetry/snapshot
        │ get copy
        ▼
services/dev_ctx
        ├─ operational_snapshot_get()
        ├─ safety_snapshot_get()
        ├─ wash_snapshot_get()
        └─ cloud_link_get_ops()->is_online()
```

## 2. 分层归属与依赖方向

### 2.1 模块落位

| 层次 | 路径 | 职责 |
|------|------|------|
| **读模型 domain** | `domain/telemetry/snapshot/*_snapshot.{h,c}` | 线程安全快照存储与公开读接口 |
| **内部更新接口** | `domain/telemetry/snapshot/*_internal.h` | projection 专用更新入口 |
| **运行模式投影** | `application/operational_projection.*` | 订阅模式事件，刷新 operational snapshot |
| **安全投影** | `application/safety_projection.*` | 订阅报警事件，刷新 safety snapshot |
| **洗车投影** | `application/wash_projection.*` | 订阅会话事件，刷新 wash snapshot |
| **组合上下文** | `services/dev_ctx/dev_ctx.*` | 汇总各 snapshot 与云连接状态 |
| **事件骨干** | `runtime/event_bus/` | projection handler 的串行触发机制 |

### 2.2 依赖方向

```text
application/*_projection
        ├─ event_bus subscribe
        ├─ 读取领域事实源
        └─ 调用 snapshot_internal update

services/dev_ctx
        ├─ snapshot public get
        └─ cloud_link_port.is_online
```

**依赖禁令**：

- snapshot 公开头文件不得暴露更新接口；更新入口只放在 `*_internal.h`。
- `dev_ctx` 不得直接修改任何领域状态。
- projection handler 不得长时间阻塞，不得执行网络上报。
- 云连接状态由 `cloud_link_port` 查询，不存入 telemetry snapshot。

## 4. Snapshot 数据模型

### 4.1 Operational Snapshot

```c
typedef struct {
    operational_mode_t mode;
    bool               service_enabled;
    bool               estop_active;
} operational_snapshot_t;
```

| 字段 | 来源 |
|------|------|
| `mode` | `op_mode_get_current()` |
| `service_enabled` | `op_mode_is_service_enabled()` |
| `estop_active` | `op_mode_is_estop_active()` |

辅助判断：

| API | 语义 |
|-----|------|
| `operational_snapshot_is_stopping()` | service disabled，或 INIT/EXCEPTION/RECOVERING |
| `operational_snapshot_is_standby()` | IDLE 且 service enabled |

### 4.2 Safety Snapshot

```c
typedef struct {
    safety_posture_t posture;
    bool             blocking_active;
    uint32_t         top_alarm_code;
    unsigned         active_alarm_count;
    alarm_instance_t active_list[ALARM_ACTIVE_MAX];
} safety_snapshot_t;
```

| 字段 | 来源 |
|------|------|
| `active_list` / `active_alarm_count` | `alarm_registry_copy_active_projection()` |
| `blocking_active` | registry projection 输出 |
| `top_alarm_code` | registry projection 输出 |
| `posture` | `alarm_registry_safety_posture()` |

`safety_snapshot_is_warning_active()` 返回 `blocking_active || posture == LOCKOUT`。

### 4.3 Wash Snapshot

```c
typedef struct {
    wash_mode_t mode;
} wash_snapshot_t;
```

当前只记录最近一次 `EVT_WASH_SESSION_STARTED` 中的洗车模式。

### 4.4 Device Context

```c
typedef struct {
    operational_mode_t operational_mode;
    bool               service_enabled;
    bool               estop_active;
    wash_mode_t        wash_mode;
    bool               cloud_connected;
    safety_posture_t   safety_posture;
    bool               blocking_active;
    uint32_t           top_alarm_code;
    unsigned           active_alarm_count;
    alarm_instance_t   active_list[ALARM_ACTIVE_MAX];
} device_context_t;
```

`cloud_connected` 不由 snapshot 投影维护，而是在 `dev_ctx_snapshot()` 调用时通过 `cloud_link_get_ops()->is_online()` 实时读取；未注册 cloud link 时返回 `false`。

## 5. Projection 行为

### 5.1 Operational Projection

订阅表：

| 事件 | 行为 |
|------|------|
| `EVT_OP_MODE_CHANGED` | 从 `operational_mode` 拉取 mode/service/estop，更新 snapshot |
| `EVT_OP_MODE_CONTEXT_SYNC` | 同上，用于 service_enabled / estop 等上下文同步 |

`operational_projection_init()` 订阅事件后会立即执行一次 `sync_snapshot()`，确保初始读模型与当前聚合状态一致。

### 5.2 Safety Projection

订阅表：

| 事件 | 行为 |
|------|------|
| `EVT_ALARM_TRIGGERED` | 刷新 active list、blocking、top alarm、posture |
| `EVT_ALARM_CLEARED` | 同上 |
| `EVT_ALARM_BATCH_CLEARED` | 同上 |

`safety_projection_init()` 订阅事件后会立即刷新一次。报警事件的 `param` 只用于事件语义，投影刷新以 registry 当前状态为准。

### 5.3 Wash Projection

订阅表：

| 事件 | 行为 |
|------|------|
| `EVT_WASH_SESSION_STARTED` | `param & 0xFF` 解释为 `wash_mode_t`，写入 wash snapshot |

当前未订阅 `EVT_WASH_DONE` / `EVT_WASH_ABORTED`，因此 wash snapshot 只表达最近启动模式，不表达 busy/done/abort 状态。

## 6. 初始化与启动边界

当前代码提供 projection/dev_ctx init API 和单元测试，但 `bootstrap_run()` 尚未直接调用：

```text
operational_projection_init()
safety_projection_init()
wash_projection_init()
dev_ctx_init()
```

项目或后续 bootstrap 集成应在以下条件满足后初始化：

| 模块 | 初始化前置条件 |
|------|----------------|
| `operational_projection` | `event_bus_init()`、`operational_mode_init()` |
| `safety_projection` | `event_bus_init()`、`alarm_registry_init()`、报警目录已可查询 |
| `wash_projection` | `event_bus_init()` |
| `dev_ctx` | snapshots 可读；cloud link 可选 |

推荐放置在 `bootstrap_init()` 的 `op_mode_bridge_init()` 附近，或由项目 hook 显式调用。若未初始化 projection，snapshot 仍可通过内部测试接口写入，但运行期不会随事件自动刷新。

## 7. 线程安全与一致性

| 模块 | 线程安全策略 |
|------|--------------|
| `operational_snapshot` | 单 mutex 保护静态快照 |
| `safety_snapshot` | 单 mutex 保护静态快照和 active list |
| `wash_snapshot` | 单 mutex 保护静态快照 |
| projection handler | 在 `event_dispatch` 线程串行执行 |
| `dev_ctx_snapshot()` | 分别读取各 snapshot 副本后组合 |

`dev_ctx_snapshot()` 不保证跨多个 snapshot 的全局原子一致性；它保证每个子快照自身一致。对云端上报和诊断视图，这种近似一致性足够。

## 8. 当前边界与扩展指南

### 8.1 已落地边界

- 已落地 operational/safety/wash 三类 snapshot。
- 已落地三个 projection，覆盖运行模式、报警安全、洗车启动模式。
- 已落地 `dev_ctx` 组合上下文。
- 已有 `test_telemetry_projection` 和 `test_dev_ctx` 单元测试。

### 8.2 待项目选择的接入点

- 是否把 projection 初始化加入通用 bootstrap。
- 是否把 `dev_ctx` 作为 cloud model get 回调的统一来源。
- 是否扩展 wash snapshot，加入 busy、current phase、abort cause、direction 等字段。
- 是否增加 cloud snapshot，避免每次 `dev_ctx_snapshot()` 实时读 link port。

### 8.3 新增投影

1. 先确认领域事实源和触发事件。
2. 在 `domain/telemetry/snapshot` 新增 public get 与 internal update。
3. 在 `application/*_projection` 订阅事件并从事实源拉取状态。
4. 不在事件 `param` 中塞指针或复杂结构。
5. 补充投影单元测试，覆盖初始同步和事件刷新。
