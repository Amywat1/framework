## 1. 设计目标与核心理念

报警子系统把硬件/流程/通讯异常转化为**可分级、可清除、可查询**的活跃报警实例，并通过事件总线驱动安全姿态与运行模式收敛。

### 1.1 设计目标

- **单一事实源**：活跃报警列表与会话 journal 由 `alarm_registry` 维护。命令路径（开洗拒绝、洗后 STOPPED、recover）同步读 registry，不以事件到达为事实。
- **端口隔离**：项目 detector 经 `alarm_binding_port` 触发/清除，不直接 `#include` registry 实现。
- **放锁后发布**：活动表变位在释放 registry 锁之后 `event_publish_required`，与 `operational_mode` 相同。先逐码 `EVT_ALARM_*`，再姿态边沿 `EVT_SAFETY_*`。入队不等于机构已停——`abort_jobs` 由 dispatch 线程上的 `safety_session_coordinator` 消费 CRITICAL 的 `EVT_ALARM_TRIGGERED`。`EVT_SAFETY_LOCKOUT` 只表示姿态，不单独停机构。
- **重评估桥接**：锁存且填了组的条目，经生命周期事件与项目 binding 表映射到 `reeval_group`。
- **与运行模式解耦**：等级语义在报警域；模式转移由 `op_mode_bridge` 消费 `EVT_ALARM_TRIGGERED` 做一次 blocking 收敛。提示裁决另走 `EVT_ALARM_ANNOUNCE` / `MUTE`，不改 blocking。

### 1.2 独立轴

| 轴 | 回答问题 | 权威模块 |
|----|----------|----------|
| 报警等级 `alarm_level_t` | 严重度 + 运行时处置 | `safety_matrix.h` 行为属性表 |
| 生命周期 `alarm_lifecycle_t` | 条件消失如何结案 | `safety_matrix.h` |
| 提示 `announced` | 是否向人提示 | registry 内三类设计抑制 + 搁置/停用。互挡键是层×对象号，不是机构名；同对象根因、对象 `TRIPPED`、切断链同时有效，只挡次生提示。细则见 `doc/architecture/05` §3.1 |
| 安全姿态 `safety_posture_t` | 是否 LOCKOUT | `alarm_registry_safety_posture()`（CRITICAL 推导） |
| 运行模式 `operational_mode_t` | 允许哪些命令 | `operational_mode` |

等级语义：

| 等级 | 行为 |
|------|------|
| `MINOR` | 仅记录，不挡开洗 |
| `MAJOR` | blocking：禁开洗；洗中不中断；洗完仍活跃 → `STOPPED` |
| `CRITICAL` | LOCKOUT 挡开洗；新进表经 `EVT_ALARM_TRIGGERED` 停当前自动运动。同一条码已在表里不再进表。运营后果见 `doc/architecture/10-通用洗车运营模型.md` §4.1 |

生命周期仍独立：`FOLLOW_SIGNAL` / `LATCH`。目录归类只问两句：条件消失能否认定结案（须有持续可观察的「还成立」）→ 跟随信号且组必须 `NONE`；若不能，同组再动作做成且当时条件已是 false 能否结案 → 锁存并填组，否则锁存无组、只等复位或恢复。恢复强制清非安全不是第三档。运动结案是锁存上的可选 `reeval_group`，不是第三档。

上述两组语义都以**行为属性**表达，单一事实源是 `domain/safety/model/safety_matrix.h`；`alarm_registry` 的全部等级与生命周期判定都查这张表，不再各处写 `level >= MAJOR` 这类内联判断。未知等级取最严格值、未知生命周期不自动结案——漏配置若默认放行，现场表现是"有报警却照常开洗"或"安全状态被未定义行为解除"，比误停机危险得多。完整格点见 `doc/architecture/05-安全与报警架构.md` §3。

### 1.3 端到端事件链

```text
  项目 detector / HAL / CommWatchdog
        │ alarm_binding_port.trigger/clear
        ▼
  alarm_registry（活跃列表 + session journal）
        │ 放锁后 event_publish_required
        ▼
  EVT_ALARM_TRIGGERED / CLEARED
        ├─► 同函数内姿态边沿 → EVT_SAFETY_LOCKOUT / NOMINAL
        ├─► telemetry_projection
        └─► op_mode_bridge → op_mode_on_blocking_alarm
  EVT_ALARM_ANNOUNCE / MUTE
        └─► telemetry_projection（提示态；云端 error 仍报全量活动码）

  命令 / 会话路径（正交）：
  START_WASH           → 存在 blocking 报警则拒绝（不看 announced）
  WASH 正常结束        → 仍 blocking 则 STOPPED，否则 WASH_DONE
  DEV_CMD_RECOVER      → 清搁置 + 对象开停回 IDLE + 复位非安全（保留形态 11）+ home + blocking 验证
  DEV_CMD_SET_SERVICE 关且已 STOPPED → 清搁置与检测停用
  DEV_CMD_ALARM_SHELVE / UNSHELVE / OOS → 命令网关后写 registry（OOS 除 INIT 外随时放行）
```

### 2.2 依赖方向

```text
项目 detector / watchdog（项目仓库）
        │ alarm_binding_port
        ▼
   domain/safety/alarm_registry
        │ 放锁后 event_publish_required
        ▼
   event_bus
        │
        ├─► EVT_ALARM_* / EVT_SAFETY_*
        └─► op_mode_bridge / telemetry_projection / safety_session_coordinator
```

**依赖禁令**：

- `alarm_registry` 不得依赖 MQTT、云端或 `operational_mode`。
- `alarm_bridge` 不得解析机型业务，只做端口绑定、会话开关与可选锁存运动结案查表。
- detector 不得绕过 port 直接写 registry 静态状态。
- 持 registry 锁时不得调用 `event_publish*`（handler 可能回读 registry）。

## 4. 数据模型

### 4.1 报警定义（alarm_def_t）

| 字段 | 说明 |
|------|------|
| `code` | 6 位报警码（`ALARM_CODE_MAKE`） |
| `level` | MINOR / MAJOR / CRITICAL |
| `lifecycle` | FOLLOW_SIGNAL / LATCH |
| `reeval_group` | 锁存可选运动结案分组；跟随信号须 `ALARM_REEVAL_GROUP_NONE` |
| `desc` | 描述 |
| `need_run` | 缺省 ANY；超时/欠载装载期升为 COMMANDED |
| `eclipse_role` | 缺省按故障形态：过载/安全/主动停止/信号异常为根因 |
| `shelve_policy` / `allow_oos` / `oos_admit` / `suppress_modes` | 提示策略；接单态写入 `suppress_modes` 装载失败 |

### 4.2 报警码编码

```text
报警码 = 对象层 layer(1) + 对象号 object(3) + 故障形态 fault_mode(2)
```

范围：layer `1..9`，object `0..999`，fault_mode `0..99`。  
故障形态按「怎么发现的」划分：未分类、过载、通讯中断、欠载、信号异常、动作超时、故障反馈、液位异常、压力异常、安全触发、主动停止、检测停用（形态 11，由装载期为 `allow_oos` 条目合成补偿码）。  
通用对象层/故障形态常量见 `alarm_types.h`；具体码表由项目目录提供。

**该编码格式是框架统一约定**，所有接入项目共用，不由项目自定：`alarm_registry_load_catalog()`
对每条目录项调用 `alarm_code_is_valid()`，不符合格式的码整表拒绝。统一格式让云端、运维工具和
日志按大类与性质聚合时不需要逐项目适配。项目只决定 index 的分配与每个码的等级、清除策略和描述；
大类与性质优先复用 `ALM_C_*` / `ALM_N_*`，需要新的通用取值时在 `alarm_types.h` 追加，而不是在项目内另起编号体系。

### 4.3 总线事件

变位在放锁后直接 `event_publish_required`：

| 活动表变化 | 发布 |
|------------|------|
| 新插入 | `EVT_ALARM_TRIGGERED`（param=code） |
| 删除（含 lockout 驱逐） | `EVT_ALARM_CLEARED`（param=code）；若当时在提示则先 `MUTE` |
| 提示边沿 | `EVT_ALARM_ANNOUNCE` / `EVT_ALARM_MUTE`（param=code） |
| 姿态 NOMINAL→LOCKOUT | 逐码之后发 `EVT_SAFETY_LOCKOUT` |
| 姿态 LOCKOUT→NOMINAL | 逐码之后发 `EVT_SAFETY_NOMINAL` |

实际删除活动告警时，对每条告警发独立 `CLEARED`。重复 trigger 不重复 TRIGGERED，条件已成立时也不取消搁置；条件从消失回到成立视为新事件，搁置下架。`load_catalog` / `init` 清空运行态且不补发 CLEARED。

不另设 pending 队列，不发布 `EVT_ALARM_RESYNC`。总线满时走仓内 `event_publish_required` 契约（失败可见）；活动表仍是事实源，开洗/洗后仍同步读，投影 1s 重建。

### 4.4 安全姿态

| 值 | 推导 |
|----|------|
| `SAFETY_POSTURE_NOMINAL` | 无 CRITICAL 活跃 |
| `SAFETY_POSTURE_LOCKOUT` | 存在 CRITICAL 活跃 |

由 `alarm_registry_safety_posture()` 计算（`copy_safety_view` 的薄封装）；registry 在变位函数内检测边沿并发布。

### 4.5 容量与满池

| 宏 | 默认 | 说明 |
|----|------|------|
| `ALARM_CATALOG_MAX` | 64 | 静态目录（含装载期合成的停用补偿码） |
| `ALARM_ACTIVE_MAX` | 32 | 活跃池；本轮待发布条数不超过此值 |
| `ALARM_SESSION_JOURNAL_MAX` | 16 | 洗车会话 journal |
| `ALARM_OOS_MAX` | 8 | 同时检测停用的原码 |

活跃池满时：非 lockout 打日志并返回 `SW_ERR_OVERFLOW`；lockout 等级驱逐一条非
lockout（先 MINOR 最早触发，再 MAJOR 最早触发，发 CLEARED + ERROR 日志）后再插入。
32 条都是 lockout 时仍 `SW_ERR_OVERFLOW`。无元告警。
journal 满时：不覆盖已有码，累计 `session_journal_dropped`，读取不清零。

### 4.6 会话 journal

洗车会话期间触发的 MAJOR+ 码记入 journal，经 `safety_snapshot_t` 供云/CLI 读取；**不参与**洗后停机布尔判定（判定用当前 `alarm_registry_has_blocking_active()`）。满池丢弃计数随会话累积，新会话清零。

## 5. 核心模块行为契约

### 5.1 alarm_registry

下表 API 名省略 `alarm_registry_` 前缀，实际符号为 `alarm_registry_<名>`。

| API | 行为要点 |
|-----|----------|
| `load_catalog` | 逐条校验目录（码合法且唯一、等级与生命周期已定义、跟随信号须 NONE 分组），任一条不合法即整表拒绝 `SW_ERR_PARAM`；装载成功则清空 active / journal 且不补发 CLEARED |
| `trigger` | 表示故障条件成立；未知码 `SW_ERR_PARAM`；已 active 时刷新条件且不重复 TRIGGERED；条件已成立不取消搁置，从消失回到成立则下架搁置；池满时非 lockout 返回 `SW_ERR_OVERFLOW`，lockout 可驱逐一条非 lockout 后插入；成功变位则返回前入队 |
| `clear` | 表示故障条件消失；跟随信号立即删除并发 CLEARED，锁存只清条件、保留搁置 |
| `reset_all` | 仅删除故障条件已消失的锁存；条件仍成立时复位无效；删除在返回前发 CLEARED |
| `reset_non_safety` | 强制删除非安全触发（码尾非 09），条件仍成立也删除；安全触发与形态 11 补偿码保留 |
| `has_safety_trigger_active` | 活动表中有安全触发且 `condition_active` |
| `reevaluate_group` | 对匹配分组且条件已消失的锁存删除，返回前发 CLEARED。完成事件只在非电流停的到位做成时发出 |
| `has_blocking_active` | 存在 blocking 等级（查 `safety_matrix`，不是 `level >= MAJOR`）；不看 `announced`；`copy_safety_view` 的薄封装 |
| `get_session_journal` | 拷贝本会话 MAJOR+ 码列表，并交出累计丢弃数（读取不清零） |
| `copy_safety_view` | 一次持锁读出活动表 + blocking + 最高码 + 姿态 + journal + 停用列表；需要多项时一律走此接口 |
| `on_wash_session_started/ended` | 开关 journal 窗口 |
| `set_op_mode` / `set_object_run` | 应用桥/项目推送工况与对象开停，重算提示。项目把一台电机映射到哪些目录对象、故障结束是否推 `TRIPPED`，框架不认识机构名。超时结束应保持 `COMMANDED`，避免过程量把自己静音 |
| `shelve` / `unshelve` / `set_oos` / `poll` | 限时搁置、检测停用、到期取消搁置 |
| `clear_announce_overrides` | 清全部搁置并把对象开停清回 IDLE；恢复起步调用，不清检测停用 |
| `clear_oos` | 清全部检测停用并删除形态 11 补偿码；关总开关落到 STOPPED 调用；上电由 init/装载目录清零 |

活动实例插入时即缓存 `level` / `lifecycle` / `reeval_group`，目录在运行期不变
（`load_catalog` 会同时清空活动表），因此 `clear` / `reset_all` /
`reset_non_safety` / `reevaluate_group` 都只扫活动表一趟、不回查目录。遍历中删除时倒序扫描，
因为删除会前移后续条目。`has_blocking_active` 与 `safety_posture` 也复用
`copy_safety_view` 的同一次扫描，「MAJOR 阻塞开洗」「CRITICAL 进 LOCKOUT」
这两句判定在实现里各只出现一次。

### 5.2 alarm_bridge

| API | 行为 |
|-----|------|
| `bind` | 注册 `alarm_binding` 入站 ops，直转 `alarm_registry_trigger/clear/load_catalog` |
| `init` | 订阅洗车会话生命周期以开关 journal；不注册周期任务 |
| `poll` | 周期调用 `alarm_registry_poll`，到期取消搁置 |
| `reeval_init` / `reeval_handle` | 项目锁存运动结案 binding 表与生命周期事件 |

不导出 `alarm_bridge_drain`。入队由 registry 完成。

### 5.3 alarm_binding_port

```c
typedef struct {
    sw_err_t (*trigger)(uint32_t alarm_code);
    sw_err_t (*clear)(uint32_t alarm_code);
    sw_err_t (*load_catalog)(const alarm_def_t *defs, unsigned count);
} alarm_binding_ops_t;
```

trigger/clear 直转 `alarm_registry_*`，不再包装 drain。不在此路径调用 `safety_cutout_execute` / `safety_output_hold_request`。需要断动力的码（如通讯丢失）仍由项目在 trigger 前自行 cutout。

### 5.6 急停码判定（safety_port）

`op_mode_alarm_port_is_estop(code)`：由项目注册的 `safety_ops_t.alarm_is_estop` 回答（例如项目的急停 DI 报警码）；
供 `op_mode_bridge` 识别急停报警，与 `EVT_HW_ESTOP_*` 硬件路径并存。报警编码表属项目资产，故由项目实现。

注册安全端口时同时把 `estop_is_active` 绑到 `safety_output_hold`。机构「别再写输出」
不读电机绑定表里的第二根 DI，见 `doc/module-design/domain/机构控制模式模块设计.md`。

### 5.7 通讯 cutout（项目）

周期通讯丢失：若该条目 `level == CRITICAL`，watchdog 在 trigger 前同步 `safety_cutout_execute()`（不再单独配置 cutout 列）。切断会递增能量代次以作废当前电机输出，不置 hold。

## 6. 与运行模式的衔接

| 衔接点 | 说明 |
|--------|------|
| START_WASH | `alarm_registry_has_blocking_active()` 则拒绝 |
| 洗车正常完成 | `op_mode_on_last_job_finished`：仍 blocking → `STOPPED`，否则 → `WASH_DONE` |
| LOCKOUT | 姿态边沿，不单独 `abort_jobs`。停机构由 CRITICAL 的 `EVT_ALARM_TRIGGERED`。模式由 `EVT_ALARM_TRIGGERED` → `op_mode_on_blocking_alarm` 一次收敛（ACTIVE 中不立刻切模式，走中止/CLEARING；清障中再来 CRITICAL 停会话） |
| Recover | 清可恢复告警 + 异步归位 → IDLE / STOPPED |
| 自检 | 查 LOCKOUT 与 blocking |

急停旗标只认 `EVT_HW_ESTOP_*`。急停报警由 `estop_alarm_bridge` 从同一对确认事件投影并进入 LOCKOUT，不再对急停 DI 做独立次数滤波。

## 8. 扩展指南

### 8.1 新增报警码

1. 在项目 config 表追加目录项（level / lifecycle / reeval_group）。
2. `load_catalog` 加载——码须合法且全表唯一，`FOLLOW_SIGNAL` 须配 `ALARM_REEVAL_GROUP_NONE`，`LATCH` 的组可空可填，否则整表被拒。
3. detector / 调用点经 `alarm_binding_port` 触发。
4. 按等级语义评估对开洗、洗中、洗后的影响。

### 8.2 新增锁存运动结案绑定

1. 定义 `reeval_group`。
2. 目录项 `lifecycle=latch` 并填 group。
3. wiring 提供 binding 表并 `alarm_bridge_reeval_init`。

### 8.3 新增 `EVT_ALARM_*` 订阅者

边沿订阅者漏事件后，应以 registry / `copy_safety_view` 或投影周期重建为事实源，不得依赖已删除的 `EVT_ALARM_RESYNC`。命令路径必须同步读 registry。

### 8.4 禁止

- detector 直接依赖 registry 实现文件。
- 在 detector 里读八态或对象开停决定报不报；真值仍全量上报。
- 用从云端 `error` 里拿掉码、或适配器私写屏蔽，来表示搁置/停用。
- 提示静音改变 `alarm_registry_has_blocking_active()`、LOCKOUT 或结案。
- 在 bridge 内硬编码机型分支。
- 用事件 param 传递指针。
- 重新引入与等级重复的「响应策略」枚举，除非有可交叉的真实语义。
- 本机 ISA 确认态、持续搁置、OOS 落盘。
