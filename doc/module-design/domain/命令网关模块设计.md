## 1. 设计目标与核心理念

命令网关是外部控制请求的**唯一业务入口**：云端、CLI、仿真等来源解析为 `dev_cmd_t` 后，经端口提交，在 `event_dispatch` 线程完成模式裁决与副作用执行，并同步返回回执。

### 1.1 设计目标

- **统一入站契约**：所有外部命令走 `device_command_port.submit()`，返回 `dev_cmd_receipt_t`。
- **线程安全串行化**：RPC/CLI 线程只入队；`operational_mode` 仅在 dispatch 线程访问。
- **裁决与执行分离**：domain 层 `operational_mode` 做权限与模式转移；application 层 `side_effect_router` 调 orchestrator/HAL。
- **同步回执**：调用方阻塞等待 sem，获得 ACCEPTED / REJECTED / FAILED / TIMEOUT / BUSY。
- **可观测**：裁决拒绝、模式变更、命令处理完成经 `event_bus` 广播；状态转移日志带名称字符串与原因。

### 1.2 核心理念

| 原则 | 规定 |
|------|------|
| 命令词汇在 domain | `dev_cmd_kind_t`、`dev_cmd_t` 定义于 `device_command.h`；port 只引用 |
| 表驱动权限 | `k_cmd_matrix[kind][mode]` 静态矩阵 + 条件分支（急停、报警、service_enabled） |
| 副作用枚举 | 允许执行的命令映射为 `dev_cmd_effect_t`，由 router 执行，domain 不直接调 HAL |
| 模式单线程 | `operational_mode` 不订阅 event；外部生命周期通过显式 `op_mode_on_*` 钩子驱动 |
| 唤醒不携带命令 | `EVT_CMD_GATEWAY_WAKE` param=0；命令载荷保存在网关队列 slot |

### 1.3 处理流水线

```text
  CLI / Cloud / Sim
        │
        ▼
  device_command_port.submit(cmd, receipt, timeout_ms)    ← 调用方线程
        │
        ├─ 分配 queue slot（最多 4 条并发等待）
        ├─ event_publish(EVT_CMD_GATEWAY_WAKE)
        └─ sem_timedwait(done) 阻塞等待
                    │
                    ▼
  event_dispatch 线程：on_gateway_wake → command_gateway_drain()
        │
        ├─ op_mode_handle_command(cmd)     ← 裁决 + 模式转移
        │       ├─ DENIED → receipt REJECTED
        │       └─ ALLOWED → pending_effect
        │
        ├─ side_effect_router_run(effect, cmd)   ← 副作用（若 ALLOWED）
        │
        ├─ publish EVT_OP_MODE_CMD_HANDLED
        └─ sem_post(done) → 唤醒 submit 线程
                    │
                    ▼
  调用方收到 receipt，submit 返回 sw_err_t
```

## 2. 分层归属与依赖方向

### 2.1 模块落位

| 层次 | 路径 | 职责 |
|------|------|------|
| **入站端口** | `ports/inbound/command/command_port.h` | `submit` 契约、register/get |
| **网关** | `application/command_gateway.{h,c}` | 队列、唤醒、drain、注册 port ops |
| **副作用路由** | `application/side_effect_router.{h,c}` | 按 `dev_cmd_effect_t` 调 orchestrator/HAL |
| **运行模式** | `domain/op_mode/operational_mode.{h,c}` | 状态机、命令矩阵、模式转移 |
| **命令词汇** | `domain/op_mode/device_command.h` | kind/source/body/receipt 类型 |
| **命令类型** | `domain/op_mode/command_types.h` | `dev_cmd_decision_t`、`dev_cmd_status_t`、`dev_cmd_receipt_t` |

| **模式桥接** | `application/op_mode_bridge.{h,c}` | 异步事件 → `op_mode_on_*` |
| **端口注册** | `ports/port_registry_infra.c` | `device_command_port_register` 等 |
| **事件契约** | `common/event_types.h` | `EVT_CMD_*`、`EVT_OP_MODE_*`、`EVT_WASH_*` 等 |

### 2.2 依赖方向

```text
adapters / CLI / cloud submit 回调
        │ device_command_port
        ▼
   application/command_gateway
        ├── domain/op_mode/operational_mode
        ├── application/side_effect_router
        │       ├── wash_orchestrator / self_check_service
        │       └── machine_ops_port
        └── runtime/event_bus
```

**依赖禁令**：

- `operational_mode` 不得调用 `side_effect_router` 或 HAL；只产出 `pending_effect`。
- `side_effect_router` 不得做命令权限判断（假设 gateway 已裁决 ALLOWED）。
- port 层不得包含业务裁决逻辑。
- 除 `command_gateway` 外，模块不得直接写 `operational_mode` 内部静态状态（须走 `op_mode_on_*` API）。

## 4. 数据模型

### 4.1 设备命令（dev_cmd_t）

```c
typedef struct {
    dev_cmd_meta_t meta;   /* request_id, source */
    dev_cmd_body_t body;   /* kind + payload union */
} dev_cmd_t;
```

**命令种类（dev_cmd_kind_t，闭集）**

| 枚举 | 载荷 | 说明 |
|------|------|------|
| `DEV_CMD_START_WASH` | `start_wash.mode` | 启动洗车（需 IDLE + service_enabled + 无阻塞报警） |
| `DEV_CMD_STOP_WASH` | 无 | 手动中止洗车会话 |
| `DEV_CMD_STOP_OPERATION` | 无 | 关闭运营接单 |
| `DEV_CMD_RESUME_OPERATION` | 无 | 恢复运营接单 |
| `DEV_CMD_HOME_DEVICE` | 无 | 归位（STOPPED → HOMING → IDLE，需 service_enabled） |
| `DEV_CMD_MANUAL_ACTUATOR` | `act_id`, `param` | 手动点动（STOPPED 直接允许；EXCEPTION 需无急停） |
| `DEV_CMD_START_SELF_CHECK` | 无 | 启动自检（STOPPED / EXCEPTION 均允许） |
| `DEV_CMD_RECOVER` | 无 | 故障恢复（EXCEPTION → RECOVERING → IDLE，需无急停） |
| `DEV_CMD_STOP_ALL_OUTPUTS` | 无 | 停止全部输出（多数状态可用） |

**命令来源（dev_cmd_source_t）**：`CLOUD` / `CLI` / `SIM` / `TEST`（元数据，不参与矩阵）。

### 4.2 运行模式（operational_mode_t）

| 模式 | 含义 |
|------|------|
| `OP_MODE_INIT` | 初始化前占位（`operational_mode_init` 调用前） |
| `OP_MODE_STOPPED` | 停机（手动维护可用，归位后进入待机）；**上电默认态** |
| `OP_MODE_HOMING` | 归位中（HOME_DEVICE 副作用执行中，完成后进入 IDLE） |
| `OP_MODE_IDLE` | 待机，等待洗车指令 |
| `OP_MODE_WASHING` | 洗车会话执行中 |
| `OP_MODE_ALARM_HOMING` | 报警归位中（WASHING 中止后执行安全归位，完成后进入 EXCEPTION） |
| `OP_MODE_WASH_DONE` | 洗车完成，等待客户离场（离场后进入 IDLE） |
| `OP_MODE_SELF_CHECK` | 自检中 |
| `OP_MODE_EXCEPTION` | 故障停机 |
| `OP_MODE_RECOVERING` | 恢复中（清告警 + 归位 + 验证） |

聚合内还维护：

- `s_estop_active`：急停标志（影响 CONDITIONAL 命令）
- `s_service_enabled`：运营接单开关（Stop/Resume Operation，内部 static，仅由命令触发）

### 4.3 裁决结果（dev_cmd_decision_t）

```c
typedef struct {
    op_cmd_result_t    verdict;        /* ALLOWED / DENIED */
    op_reject_reason_t reason;
    dev_cmd_effect_t   pending_effect; /* ALLOWED 时待执行副作用 */
} dev_cmd_decision_t;
```

**拒绝原因（op_reject_reason_t）**

| 枚举 | 典型场景 |
|------|----------|
| `OP_REJECT_WRONG_MODE` | 矩阵 DENIED 或 START_WASH 有 blocking 报警或 RESUME 时 service 未停 |
| `OP_REJECT_ESTOP_ACTIVE` | CONDITIONAL 命令且急停有效 |
| `OP_REJECT_SERVICE_DISABLED` | START_WASH 或 HOME_DEVICE 但 service_enabled=false |
| `OP_REJECT_UNKNOWN_CMD` | kind 非法 |

### 4.4 回执（dev_cmd_receipt_t）

| status | 含义 | submit 返回 |
|--------|------|-------------|
| `DEV_CMD_STATUS_ACCEPTED` | 裁决通过且副作用 SW_OK | `SW_OK` |
| `DEV_CMD_STATUS_REJECTED` | 裁决 DENIED | `SW_ERR_STATE` |
| `DEV_CMD_STATUS_FAILED` | ALLOWED 但副作用失败 | `effect_error` |
| `DEV_CMD_STATUS_TIMEOUT` | sem 等待超时 | `SW_ERR_TIMEOUT` |
| `DEV_CMD_STATUS_BUSY` | 队列满或未入队 | `SW_ERR_BUSY` |

### 4.5 副作用种类（dev_cmd_effect_t）

| effect | 触发命令 | router 行为 |
|--------|----------|-------------|
| `DEV_CMD_EFFECT_START_WASH` | START_WASH | `wash_orchestrator_start(mode)` |
| `DEV_CMD_EFFECT_STOP_WASH` | STOP_WASH | `wash_orchestrator_abort(MANUAL)` |
| `DEV_CMD_EFFECT_SELF_CHECK` | START_SELF_CHECK | `self_check_service_start()` |
| `DEV_CMD_EFFECT_HOME_DEVICE` | HOME_DEVICE | `machine_ops.home_device()` + 发布 `EVT_OP_MODE_HOME_COMPLETED(1/0)` |
| `DEV_CMD_EFFECT_MANUAL_ACTUATOR` | MANUAL_ACTUATOR | `machine_ops.execute_manual_actuator()` |
| `DEV_CMD_EFFECT_STOP_ALL_OUTPUTS` | STOP_ALL_OUTPUTS | `machine_ops.stop_all_outputs()` |
| `DEV_CMD_EFFECT_NONE` | STOP/RESUME_OPERATION、RECOVER | 仅模式/标志变更，router 直接 SW_OK |

### 4.6 相关事件

| 事件 | 发布方 | `param` 编码 |
|------|--------|--------------|
| `EVT_CMD_GATEWAY_WAKE` | command_gateway submit | 0 |
| `EVT_OP_MODE_CHANGED` | operational_mode | `(from << 8) \| to` |
| `EVT_OP_MODE_CMD_REJECTED` | operational_mode | `(kind << 8) \| reason` |
| `EVT_OP_MODE_CMD_HANDLED` | command_gateway drain | `(kind << 16) \| (status << 8) \| reason` |
| `EVT_OP_MODE_RECOVERY_REQUESTED` | RECOVER 命令 | 0 |
| `EVT_OP_MODE_RECOVERY_COMPLETED` | recovery_service | `recovery_result_t` |
| `EVT_OP_MODE_HOME_COMPLETED` | side_effect_router（HOME_DEVICE 副作用后） | 1=成功，0=失败 |
| `EVT_OP_MODE_ALARM_HOME_REQUESTED` | operational_mode（进入 ALARM_HOMING 时） | 0 |
| `EVT_OP_MODE_CONTEXT_SYNC` | service_enabled 变更 / 急停清除 | 0 |
| `EVT_SAFETY_HOME_DONE` | emergency_handler（安全归位完成后） | 0 |
| `EVT_WASH_CUSTOMER_GONE` | 传感器/超时服务（客户已离场） | 0 |

## 5. 核心模块行为契约

### 5.1 command_gateway

**队列参数**

| 常量 | 值 | 说明 |
|------|-----|------|
| `CMD_GATEWAY_QUEUE_SIZE` | 4 | 最大并发等待 submit |
| `CMD_GATEWAY_WAIT_MS` | 5000 | `timeout_ms==0` 时的默认等待 |

**gateway_submit 行为**

1. 在 mutex 下分配空闲 slot，写入 cmd，置 `DEV_CMD_STATUS_BUSY`。
2. 队列满 → 立即返回 `SW_ERR_BUSY`（可选填 receipt）。
3. `event_publish(EVT_CMD_GATEWAY_WAKE)` 失败 → 释放 slot，`SW_ERR_BUSY`。
4. `sem_timedwait` 等待 drain 完成。
5. 超时或 generation 不匹配 → `SW_ERR_TIMEOUT`。
6. 拷贝 receipt，按 status 映射 `sw_err_t` 返回。

**command_gateway_drain 行为**

- 在 **event_dispatch 线程**执行（由 `on_gateway_wake` 或直接测试调用）。
- 扫描所有 used slot：裁决 → 副作用 → 写 receipt → `sem_post`。
- generation 机制防止超时释放后误 post 旧 slot。

### 5.2 operational_mode — 命令矩阵

矩阵值：`OP_PERM_DENIED` / `OP_PERM_ALLOWED` / `OP_PERM_CONDITIONAL`。

**CONDITIONAL 附加规则**：若 `s_estop_active`，拒绝并返回 `OP_REJECT_ESTOP_ACTIVE`。

**业务附加规则**

| 命令 | 附加条件 |
|------|----------|
| `DEV_CMD_START_WASH` | `service_enabled` 且无 blocking 报警 |
| `DEV_CMD_HOME_DEVICE` | `service_enabled`（归位须确认设备可进入运营） |
| `DEV_CMD_RESUME_OPERATION` | 仅当 `!service_enabled` |

**允许时的模式转移**

| 命令 | 模式/标志变更 |
|------|---------------|
| `DEV_CMD_HOME_DEVICE` | → `OP_MODE_HOMING`（副作用完成后经事件桥接 → IDLE 或 EXCEPTION） |
| `DEV_CMD_START_SELF_CHECK` | → `OP_MODE_SELF_CHECK`（记录 `s_self_check_origin`） |
| `DEV_CMD_RECOVER` | → `OP_MODE_RECOVERING` + 发布 `EVT_OP_MODE_RECOVERY_REQUESTED` |
| `DEV_CMD_STOP_OPERATION` | `service_enabled = false` |
| `DEV_CMD_RESUME_OPERATION` | `service_enabled = true` |

**外部生命周期钩子（非命令路径）**

| API | 触发场景 | 状态转移 |
|-----|----------|----------|
| `op_mode_on_wash_session_started` | IDLE | → WASHING |
| `op_mode_on_wash_session_completed` | WASHING | 无 blocking → WASH_DONE；仍有 MAJOR+ → EXCEPTION |
| `op_mode_on_wash_session_aborted(cause)` | WASHING | → ALARM_HOMING + 发布 ALARM_HOME_REQUESTED |
| `op_mode_on_wash_customer_gone` | WASH_DONE | → IDLE |
| `op_mode_on_home_done(success)` | HOMING | 成功 → IDLE；失败 → EXCEPTION |
| `op_mode_on_home_done(any)` | ALARM_HOMING | 始终 → EXCEPTION（忽略 success 参数） |
| `op_mode_on_self_check_completed(land_exception)` | SELF_CHECK | `land_exception=true` → EXCEPTION；否则 → STOPPED |
| `op_mode_on_critical_alarm` | 非 WASHING/ALARM_HOMING/RECOVERING | → EXCEPTION |
| `op_mode_on_estop(true)` | 任意 | → EXCEPTION，标志置位 |
| `op_mode_on_estop(false)` | 任意 | 标志清除，发布 CONTEXT_SYNC |
| `op_mode_on_recovery_completed(result)` | RECOVERING | IDLE 结果 → IDLE；否则 → EXCEPTION |

**日志设计**

| 事件 | 级别 | 格式示例 |
|------|------|---------|
| 正常状态转移 | INFO | `op_mode: STOPPED -> HOMING` |
| 进入 EXCEPTION / ALARM_HOMING | WARN | `op_mode: WASHING -> ALARM_HOMING (critical)` |
| 命令被拒绝 | WARN | `op_mode: cmd 1 rejected (reason=2, mode=STOPPED)` |

### 5.3 side_effect_router

- 入参 `effect == DEV_CMD_EFFECT_NONE` 直接 `SW_OK`。
- HAL 类 effect：`machine_ops_get()` 为 NULL 或函数指针 NULL → `SW_ERR_NOT_INIT`。
- `DEV_CMD_EFFECT_HOME_DEVICE`：调用 `machine_ops.home_device()`，完成后发布 `EVT_OP_MODE_HOME_COMPLETED(1/0)`。

### 5.4 op_mode_bridge — 事件驱动模式转移

`operational_mode` **不订阅** event_bus；异步生命周期由 `op_mode_bridge` 在 dispatch 线程调用 `op_mode_on_*` 完成。

**订阅表**

| 事件 | handler 行为 |
|------|--------------|
| `EVT_WASH_SESSION_STARTED` | `op_mode_on_wash_session_started` |
| `EVT_WASH_DONE` | `op_mode_on_wash_session_completed`（洗后评估） |
| `EVT_WASH_ABORTED` | 解码 cause → `op_mode_on_wash_session_aborted(cause)` → ALARM_HOMING |
| `EVT_WASH_CUSTOMER_GONE` | `op_mode_on_wash_customer_gone` → IDLE |
| `EVT_SAFETY_LOCKOUT` | `op_mode_on_critical_alarm` |
| `EVT_HW_ESTOP_ON` | `op_mode_on_estop(true)` → EXCEPTION |
| `EVT_HW_ESTOP_OFF` | `op_mode_on_estop(false)` → 清标志，发布 CONTEXT_SYNC |
| `EVT_OP_MODE_RECOVERY_COMPLETED` | `op_mode_on_recovery_completed(param)` |
| `EVT_OP_MODE_SELF_CHECK_COMPLETED` | `op_mode_on_self_check_completed(param!=0)` |
| `EVT_OP_MODE_HOME_COMPLETED` | `op_mode_on_home_done(param==1)` → IDLE 或 EXCEPTION |
| `EVT_SAFETY_HOME_DONE` | `op_mode_on_home_done(true)` → EXCEPTION（ALARM_HOMING 路径） |

### 5.5 emergency_handler — 急停与报警归位

| 触发事件 | 行为 |
|----------|------|
| `EVT_HW_ESTOP_ON` | `safety_deferred_stop()` + `wash_orchestrator_abort(WASH_ABORT_ESTOP)` |
| `EVT_HW_ESTOP_OFF` | 无操作（归位须操作员手动触发 HOME_DEVICE 或 RECOVER） |
| `EVT_SAFETY_LOCKOUT` | `wash_orchestrator_abort(WASH_ABORT_CRITICAL)`（归位由 ALARM_HOMING 路径触发） |
| `EVT_OP_MODE_ALARM_HOME_REQUESTED` | 执行 `machine_ops.safety_home()` + 发布 `EVT_SAFETY_HOME_DONE` |

### 5.6 recovery_service — 故障恢复

订阅 `EVT_OP_MODE_RECOVERY_REQUESTED`，触发后：

1. `alarm_registry_recover_all()`
2. `machine_ops.home_device()`
3. 无 lockout 且归位成功 → 发布 `EVT_OP_MODE_RECOVERY_COMPLETED(RECOVERY_RESULT_IDLE)`
4. 否则 → 发布 `EVT_OP_MODE_RECOVERY_COMPLETED(RECOVERY_RESULT_EXCEPTION)`

### 5.7 device_command_port API

```c
sw_err_t (*submit)(const dev_cmd_t *cmd,
                   dev_cmd_receipt_t *receipt,
                   uint32_t timeout_ms);
```

| 条件 | 返回值 |
|------|--------|
| 成功进入业务流水线 | `SW_OK`（receipt 内可能是 REJECTED/FAILED） |
| 队列/事件/硬件错误 | `SW_ERR_BUSY` / `SW_ERR_TIMEOUT` / `SW_ERR_HW` 等 |
| ops 未注册 | 调用方应检查 `device_command_port_get_ops() == NULL` |

---

## 6. 与云端模块的衔接

云端物模型 `DEVICE_CMD` 语义经 wiring 注册 `cloud_point_set_device_cmd_submit()`，内部构造 `dev_cmd_t` 并调用本 port。云端脉冲命令通常只有 `kind`，无 `start_wash.mode` 等载荷；带载荷命令（如 START_WASH）须在 submit 回调中按云平台协议填充 `body.payload`。

详见 `doc/module-design/ports-adapters/CloudModel模块设计.md` §6。

---

## 7. 与事件总线的衔接

| 角色 | 说明 |
|------|------|
| 串行化 | submit 线程与 dispatch 线程解耦；模式状态只在 dispatch 线程变更 |
| 唤醒 | `EVT_CMD_GATEWAY_WAKE` 无载荷；避免在 event param 传递命令指针 |
| 广播 | 模式变更、拒绝、处理完成供上报、日志等订阅 |
| 非命令事件 | 洗车/急停/报警等经 **`op_mode_bridge`** 调用 `op_mode_on_*`，不经过 command_gateway 队列 |

`operational_mode` **不订阅** event_bus；`op_mode_bridge` 须与 `emergency_handler`、`recovery_service` 同处于 dispatch 线程语义下初始化（见 §2.3）。

## 8. 完整接入示例

> **示例（单元测试 / 完整框架，仅供参考）**

```c
/* 启动 */
operational_mode_init();   /* → STOPPED */
command_gateway_init();
alarm_event_bridge_init();
op_mode_bridge_init();
/* 启动 event_dispatch 线程 */

/* 归位进入 IDLE */
dev_cmd_t home_cmd = dev_cmd_make_simple(DEV_CMD_HOME_DEVICE);
dev_cmd_receipt_t receipt;
device_command_port_get_ops()->submit(&home_cmd, &receipt, 1000U);
/* 副作用完成后 EVT_OP_MODE_HOME_COMPLETED → op_mode IDLE */

/* 提交洗车 */
dev_cmd_t wash_cmd = dev_cmd_make_start_wash(WASH_MODE_STANDARD);
device_command_port_get_ops()->submit(&wash_cmd, &receipt, 1000U);
/* ret==SW_OK && receipt.status==DEV_CMD_STATUS_ACCEPTED */
```

## 9. 扩展指南

### 9.1 新增命令种类

1. `device_command.h`：追加 `dev_cmd_kind_t`（保持 `DEV_CMD_MAX` 边界）。
2. `operational_mode.c`：扩展 `k_cmd_matrix` 行、`k_cmd_effects[]` 静态表、`op_mode_handle_command` switch。
3. `side_effect_router.c`：追加 `dev_cmd_effect_t` case（若需副作用）。
4. 更新单元测试与本文档矩阵说明。

### 9.2 新增模式或转移规则

1. 修改 `op_mode_types.h` 中 `operational_mode_t`（影响矩阵列宽，全表审查）。
2. 补充 `op_mode_on_*` 钩子供 orchestrator/bridge 调用。
3. 评估 `EVT_OP_MODE_CHANGED` 消费方。

### 9.3 禁止的扩展方式

- 在 CLI/MQTT 线程直接调用 `op_mode_handle_command` 或 orchestrator。
- 在 `operational_mode` 内调用 `machine_ops` 或 `wash_orchestrator_start`。
- 扩大 `CMD_GATEWAY_QUEUE_SIZE` 而不评估 dispatch drain 延迟。
