**版本**：v1.0  
**状态**：已落地（追踪上下文 + 资产版本 helper）

**架构基线**：线程局部因果关联 + 语义化版本兼容判定  
**关键词**：trace_context、asset_version、correlation、semver

## 1. 设计目标与核心理念

本篇覆盖 `common/` 中两项横切能力：跨线程业务因果上下文，以及项目资产 schema 版本的解析与兼容判定。二者都不承载设备业务规则，可被 runtime / application / observability / 项目 loader 复用。

### 1.1 设计目标

- **因果可关联**：命令、事件、观测记录能携带同一组会话/命令/关联/因果 ID。
- **版本问题前置**：资产与框架不匹配时在加载期失败，而不是运行期字段错位。
- **框架不感知资产内容**：只提供版本表达与判定；格式与表内容仍在项目侧。

## 2. 分层归属与依赖方向

| 模块 | 路径 | 依赖 |
|------|------|------|
| 追踪上下文 | `common/trace_context.*` | 仅标准整数类型 |
| 资产版本 | `common/asset_version.*` | `common/sw_error.h` |

二者均属 `wdf_common`。上层可依赖它们；它们不得依赖 domain / application / adapters。

`observation_context_t` 是 `trace_context_t` 的类型别名（见可观测性专篇）：同一四字段模型，差别只在存储——`trace_context` 为线程局部「当前链路」，observation 另有可显式设置的「记录默认上下文」。

## 4. 数据模型与核心行为契约

### 4.1 `trace_context_t`

| 字段 | 含义 |
|------|------|
| `wash_session_id` | 洗车会话编号；非洗车为 0 |
| `command_id` | 当前根命令编号；无命令来源为 0 |
| `correlation_id` | 整条关联链编号 |
| `causation_id` | 直接父命令或父事件编号 |

| API | 契约 |
|-----|------|
| `trace_context_get()` | 返回当前线程上下文值拷贝；未设置时各字段为 0 |
| `trace_context_set(ctx)` | 设置当前线程上下文；`NULL` 表示清空 |

事件总线在派生/转发路径上传播该上下文（见 EventBus 测试）。命令网关在提交路径写入命令相关字段。

### 4.2 `asset_version_t`

| 字段 | 含义 |
|------|------|
| `major` / `minor` / `patch` | 语义化版本分量 |
| `valid` | 解析是否成功 |

兼容规则：

| 条件 | 结果 |
|------|------|
| 主版本不同 | 不兼容（结构性变更） |
| 资产次版本高于框架支持 | 不兼容（可能含未知字段） |
| 资产次版本低于或等于框架 | 兼容（框架向后兼容旧资产） |
| 修订号 | 不参与判定 |
| 资产解析失败 | 一律不兼容 |

| API | 契约 |
|-----|------|
| `asset_version_parse(text)` | 接受 `"1.0"` / `"1.0.3"`；不接受空白或多余字符 |
| `asset_version_is_compatible(asset, supported)` | 按上表判定 |
| `asset_version_check(...)` | 解析失败 → `SW_ERR_PARAM`；可解析但不兼容 → `SW_ERR_STATE` |

刻意不做「未知字段自动忽略」：安全相关资产静默忽略未识别字段等于放行缺失约束。

## 5. 测试覆盖

| 测试名 | 覆盖点 |
|--------|--------|
| `test_asset_version` | 解析合法/非法串、兼容与不兼容组合、`check` 的 PARAM/STATE 区分 |
| `test_event_bus`（`test_trace_context_propagates_to_derived_event`） | 追踪上下文传播到派生事件 |

`trace_context` 无独立测试目标；线程局部 get/set 由 event_bus / command_gateway 路径间接覆盖。不另造不存在的测试名。

用例数与通过情况以 `scripts/check_all.sh` 报告为准。

## 6. 当前落地状态与扩展指南

| 能力 | 状态 |
|------|------|
| 线程局部追踪上下文 | 已落地 |
| 事件派生传播 | 已落地（event_bus） |
| 资产版本解析与兼容判定 | 已落地 |
| 各项目资产在 loader 中强制调用 `asset_version_check` | 项目侧接入进度不一 |

项目 loader 应在解析资产头后调用 `asset_version_check`，把版本问题留在启动/加载期。新增关联字段须同步改 `trace_context_t` 与 observation 别名约定，禁止再定义第二套四元组。
