# 可观测性模块设计

**版本**：v1.0  
**状态**：已落地（观测核心 + 黑匣子 + 可选事件桥接）  
**最后同步代码**：2026-08-08（`observability/core`、`observability/recorder`、`observation_event_bridge`）  
**适用范围**：`observability/core/`、`observability/recorder/`、`application/bridges/observation_event_bridge.*`  
**架构基线**：旁路诊断 + 非阻塞入队 + 项目可选挂接  
**关键词**：observation、blackbox、observation_event_bridge、双队列、非阻塞

---

## 1. 设计目标与核心理念

可观测层是与业务无关的旁路诊断设施：业务路径只发事件或调领域 API，诊断记录由旁路队列承接。它不参与命令裁决、报警事实或安全切断。

### 1.1 设计目标

- **旁路**：只依赖 `common/`，不回调 domain / application / adapters。
- **非阻塞**：`observation_publish` / `blackbox_recorder_record` 不动态分配、不落盘、不阻塞业务热路径；满则丢弃并计数。
- **可选**：项目可不启用；框架 `bootstrap` 不自动挂接事件桥接。
- **集中决策**：哪些框架事件值得留痕，集中在 `observation_event_bridge`，避免各层直接依赖 observability。

### 1.2 数据流

```text
业务路径发布 EVT_*
        │
        ▼
event_bus dispatch
        │（项目显式启用时）
        ▼
observation_event_bridge
        │ observation_publish（非阻塞）
        ▼
observation 双队列 ──► 项目消费（落盘/外发，框架不规定）
        ▲
其它发布方（诊断/测试）也可直接 publish

blackbox_recorder：项目周期采样 → trigger 冻结窗口 → 导出后 release
```

## 2. 分层归属与依赖方向

| 层次 | 路径 | 职责 |
|------|------|------|
| 观测核心 | `observability/core/observation.*` | 记录模型、双队列、publish / try_pop / 统计 |
| 黑匣子 | `observability/recorder/blackbox_recorder.*` | 循环采样、触发、冻结、导出、重新布防 |
| 事件桥接 | `application/bridges/observation_event_bridge.*` | 订阅框架事件并转为观测记录 |

```text
application/bridges/observation_event_bridge
        │ include
        ▼
observability/core + runtime/event_bus + common
```

**依赖禁令**：

- `observability/` 不得依赖 `domain/`、`application/`、`adapters/`、`runtime/`（除测试外）。
- `event_bus` / `domain` 不得反向依赖 observability。
- 桥接不得在 publish 失败时重试或阻塞分发线程。

## 4. 数据模型与核心行为契约

### 4.1 观测记录

| 常量 | 值 | 含义 |
|------|----|------|
| `OBSERVATION_NORMAL_QUEUE_CAPACITY` | 256 | 普通队列 |
| `OBSERVATION_CRITICAL_QUEUE_CAPACITY` | 32 | 关键队列（`try_pop` 优先） |
| `OBSERVATION_PAYLOAD_MAX` | 256 | 单条载荷上限 |
| `OBSERVATION_SOURCE_MAX` | 32 | source 字符串上限 |

`observation_context_t` 是 `trace_context_t` 的类型别名：线程局部「当前链路」与观测「默认上下文」共用同一四字段模型，避免两套标识演进失同步。

| API | 契约 |
|-----|------|
| `observation_init(boot_id)` | `boot_id != 0`；未初始化时 publish 返回 `SW_ERR_NOT_INIT` |
| `observation_is_ready()` | 装配层据此决定是否挂桥接 |
| `observation_publish(spec)` | 非阻塞；忙或满返回 `SW_ERR_OVERFLOW` 并计入 drop 统计 |
| `observation_try_pop(out)` | 关键队列优先；空则 `SW_ERR_NOT_FOUND` |

### 4.2 黑匣子

状态：`ARMED` → `POST_TRIGGER` → `FROZEN` → `release` 回 `ARMED`。

| API | 契约 |
|-----|------|
| `blackbox_recorder_init(cfg)` | 窗口采样数不得超过 `BLACKBOX_SAMPLE_CAPACITY`（2048） |
| `blackbox_recorder_record` | 非阻塞；冻结或锁忙返回 `SW_ERR_OVERFLOW` |
| `blackbox_recorder_trigger` | 已有未导出窗口时 `SW_ERR_BUSY` |
| `blackbox_recorder_copy_sample` | 仅 `FROZEN` 可读；否则 `SW_ERR_BUSY` |
| `blackbox_recorder_release` | `incident_id` 必须匹配当前窗口 |

### 4.3 事件桥接

| 约束 | 说明 |
|------|------|
| 调用时机 | `observation_init` + `event_bus_init` 之后、`scheduler_start_all` 之前；由项目在 `init_adapters` 显式调用 |
| 不自动挂接 | 避免与项目自有事件投影重复产生两条不同编码的记录 |
| 载荷 | `event_code` = 框架 `event_type_t`；载荷为 4 字节 `evt->param` |
| 失败策略 | publish 失败不影响业务分发 |

bootstrap / 切断失败等 event_bus 尚未就绪或自身故障的路径不在本桥接覆盖范围。

## 6. 当前落地状态与扩展指南

| 能力 | 状态 |
|------|------|
| 观测双队列与 publish/pop | 已落地 |
| 黑匣子循环采样与冻结窗口 | 已落地 |
| 框架事件桥接（可选） | 已落地 |
| 记录落盘 / 网络外发 | 项目侧职责 |
| 项目语义 event_code / 黑匣子联动投影 | 项目自实现，跳过本桥接 |

扩展时优先新增桥接订阅项或项目投影，不在 domain / event_bus 内直接调用 `observation_publish`。
