## 测试架构

### 分层覆盖策略

```
domain/device/mechanism/
├── gantry.c            → test_gantry            37 用例   （MCC 仿真桩）
├── brush.c             → test_brush              40 用例   （MCC 仿真桩，2 电机槽位）
├── fan.c               → test_fan                37 用例   （MCC 仿真桩）
├── lift.c              → test_lift               41 用例   （MCC 仿真桩）
└── rear_lock.c         → test_rear_lock          40 用例   （MCC 仿真桩）
```

侧刷/顶刷共用一台 VFD、靠接触器切换的时序，从 2026-07-03 起改由 MCC 原生机制管理
（侧刷/顶刷各占一个 `motor_executor_t` 电机槽位，通过 `motor_driver_t::prepare` 触发
接触器切换，配合 `MOTOR_INTERLOCK_MUTEX` 双向互锁）。`brush.c` 因此从自建状态机
简化为薄封装。接触器切换的两阶段定时状态机最初被抽成独立模块
`domain/device/mechanism/contactor_switch.c`（配套 `test_contactor_switch`，12 用例，
固定 `now_ms` 序列驱动），但唯一的真实调用方始终是 `machines/m8/adapters/setup/
m8_motor_exec.c`（适配器层），并非任何领域模块；为避免"电机管理分散在多个模块"，
已将该逻辑内联进 `m8_motor_exec.c`，`contactor_switch.c` 与 `test_contactor_switch`
均已删除（见下方"局限"）。

### 底层 MCC 库桩

gantry / brush / fan / lift / rear\_lock 五个测试均链接 `tests/stubs/mcc/motor_control_core_sim.c`
（x86\_64 仿真桩），替代 aarch64 预编译库。仿真桩行为：

| MCC API | 仿真行为 |
|---------|---------|
| `motor_run_continuous` | 立即置 `MOTOR_PHASE_RUNNING` + 记录方向/频率 |
| `motor_move_to` | 同上（忽略 spec） |
| `motor_stop` | 立即置 `MOTOR_PHASE_STOPPED` |
| `motor_home` | 立即置 `STOPPED`，`position=0`，`baseline_trusted=true` |
| `motor_set_speed` | 更新 `target_freq` 和 `dir`，phase 不变 |
| `motor_recover(MODULE_STOP)` | 置 `STOPPED`，清 fault/fault\_code |
| `motor_tick` | 空操作 |

测试中注入故障态的方式：直接写 `s_exec.m[0].phase = MOTOR_PHASE_FAULT`（
`motor_executor_t` 结构体对外公开支持静态分配）。

**局限**：仿真桩完全不模拟 `prep_required`/`prepare()`/互锁——`motor_run_continuous`
无条件立即置 `RUNNING`。因此 `m8_motor_exec.c` 里 brush 的 `prepare()` 回调（接触器
切换状态机）在 sim 环境下不会被真正触发；这部分集成路径无法通过 ctest 验证，只能
人工走查配置字段。接触器切换的定时逻辑内联进 `m8_motor_exec.c` 之后，也不再有
独立的单元测试覆盖（原 `test_contactor_switch` 已随 `contactor_switch.c` 一并删除），
与该文件其余部分现有的局限一致。

### fan 模块的计时测试

`fan.c` 使用真实时钟（`common/time_util.c`，`CLOCK_MONOTONIC`）管理复位脉冲超时。
测试中将 `reset_pulse_ms` 配置为 **10ms**，并在需要模拟超时的用例中使用
`usleep(20000)`（20ms）等待后再调 `fan_tick()`，兼顾可靠性与执行速度。

不需要模拟超时的用例（验证"脉冲期间仍停留 RESETTING"）在 `fan_reset()` 后立即
调 `fan_tick()`，elapsed 远小于 10ms，行为确定。

### 测试隔离与 setUp 约定

所有测试文件共同约定：

- `setUp()` 只重置底层资源（MCC exec 或 IO mock 状态），不调用领域层 init；
- "未初始化保护"用例须在 `main()` 中**排在最前面**运行，确保领域层内部
  静态指针仍为 NULL（C 静态变量上电值）；
- 其余用例在函数体内第一行显式调用 init，保证状态完全可重复。

### 构建与运行

```bash
cmake -B build_sim -DBUILD_SIM=ON
cmake --build build_sim -j4
ctest --test-dir build_sim -R 'test_gantry|test_brush|test_fan|test_lift|test_rear_lock' -V
```

## test_brush（刷子机构）— 40 个用例，全部通过

> `brush.c` 现在是 `motor_executor_t` 的薄封装，支持任意数量刷子槽位与可配置
> 互锁对（`brush_interlock_pair_t`，由项目层在 `brush_init()` 时注入）：声明为
> 互锁的两个槽位，任一方启动前会自动停止另一方；未声明互锁的槽位互不影响，
> 可同时运行。`brush_id_t` 不再是具名枚举，而是项目层分配的槽位索引；侧刷/
> 顶刷这类具体命名已下沉到 `projects/m8/config/m8_brush_ids.h`。接触器切换
> 时序、冷却排队由 MCC 负责，本层只负责按互锁配置转发命令，不再自建状态机。
> 停止类接口（`brush_stop`/`brush_stop_all`）不检查故障状态，只有启动类接口
> 检查目标槽位自身故障，对齐 `fan.c` 的既有约定。

## test_fan（风机机构）— 37 个用例，全部通过

> `fan.c` 通过注入的 `fan_io_ops_t` 回调控制风机变频器的启停与复位，不依赖 MCC。
> 状态机：IDLE ↔ RUNNING（正常运行），报警时 tick 自动→ FAULT；
> `fan_reset()` 激活 FAN\_RESET DO 并进入 RESETTING，由 tick 检测脉冲超时后清除。

### 测试 Mock 设计

```c
static bool s_start_on;   /* FAN_START DO 当前电平 */
static bool s_reset_on;   /* FAN_RESET DO 当前电平 */
static bool s_alarm;      /* FAN_ALARM DI 模拟值（测试中手动设置） */

static sw_err_t mock_set_start(void *ctx, bool on) { s_start_on = on; return SW_OK; }
static sw_err_t mock_set_reset(void *ctx, bool on) { s_reset_on = on; return SW_OK; }
static bool     mock_read_alarm(void *ctx)          { return s_alarm; }
```

配置：`reset_pulse_ms = 10`（ms），超时测试使用 `usleep(20000)`（20ms）。
