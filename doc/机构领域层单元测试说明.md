# 机构与运动模式单元测试说明

**测试日期**：2026-07-11  
**测试范围**：framework `device_control/patterns/` 运动模式库 + M8 命名机构 `projects/m8/domain/mechanism/gantry`  
**测试结果**：149 个用例全部通过，0 失败

---

## 测试架构

### 分层覆盖策略

改造后采用 **framework 测模式、项目测命名机构** 的分工：

```text
framework/domain/device_control/patterns/
├── bidirectional_motion.*  → test_bidirectional_motion   41 用例
├── continuous_rotary.*     → test_continuous_rotary       27 用例
├── interlocked_slots.*     → test_interlocked_slots       40 用例
└── fluid_path.*            → test_fluid_path               4 用例

projects/m8/domain/mechanism/
└── gantry.*                → test_m8_gantry               37 用例
```

M8 其余命名机构（`m8_top_brush_lift`、`m8_brush_rotation`、`m8_fan`、`m8_rear_lock`）由上述 pattern 测试覆盖共性行为；项目层仅保留命名映射与 lifecycle 注入差异，不重复单测。

### 底层 MCC 库桩

电机类 pattern 与 `test_m8_gantry` 均链接 `tests/stubs/mcc/motor_control_core_sim.c`（x86_64 仿真桩），替代 aarch64 预编译库。仿真桩行为：

| MCC API | 仿真行为 |
|---------|---------|
| `motor_run_continuous` | 立即置 `MOTOR_PHASE_RUNNING` + 记录方向/频率 |
| `motor_move_to` | 同上（忽略 spec） |
| `motor_stop` | 立即置 `MOTOR_PHASE_STOPPED` |
| `motor_home` | 立即置 `STOPPED`，`position=0`，`baseline_trusted=true` |
| `motor_set_speed` | 更新 `target_freq` 和 `dir`，phase 不变 |
| `motor_recover(MODULE_STOP)` | 置 `STOPPED`，清 fault/fault_code |
| `motor_tick` | 空操作 |

测试中注入故障态：直接写 `s_exec.m[n].phase = MOTOR_PHASE_FAULT`（`motor_executor_t` 支持静态分配）。

**局限**：仿真桩不模拟 `prep_required`/`prepare()`/互锁——`motor_run_continuous` 无条件立即置 `RUNNING`。因此 `m8_motor_exec.c` 里 brush 的 `prepare()` 回调（接触器切换）在 sim 环境下不会被真正触发；集成路径需场景测试或人工走查。

### 测试隔离与 setUp 约定

| 模块 | setUp 约定 |
|------|------------|
| pattern 测试 | 重置 `motor_executor_t`；pattern 实例（`bidirectional_motion_t` 等）`memset` 为未初始化 |
| `test_m8_gantry` | 重置 exec；不在 setUp 调 `gantry_init`，未初始化用例须排在 `main()` 最前 |
| `test_fluid_path` | mock 槽位状态清零；`tearDown` 调 `fluid_path_all_off` 并 drain poll |

各用例在函数体内按需调用 `*_init()`，保证可重复。

### 构建与运行

```bash
cmake -B build_sim -DBUILD_SIM=ON
cmake --build build_sim -j4
ctest --test-dir build_sim -R 'test_bidirectional|test_continuous|test_interlocked|test_fluid|test_m8_gantry' -V
```

## test_bidirectional_motion（双向往复模式）— 41 用例

源文件：`tests/framework/domain/test_bidirectional_motion.c`  
被测 API：`bidirectional_motion_init/run/stop/home/state/recover`  
覆盖：未初始化保护、参数校验、正/反方向运行、停止/归位、phase→state 映射、故障阻断与恢复。

---

## test_continuous_rotary（连续旋转模式）— 27 用例

源文件：`tests/framework/domain/test_continuous_rotary.c`  
被测 API：`continuous_rotary_init/start/stop/state/recover`  
覆盖：未初始化保护、启动/停止、RUNNING/STOPPING/FAULT 状态映射、故障阻断与恢复。

> 注：旧版 `fan.c` 基于 DO 脉冲复位的状态机已移除；M8 风机现组合 `continuous_rotary` + 电机槽位，不再提供 `fan_tick`/`fan_reset`。

## test_interlocked_slots（多槽互锁模式）— 40 用例

源文件：`tests/framework/domain/test_interlocked_slots.c`  
被测 API：`interlocked_slots_init/start/stop/stop_all/state/fault_code`  
覆盖：互锁配置、独立运行（无互锁）、同槽调速、槽位级故障隔离、`stop_all`。

## test_fluid_path（流体路径模式）— 4 用例

源文件：`tests/framework/domain/test_fluid_path.c`  
被测 API：`fluid_path_init/set/all_off/poll/is_settled`  
覆盖：初始化全关、单路开启、并行路径共享泵、非阻塞请求与 poll 收敛。  
编译宏 `FLUID_PATH_UNIT_TEST=1` 暴露 poll 接口供单测主动推进时序。

---

## test_m8_gantry（M8 龙门命名机构）— 37 用例

源文件：`projects/m8/tests/test_m8_gantry.c`  
被测模块：`projects/m8/domain/mechanism/gantry.c`（组合 `bidirectional_motion`）

> `gantry.c` 保留 M8 语义 API（`gantry_move_fwd/rev/stop/home/...`），并在 stop/recover 成功时发布 `actuator_publish_motion_completed(M8_ACTUATOR_GANTRY)`；不含报警头文件。

覆盖：未初始化保护、init 参数、前进/后退、停止/归位、phase→`gantry_state_t` 映射、故障与恢复、lifecycle 相关行为与 pattern 一致的部分。
