# 任务索引

常见改动 → 必须一起改的位置。**本文件手工维护**：它记的是判断（"改这个必须同时改
那个"），不是可从代码抽取的数据，与同目录另两份自动生成的索引不同。

框架的硬约束大量落在容易漏改的登记点上：新增一个 `.c` 要在构建清单登记，新增
provider 要配 CMake 选项与 include 白名单，新增事件要同步容量断言。漏掉任何一处，
症状都不是编译失败，而是门禁在另一个位置报一条看起来无关的错。本文件把这些成组
出现的位置显式列出。

配套：符号定位见 `符号索引.md`，目录与目标对应见 `代码地图.md`，
设计取舍见 `../architecture/`，代码级契约见 `../module-design/`，
行为归属与验证级别见 `../contract/行为契约.md`。

---

## 新增框架源文件（`.c`）

| 步骤 | 位置 | 漏掉的后果 |
|------|------|-----------|
| 1 | 登记到 `cmake/wdf_targets.cmake` 对应 INTERFACE 目标 | R7 失败：框架层 `.c` 未被任何目标登记 |
| 2 | 若刻意不导出，登记到 `scripts/check_arch_boundary.sh` 的 `UNEXPORTED_SOURCES` | 同上 |
| 3 | 确认所属层的出向依赖合规（见下节） | R1~R5、R11~R14 之一失败 |

R7 顺带能抓出框架自身的死代码：任何不被构建的框架文件都会在此暴露。

## 新增头文件（`.h`）

保护宏必须等于路径的全大写下划线形式，否则 R15 失败。例：
`domain/safety/model/alarm_types.h` → `DOMAIN_SAFETY_MODEL_ALARM_TYPES_H`。

无路径前缀的短宏（`DRV_VFD_H` 这类）曾在本仓大量存在：vendor SDK 出现同名宏时，
后包含的头被静默跳过，报"类型未定义"而非重复定义，排查成本远高于改名成本。

## 各层允许的出向依赖

| 层 | 允许依赖 | 检查规则 |
|----|----------|----------|
| `common/` | 无 | R1 |
| `domain/` | `common`、`ports`、`runtime`（仅 event_bus） | R2、R9 |
| `ports/` | `common`、`domain` | R3 |
| `runtime/event_bus`、`runtime/scheduler` | `common` | R4、R5 |
| `application/` | `common`、`domain`、`ports`、`runtime` | R11 |
| `services/` | `common`、`domain`、`ports` | R13 |
| `observability/` | `common` | R14 |
| `adapters/` | 以上各层 | — |

`domain/` 另有四条层内禁令（R9a~R9d）：不做文件 IO、不解析序列化格式、不自建线程
或周期任务、不使用动态内存。方案引擎三个文件按加载期一次性分配登记了动态内存豁免。

全框架禁止 `../` 形式的 include（R8）——它指向真实框架文件，能通过 R6 的可解析性
判定，却会绕过 R1~R5 的路径前缀匹配。

## 新增事件

| 步骤 | 位置 |
|------|------|
| 1 | 在 `common/event_types.h` 对应类别下追加 `EVT_<CAT>_ID_*` 与 `EVT_*` 宏 |
| 2 | 若类内槽位将满，检查 `EVT_PER_CAT_MAX`（当前 32） |
| 3 | 订阅方在自己的 `*_init()` 内 `event_subscribe` 或注册订阅表 |
| 4 | 单事件订阅者数不得超 `EVENT_BUS_MAX_SUBS_PER_EVT`（当前 8） |
| 5 | 若 param 承载多字段，在 `domain/op_mode/op_mode_types.h` 加 encode/decode inline 函数，不在调用点手写 `<<` / `&` |
| 6 | 重新生成 `符号索引.md`（`./scripts/gen_doc_index.py`） |

新增**类别**须同时确认 `EVT_CAT_MAX` 与统计数组下标（`published_by_cat[]` 等）容量。

param 只允许 `uint32_t` 标量。复杂状态由订阅方向领域模块查询，不塞进事件——
载荷一旦变复杂，事件顺序与状态一致性就无法再靠单一 dispatch 线程保证。

## 新增端口

| 步骤 | 位置 |
|------|------|
| 1 | 在 `ports/` 下建契约头，含 `@brief`（符号索引从此抽取职责列） |
| 2 | 在对应 `ports/port_registry_*.c` 加 `*_register()` / `*_get_ops()` |
| 3 | `*_register()` 返回 `sw_err_t`；`ops == NULL` 语义为解除注册，返回 `SW_OK` |
| 4 | 必填函数指针缺失返回 `SW_ERR_PARAM`，且**保持原注册不变**——不得被半个 ops 覆盖 |
| 5 | 在 `ports/port_registry.h` 声明该注册表的 `*_reset()` |
| 6 | 若为必需端口，在 `ports/port_contract.h` 加 `PORT_REQ_*` 位 |
| 7 | 单元测试覆盖：合法注册、NULL 解除、缺必填字段被拒、重复注册替换、复位清空 |

必填字段只限调用方会无条件解引用的入口。允许注册能力子集的端口（HAL、machine_ops、
cloud）不设必填，由调用方逐个判空。

## 新增 vendor provider

| 步骤 | 位置 |
|------|------|
| 1 | 源码放 `adapters/**/providers/<vendor>/` |
| 2 | 根 `CMakeLists.txt` 加 `option(WDF_ENABLE_*)` 与 STATIC 库定义 |
| 3 | vendor SDK 头前缀登记到 `check_arch_boundary.sh` 的 `VENDOR_INCLUDE_ALLOW` |
| 4 | 确认该头只在 `adapters/**/providers/` 下被引用，否则 R6 报位置违规 |

第 3 步刻意要求显式登记：这一步正是要让评审看见新的外部依赖。

## 新增必需资产校验

端口契约（`ports/port_contract.h`）答「函数表是否注册」，资产契约
（`application/asset_contract.h`）答「数据是否就位」。两者是同一问题的两面——
端口注册了但资产没加载，业务链路同样在第一次真实调用才失败，而启动日志一切正常。

新增资产位：加 `ASSET_REQ_*`，补探测入口（如 `alarm_registry_catalog_count()`），
在项目侧 `project_validate()` 声明该位。只答「有没有」，不答「对不对」——字段级
校验由各自的 validate 函数负责。

## 新增周期任务或线程

| 步骤 | 位置 |
|------|------|
| 1 | 在 `project_register_runtime_tasks()` 或框架模块 `*_init()` 内 `thread_register` / `periodic_task_register` |
| 2 | 栈大小常量加到 `runtime/config/thread_config.h` |
| 3 | 确认不超 `THREAD_REGISTRY_MAX`（当前 24，`PERIODIC_TASK_MAX` 与之对齐并有编译期断言） |
| 4 | 若持有互斥量，在 `check_arch_boundary.sh` 登记 RT 可达性分类（R16） |
| 5 | 若含阻塞等待，在 R18 的三张表之一登记该等待点 |

第 4、5 步未登记即报错，强制作者表态。分类取保守侧：对非 RT 锁启用优先级继承的
代价不可测量，对 RT 锁漏启用的代价是无界优先级反转。

领域层不自建线程（R9c），时序推进由调用方驱动 tick。

## 调整容量常量

改 `EVENT_BUS_QUEUE_SIZE` 这类常量时，同步更新三处：常量定义处的实测依据注释、
`tests/runtime/test_event_bus_capacity.c` 的断言门限、
`../history/整治记录.md` 第 3.3 节的余量表格。

容量常量不是拍定的数，都附有按真机最密周期档压测的实测依据。

## 改动文档

| 情形 | 要求 |
|------|------|
| 引用代码路径或函数名 | 必须真实存在，否则 D1/D2 失败 |
| 文档间互引 | 链接必须可解析，否则 D3 失败 |
| 记录已删除的符号或路径 | 登记到 `check_doc_refs.sh` 的 `PATH_ALLOW` / `SYMBOL_ALLOW` 并写理由 |
| 改了被索引的代码 | 重新生成 `doc/ai/` 下的索引 |

`architecture/` 只写方案与取舍，不写结构体字段、完整 API 表和测试细节；
`module-design/` 必须与当前代码一致；`doc/ai/` 两份索引自动生成，不手工编辑。
