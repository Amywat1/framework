# 执行器（Actuator）功能设计说明

**版本**：v1.0  
**适用范围**：`domain/device/actuator/` 通用电机管理层  
**关联代码**：`domain/device/actuator/motor/`、`machines/m8/config/m8_motor_table.h`、`ports/hal/hal_motor_port.h`

---

## 1. 概述

### 1.1 定位

执行器领域层负责将上层业务对「电机运动」的语义化指令，转化为可安全执行的硬件控制序列。当前实现为**通用电机管理层**（`motor` 模块），对上提供统一 API，对下通过 `hal_motor_ops_t` 端口访问 VFD、数字 IO、编码器计数板等硬件能力。

在分层架构中的位置：

```text
application / mechanism（龙门、侧刷等业务语义）
        │
        ▼  motor_hold / motor_move / motor_stop ...
domain/device/actuator/motor
        │
        ▼  hal_motor_ops（set_output / set_gear / read_current ...）
ports/hal + adapters（机型 setup、drv_vfd、IO 驱动）
        │
        ▼
物理设备（VFD、接触器、编码器、限位开关）
```

### 1.2 设计目标

| 目标 | 实现方式 |
|------|----------|
| 配置与逻辑分离 | 电机差异写入机型配置表（`m8_motor_table`），通用状态机与 tick 逻辑复用 |
| 两种动作语义 | `MOTOR_ACTION_HOLD`（持续运行）与 `MOTOR_ACTION_MOVE`（有完成条件） |
| 共享 VFD 安全 | 停止后延迟启动（`post_stop_delay_ms`）+ 启动前回调（`pre_start_cb`） |
| 运行时监测 | 10ms 周期线程采样编码器、VFD 电流/状态，自动判定完成与故障 |
| 线程安全 | 对外 API 持互斥锁；耗时 IO 在无锁区执行，避免死锁 |

### 1.3 模块文件

| 文件 | 职责 |
|------|------|
| `motor.h` | 对外公开接口与类型定义 |
| `motor.c` | 初始化、状态机、命令入口、PENDING 启动逻辑 |
| `motor_internal.h` | 内部共享结构体、常量、跨文件声明 |
| `motor_tick_internal.c` | 10ms 周期线程编排 |
| `motor_encoder_internal.c` | 编码器计数、清零、零位确认、异常检测 |
| `motor_monitor_internal.c` | VFD 电流/状态采样与故障传播 |

## 2. 配置模型

每台电机在机型配置表中描述为一条 `motor_cfg_t` 记录，由 `motor_init()` 加载到运行时映射表 `s_cfg_map[]`。

### 2.1 核心字段

| 字段组 | 字段 | 含义 |
|--------|------|------|
| 标识 | `id`, `name` | 电机 ID 与调试名 |
| 驱动 | `drv_type`, `vfd_id` | 驱动类型（当前仅 VFD）及 HAL VFD 实例 ID |
| 语义 | `action_type` | `MOTOR_ACTION_HOLD` 或 `MOTOR_ACTION_MOVE` |
| 方向 IO | `io_cw`, `io_ccw`, `io_stop`, `io_vel0`, `io_vel1` | 接触器/方向/速度档位等 DO |
| 限位 | `limit_mode`, `limit_io_cw/ccw`, `limit_pos_min/max` | 限位模式与 IO/位置范围 |
| 超时 | `timeout_ms` | 运动超时；`MOTOR_TIMEOUT_FOREVER` 表示不限 |
| 编码器 | `has_encoder`, `encoder_backend`, `encoder_io`, `encoder_zero_io` 等 | 是否带编码器及后端类型、异常阈值 |
| 电流监测 | `current_high/low_threshold`, `current_check_delay_ms`, `current_confirm_ms` | VFD 过/欠流判定参数 |
| 延迟启动 | `post_stop_delay_ms` | 停止后再次启动前的最短等待（共享 VFD + 接触器场景） |

### 2.2 动作类型约束

- **`MOTOR_ACTION_HOLD`**：仅允许 `motor_hold()` / `motor_hold_gear()`；无运动完成回调。
- **`MOTOR_ACTION_MOVE`**：允许 `motor_move()` 及内部的位置/定时运动；满足完成条件时触发 `motor_done_cb_t`。

对动作类型不匹配的 API 调用返回 `SW_ERR_PARAM`。

### 2.3 M8 机型实例

| 电机 | action_type | 特点 |
|------|-------------|------|
| `MOTOR_BRUSH`（侧刷） | HOLD | VFD 挡位模式、仅正转、`post_stop_delay_ms = 200ms` |
| `MOTOR_GANTRY`（龙门） | MOVE | VFD 频率模式、正反转、硬件编码器、限位信号、`timeout_ms = 60s` |

## 3. 状态机

### 3.1 状态定义

```text
IDLE ──启动──► PENDING ──延迟到期+pre_start──► HOLD / MOVE
  ▲               │                              │
  │               │ stop 取消                     │ MOVE 子状态
  └── stop ◄──────┘                              ├── MOVE_POS（位置到位）
                                                 ├── MOVE_TIME（定时到期）
                                                 └── PAUSE（暂停，可 resume）
任何非法迁移或硬件失败 ──► FAULT ──fault_reset/reset_fault──► IDLE
```

| 状态 | 说明 |
|------|------|
| `IDLE` | 停止，无 VFD 输出 |
| `PENDING` | 已接收启动命令，等待 `post_stop_delay_ms` 到期；到期后由 tick 调用 `pre_start_cb` 并真正输出 |
| `HOLD` | 持续运行（侧刷等） |
| `MOVE` | 持续运动，直到限位/超时/手动停止 |
| `MOVE_POS` | 按编码器位置运动，到达目标后自动完成 |
| `MOVE_TIME` | 定时运动，时间到后自动完成 |
| `PAUSE` | 暂停（保留 `speed_ref` 与累计暂停时长） |
| `FAULT` | 故障安全态，已切断输出 |

### 3.2 迁移规则

状态迁移由 `s_transition[][]` 静态表校验，非法迁移记录错误日志并返回 `SW_ERR_STATE`。

**运行态判定**（`motor_is_running()`）：

- 计入：`HOLD`、`MOVE`、`MOVE_POS`、`MOVE_TIME`
- 不计入：`PENDING`（延迟排队中）、`IDLE`、`PAUSE`、`FAULT`

### 3.3 故障进入

进入 `FAULT` 时统一执行：

1. 调用 `ops->set_output(id, 0)` 切断输出
2. 清零运动参数，记录 `stop_timestamp_ms`
3. 状态置为 `MOTOR_STATE_FAULT`

触发源包括：HAL 输出失败、VFD 过/欠流、VFD 状态不一致、运动超时等。

## 4. 控制模式

### 4.1 频率模式

通过 `motor_hold()` / `motor_move()` 传入 `speed_ref`：

- `speed_ref > 0`：正转
- `speed_ref < 0`：反转
- `speed_ref == 0`：等价于 `motor_stop()`

底层调用 `hal_motor_ops_t.set_output()`，绝对值含义由机型 HAL 注入方定义（通常为 VFD 频率 Hz）。

### 4.2 挡位模式

通过 `motor_hold_gear()` / `motor_move_gear()` 传入 `motor_gear_t`（1~4 档）及方向：

- `motor_hold_gear`：始终正转，适用于侧刷
- `motor_move_gear`：可指定 `fwd` 正反转

底层调用 `hal_motor_ops_t.set_gear()`；挡位寄存器映射由机型 setup 层完成。

## 5. 延迟启动（PENDING 机制）

### 5.1 触发条件

当满足以下**任一**条件时，启动命令不立即输出，而是进入 `PENDING`：

1. 配置项 `post_stop_delay_ms > 0`
2. 已注册 `motor_set_pre_start_cb()`

典型场景：**多台电机共享同一 VFD**，切换接触器前须确保 VFD 已完全停止。

### 5.2 执行流程

```text
motor_hold/move(_gear)
        │
        ├─ 无延迟且无 pre_start ──► motor_start_locked() 直接启动
        │
        └─ 有延迟或 pre_start
                │
                ├─ 当前正在运行 ──► 先 set_output(0)，记录 stop_timestamp_ms
                │
                └─ 进入 PENDING，保存 pending_speed_ref / pending_target_state
                        │
                        ▼（每 10ms tick）
                判断 elapsed(stop_timestamp_ms) >= post_stop_delay_ms
                        │
                        ▼（锁外）
                调用 pre_start_cb(motor_id, speed_ref, ctx)
                        │
                        ▼（锁内）
                motor_apply_pending_start_locked() → HOLD / MOVE
```

**已在 PENDING 时再次下发命令**：仅更新 pending 参数，**不重置**延迟计时。

**从未运行过**（`stop_timestamp_ms == 0`）：tick 下一拍即视为延迟已满足。

### 5.3 pre_start 回调约定

- 每个 `motor_id` 仅允许注册一个回调，重复注册覆盖旧值
- 在 tick 线程、**释放 `s_mutex` 后**调用，禁止长时间阻塞
- 返回 `SW_OK` 才继续启动；其它错误码中止启动并进入 `FAULT`
- 典型用途：共享 VFD 场景下，在 VFD 输出前完成接触器切换

## 6. 周期线程（motor_tick）

### 6.1 基本参数

| 参数 | 值 |
|------|-----|
| 周期 | `MOTOR_TICK_PERIOD_MS = 10ms` |
| 栈大小 | 16 KB |
| 启动 | `motor_tick_start()`，在 `bootstrap` 中于 `motor_init()` 之后调用 |

### 6.2 单拍流水线

```text
┌─ 加锁区一 ─────────────────────────────────────────────┐
│  prepare：编码器软状态更新 / 调度 HW 任务 / 识别 PENDING │
└────────────────────────────────────────────────────────┘
         ↓ 解锁
┌─ 无锁区（可阻塞 IO）──────────────────────────────────┐
│  编码器 HW 读写 / VFD 电流与状态采样 / pre_start 回调    │
└────────────────────────────────────────────────────────┘
         ↓ 加锁
┌─ 加锁区二 ─────────────────────────────────────────────┐
│  写回编码器 / 应用 VFD 故障 / 启动 PENDING / 收集完成事件 │
└────────────────────────────────────────────────────────┘
         ↓ 解锁
┌─ 无锁区 ───────────────────────────────────────────────┐
│  触发 motor_done_cb_t 完成回调                           │
└────────────────────────────────────────────────────────┘
```

**两次加锁的原因**：HW IO 与回调必须在无锁下执行，避免阻塞其它 API 调用方；状态变更必须在锁内保证原子性。

### 6.3 运动完成判定

仅对 `MOTOR_ACTION_MOVE` 且在 `MOVE` / `MOVE_POS` / `MOVE_TIME` 状态下评估。按优先级依次检查：

| 条件 | 结果 |
|------|------|
| 限位触发（`at_fwd_limit` / `at_rev_limit` 与方向匹配） | 完成，`SW_OK` |
| `MOVE_POS`：编码器位置到达目标 | 完成，`SW_OK` |
| `MOVE_TIME`：elapsed ≥ `move_time_ms`（扣除暂停时长） | 完成，`SW_OK` |
| elapsed ≥ `timeout_ms`（非 FOREVER） | 完成，`SW_ERR_TIMEOUT` |

完成后调用 `motor_finish_locked()` 停止电机；若配置了 `motor_done_cb_t`，在锁外回调上层。

## 7. 编码器子系统

### 7.1 后端类型

| 类型 | 说明 |
|------|------|
| `MOTOR_ENCODER_NONE` | 无编码器 |
| `MOTOR_ENCODER_COUNTER` | 硬件脉冲计数板，需 `read_hw_pulse` / `clear_hw_pulse` |

### 7.2 计数逻辑

- 仅在 `MOVE` / `MOVE_POS` / `MOVE_TIME` 状态下开启软计数（`encoder_counting`）
- 每 tick 读取 HW 计数器增量，按 `stored_dir` 累加到 `encoder_pos`
- 停止后延迟 1s 结束计数窗口

### 7.3 清零

- 对外接口：`motor_clear_encoder(id)`，在无锁区执行 HW 清零（最多重试 3 次，间隔 2ms）
- 零位传感器：连续 `encoder_zero_confirm` 次检测到零位后，自动调度 HW 清零任务

### 7.4 异常检测

在 `encoder_err_check_ms` 周期内，对运动态电机检查：

| 异常 | 条件 | 行为 |
|------|------|------|
| 计数跳变 | 单次周期增量 > `encoder_jump_threshold` | 记录 WARN，置 `encoder_err_reported` |
| 计数不变 | 连续 `encoder_err_threshold` 次位置无变化 | 记录 WARN，置 `encoder_err_reported` |

当前编码器异常仅记录日志，不自动进入 `FAULT`（可后续扩展）。

## 8. VFD 监测子系统

### 8.1 采样合并

多台电机可能共享同一 VFD 实例。监测层按 `motor_monitor_source_t` 合并采样任务，每个 VFD 源每 tick 只读一次电流与状态字：

| 源 | 关联电机 |
|----|----------|
| `MOTOR_MON_SRC_VFD_GANTRY` | `MOTOR_GANTRY` |
| `MOTOR_MON_SRC_VFD_BRUSH` | `MOTOR_BRUSH` |

### 8.2 故障判定

仅在 `motor_is_running_state()` 为 true 时生效；启动后 `current_check_delay_ms` 内不做电流判定。

| 故障类型 | 条件 | 确认时间 |
|----------|------|----------|
| 过流 | `current > current_high_threshold` | 持续 `current_confirm_ms` |
| 欠流 | `current < current_low_threshold` | 持续 `current_confirm_ms` |
| 状态不一致 | 软件认为运行中，VFD 状态字 running 位为 0 | 持续 `MOTOR_VFD_STATE_CONFIRM_MS`（3000ms） |

任一关联电机触发故障后，**同一 VFD 源下所有运行中电机**一并进入 `FAULT`（`motor_apply_source_fault_locked`）。

### 8.3 电流查询

`motor_get_current(id)` 返回 tick 缓存的 `load_current`，单位 **0.1A**；未运行时返回 0。

## 9. HAL 端口接口

`hal_motor_ops_t` 定义于 `ports/hal/hal_motor_port.h`，由机型 wiring/setup 注册：

| 回调 | 用途 | 可为 NULL |
|------|------|-----------|
| `set_output` | 频率模式启停 | 否（VFD 项目必填） |
| `set_gear` | 挡位模式启停 | 是（无挡位则 `motor_hold_gear` 返回 NOT_SUPPORT） |
| `at_fwd_limit` / `at_rev_limit` | 限位查询 | 是 |
| `read_hw_pulse` / `clear_hw_pulse` | 编码器 HW 读写 | 是（无计数板时不使用） |
| `read_current` / `read_status` | VFD 监测 | 是 |
| `fault_reset` | 驱动层故障复位 | 是 |

## 10. 对外 API 汇总

### 10.1 生命周期

| API | 说明 |
|-----|------|
| `motor_init()` | 加载配置表，校验 HAL 已注册，初始化各电机为 IDLE |
| `motor_tick_start()` | 创建并 detach 10ms 周期线程 |

### 10.2 运动控制

| API | 适用 action_type | 说明 |
|-----|------------------|------|
| `motor_hold(id, speed_ref)` | HOLD | 频率模式持续运行 |
| `motor_hold_gear(id, gear)` | HOLD | 挡位模式持续正转 |
| `motor_move(id, speed_ref)` | MOVE | 频率模式持续运动 |
| `motor_move_gear(id, gear, fwd)` | MOVE | 挡位模式运动 |
| `motor_stop(id)` | 全部 | 立即停止，进入 IDLE |

### 10.3 状态与传感

| API | 说明 |
|-----|------|
| `motor_get_state(id)` | 查询当前状态 |
| `motor_is_running(id)` | 是否处于运行态（不含 PENDING） |
| `motor_get_pos(id)` | 编码器位置；无编码器返回 -1 |
| `motor_clear_encoder(id)` | 清零 HW 计数器与软位置 |
| `motor_at_fwd_limit(id)` / `motor_at_rev_limit(id)` | 限位查询 |
| `motor_get_current(id)` | VFD 负载电流缓存（0.1A） |

### 10.4 故障与回调

| API | 说明 |
|-----|------|
| `motor_fault_reset(id)` | 调用 HAL 驱动层复位（如 VFD RST 脉冲） |
| `motor_set_done_cb(id, cb, ctx)` | 注册运动完成回调（MOVE 类型） |
| `motor_set_pre_start_cb(id, cb, ctx)` | 注册延迟启动前的预动作回调 |

### 10.5 已实现但未公开的头文件接口

以下函数在 `motor.c` 中实现，**尚未写入 `motor.h`**，仅供模块内或后续扩展使用：

- `motor_move_pos()` — 位置运动（`MOVE_POS`）
- `motor_move_time()` — 定时运动（`MOVE_TIME`）
- `motor_pause()` / `motor_resume()` — 暂停与恢复
- `motor_reset_fault()` — 清除软件 FAULT 态（不调用 HAL）

## 11. 线程安全与调用约束

| 场景 | 约束 |
|------|------|
| 对外 API | 持 `s_mutex` 访问共享上下文 |
| `motor_done_cb_t` | 在 tick 线程、锁外调用；禁止阻塞 |
| `motor_pre_start_fn` | 在 tick 线程、锁外调用；禁止阻塞；失败则进 FAULT |
| `motor_set_done_cb` / `motor_set_pre_start_cb` | 无锁写注册表；与 tick 并发时以最后一次注册为准 |
| 编码器 HW 读写 | 在 tick 无锁区执行，可阻塞 |

## 12. 集成与启动顺序

```text
bootstrap
  ├── hal_motor_register(...)     ← 机型 wiring 注入 HAL 实现
  ├── motor_init()                ← 加载 m8_motor_table
  └── motor_tick_start()          ← 启动周期监测线程
```

上层接入示例：

- **侧刷**：`projects/m8/bindings/m8_mechanism_setup.c` 装配 brush 槽位，经 `hal_motor_exec_port` 下发 hold/stop
- **龙门**（M8 机型）：`projects/m8/domain/mechanism/gantry.c` 组合 `bidirectional_motion` 模式，经 `hal_motor_exec_port` 下发运动命令，不含报警依赖

---

## 13. 扩展指南

新增一台电机时，推荐步骤：

1. 在 `motor_id_t` 中增加 ID
2. 在 `m8_motor_table[]` 中补充一条 `motor_cfg_t`
3. 在 HAL setup 中注册对应的 `set_output` / IO / 编码器 / VFD 绑定
4. 若共享 VFD，在 `motor_get_monitor_source()` 中增加监测源映射
5. 在上层 `projects/*/domain/mechanism/` 组合 patterns 并封装语义化 API（避免业务层散落 motor ID）

---

## 14. 已知限制

1. 配置表当前硬编码引用 `m8_motor_table`，多机型共存时需后续抽象为编译期或运行时选型。
2. 编码器异常目前仅告警，不触发 FAULT。
3. `motor_move_pos` / `motor_pause` 等能力已实现但未对外暴露，上层暂无法直接使用。
4. `motor.c` 中 `motor_get_state()` 存在重复定义，后续应整理为单一实现。
