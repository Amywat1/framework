# 运行模式状态机规格说明

**版本**：v2.0  
**状态**：已落地（recovery / self_check 仍为最小桩；硬件在环时序待验收）  
**适用范围**：各类洗车机嵌入式控制软件的运行模式仲裁与状态协调  
**架构基线**：`domain-design.md` v0.7 §10–§13、`软件设计框架说明.md` §11  
**关键词**：OperationalMode、命令矩阵、模式转移、急停双通道、运营门控

---

## 1. 概述

### 1.1 设计目标

本文档定义整机**运行模式状态机**的领域契约，实现：

- **唯一权威**：同一时刻只有一种运行模式；所有外部指令经统一入口仲裁，不得绕过
- **命令可观测**：被拒绝的指令必须产出可上报、可测试的拒绝结果（含原因码）
- **安全关键路径可预期**：急停动力切断不依赖事件总线排队；模式切换与硬件停机解耦
- **业务规则可追踪**：MAJOR 服务完成原则、PostWash 评估、Recover 语义均可映射到明确转移规则
- **可枚举可测试**：命令权限矩阵与模式转移表可全覆盖单元测试

### 1.2 适用场景

本规格适用于满足以下特征的控制需求：

**多业务阶段整机仲裁**  
设备在空闲、洗车、手动维护、自检、异常、恢复等阶段间切换，各阶段对外命令权限不同。

**外部多入口统一指令**  
CLI、云端、仿真等来源的命令必须经同一网关仲裁，返回同步 ALLOWED / DENIED。

**安全事件与业务模式分层**  
报警等级、安全姿态（OK / WARNING / LOCKOUT）、运行模式三条轴独立；转移 guard 可查询报警状态，但不合并枚举。

**硬实时急停与软实时收敛分离**  
硬件急停要求在毫秒级发出动力切断指令；领域状态收敛与总线 flush 可在事件分发线程延后执行。

**不适用**：单机构点动控制细节（归属 DeviceControl）、云端协议解析（归属 adapters）、具体洗车步骤编排（归属洗车引擎）。

### 1.3 核心概念一览

```text
OperationalMode（运行模式，6 态）
  ├── 门控变量
  │     ├── estop_active      急停是否激活
  │     └── service_enabled   运营是否接单
  ├── 外部命令（Command）
  │     ├── 命令类型 cmd_type_t
  │     └── 权限矩阵 [命令 × 模式]
  ├── 模式转移（Transition）
  │     ├── 指令触发（EnterManual / Recover / …）
  │     └── 事件触发（WashSessionStarted / EStopTriggered / …）
  └── 流程确认
        ├── StartWash 两阶段
        └── wash_abort_cause_t

协作概念（不得升格为运行模式）
  ├── WashSession 生命周期
  ├── SelfCheckProcedure
  ├── RecoveryProcedure
  └── SafetyPosture（报警聚合）

急停双通道
  ├── 热路径：safety_cutout_execute（动力切断，≤5ms 目标）
  └── 延后路径：safety_deferred_stop（领域收敛 + flush）
```

## 2. 分层原则

运行模式领域分三层，各司其职：

| 层次 | 载体 | 内容 |
|------|------|------|
| **概念层** | `domain/command_gateway/` | `OperationalMode` 聚合：6 态枚举、命令矩阵、转移表、门控变量 |
| **协调层** | `application/` | 指令网关、事件桥接、流程编排、模式投影、急停延后停机 |
| **平台/绑定层** | `runtime/platform/`、`ports/`、`projects/*/bindings/` | 急停硬件读取、快速切断、机型 DO 列表、安全输出 flush |

**硬性约束**：

| 约束 | 说明 |
|------|------|
| 单写者 | `OperationalMode` 只由 `event_dispatch` 线程写入，**不需要 mutex** |
| 推模式事件 | 聚合内部状态变更后直接 `event_publish()`，不设拉取式事件队列 |
| 被动输入 | 聚合**不**订阅 `event_bus`；由 `op_mode_bridge` 调用 `op_mode_on_xxx()` 喂入 |
| 热路径隔离 | `safety_thread` **不**调用 `op_mode_on_xxx()`，只发布 `EVT_HW_ESTOP_ON/OFF` |
| 项目差异下沉 | 机型 DO 列表、急停极性、安全输出表由 bindings 强符号覆盖，领域层不得硬编码机型名 |

## 3. 运行模式（OperationalMode）

### 3.1 语义

运行模式回答：**设备当前在做什么业务？允许哪些外部命令？**

整机由 `OperationalMode` 聚合唯一持有，不得维护平行的 `device_fsm` 或应用层状态镜像。`dev_ctx.operational_mode` 等为**只读投影**，由 `mode_projection` 在模式变更后写入。

### 3.2 模式枚举

固定 **6 态**，不含过程态：

```text
IDLE / WASHING / MANUAL / SELF_CHECK / EXCEPTION / RECOVERING
```

对应 C 类型：`operational_mode_t`（`domain/command_gateway/operational_mode.h`）。

### 3.3 不得作为运行模式的概念

| 概念 | 正确归属 |
|------|----------|
| 安全归位中 | `RecoveryProcedure` 或急停释放后的内部步骤 |
| 完整归位中 | `HomingProcedure`（MANUAL / EXCEPTION 下的维护用例） |
| 运营关闭 | `service_enabled` 布尔门控，不是模式 |

### 3.4 与安全姿态的分层

| 层次 | 模块 | 回答问题 |
|------|------|----------|
| 运行模式 | `OperationalMode` | 允许哪些命令？业务阶段？ |
| 安全姿态 | `AlarmRegistry` + `SafetyPosture` | 是否存在阻断性故障？ |
| 物理安全位 | `DeviceControl` | 各机构是否已到安全位置？ |

过程态（Recover 步骤、安全归位步骤）由应用服务内部状态机承载，**进入 / 退出**时才切换运行模式。

## 4. 门控变量

### 4.1 语义

门控变量影响命令附加条件与转移 guard，由聚合持有，投影到 `dev_ctx`。

| 变量 | 类型 | 语义 | 影响 |
|------|------|------|------|
| `estop_active` | `bool` | 硬件急停是否激活 | `Recover` / `StartSelfCheck` 的 CONDITIONAL 附加条件；清除后**不自动**回 IDLE |
| `service_enabled` | `bool` | 运营是否接单 | `StartWash` 前置条件；`StopOperation` / `ResumeOperation` 只切换此变量 |

### 4.2 约束

- `StartWash` 前置：`mode == IDLE && service_enabled && !estop_active`
- `StopOperation` / `ResumeOperation` 不改变 `current_mode`
- `estop_active` 由 `op_mode_on_estop_triggered/cleared()` 维护；一般 CRITICAL 报警**不得**误置此标志（见 §9）
- 云端可组合上报：`mode=IDLE, accepting_orders=false`

## 5. 外部命令（Command）

### 5.1 语义

所有外部指令（CLI / 云端 / 仿真）经 `command_port.inject()` 进入 `command_gateway`，由聚合命令矩阵裁决。

### 5.2 命令类型

`cmd_type_t`（`ports/inbound/command/command_port.h`）：

| 命令 | 说明 |
|------|------|
| `CMD_START_WASH` | 启动洗车（两阶段确认，见 §7） |
| `CMD_STOP_WASH` | 中止洗车（`WASH_ABORT_MANUAL`） |
| `CMD_ENTER_MANUAL` | 进入手动维护模式 |
| `CMD_MANUAL_ACTUATOR` | 手动点动（须先 `EnterManual`） |
| `CMD_START_SELF_CHECK` | 启动完整自检 |
| `CMD_RECOVER` | 启动恢复流程 |
| `CMD_STOP_OPERATION` | 关闭运营接单（仅 `IDLE`） |
| `CMD_RESUME_OPERATION` | 恢复运营接单（仅 `IDLE` 且已关闭） |
| `CMD_HOME_DEVICE` | 设备归位（EXCEPTION 下允许） |

### 5.3 权限矩阵

维度：`[命令类型 × 当前模式]`。单元值：`ALLOWED` / `DENIED` / `CONDITIONAL`。

```text
指令                   IDLE  WASHING  MANUAL  SELF_CHECK  EXCEPTION  RECOVERING
─────────────────────────────────────────────────────────────────────────────────
StartWash               ✓     ✗        ✗       ✗           ✗              ✗
StartSelfCheck          ✓     ✗        ✗       ✗           ✓†             ✗
EnterManual             ✓     ✗        ✗       ✗           ✗              ✗
ManualActuator          ✗     ✗        ✓       ✗           ✓              ✗
AbortWash               ✗     ✓        ✗       ✗           ✗              ✗
Recover                 ✗     ✗        ✓†      ✗           ✓†             ✗
StopOperation           ✓*    ✗        ✗       ✗           ✗              ✗
ResumeOperation         ✓*    ✗        ✗       ✗           ✗              ✗
─────────────────────────────────────────────────────────────────────────────────
†  附加条件：estop_active == false
*  Stop/Resume 仅切换 service_enabled；Stop 要求 mode==IDLE，Resume 要求 mode==IDLE 且 service_enabled==false
```

**EXCEPTION 允许 StartSelfCheck**：用于异常停机后的诊断性自检；不自动清除 CRITICAL 报警；自检期间拒绝其他外部命令。

### 5.4 CONDITIONAL 校验顺序

1. 查命令矩阵：当前模式下 `ALLOWED` / `CONDITIONAL` / `DENIED`
2. `CONDITIONAL`：检查 `estop_active` 等附加条件
3. `StartWash` 额外检查：`service_enabled == true`
4. 返回 `op_command_result_t`；`DENIED` 时聚合发布 `CommandRejected`

### 5.5 指令注入规则

| 规则 | 说明 |
|------|------|
| 单写者 | `op_mode_handle_command()` 只在 `event_dispatch` 线程执行 |
| 同步回执 | `inject()` 入队后阻塞等待回执（带超时），不跨线程直接访问聚合 |
| 代际保护 | 每个等待调用方分配递增 `generation`，防止并发/超时请求覆盖回执 |
| 网关不做转移 | `command_gateway` 只编排调用顺序，不做模式转移决策 |

## 6. 模式转移（Transition）

### 6.1 语义

每条规则描述：`(from_mode, trigger, guard) → to_mode`。

`trigger` 分两类：

- **指令触发**：矩阵 ALLOWED 后，应用层执行副作用，在确认点驱动切换
- **事件触发**：`op_mode_bridge` 收到事件后调用 `op_mode_on_xxx()`

### 6.2 指令触发

| 触发 | 前置模式 | 守卫 | 目标模式 | 副作用 |
|------|----------|------|----------|--------|
| EnterManual | IDLE | — | MANUAL | 无 |
| StartSelfCheck | IDLE / EXCEPTION | estop 未激活 | SELF_CHECK | 启动 self_check_service |
| Recover | MANUAL / EXCEPTION | estop 未激活 | RECOVERING | 发布 RecoveryRequested |
| StartWash | IDLE | service_enabled && estop 未激活 | （见 §7） | 启动 wash_orchestrator |

### 6.3 事件触发

| 事件 | 前置模式 | 守卫 | 目标模式 | 说明 |
|------|----------|------|----------|------|
| WashSessionStarted | IDLE | — | WASHING | 会话创建成功确认 |
| WashSessionCompleted | WASHING | — | IDLE | 正常结束 |
| WashSessionAborted(MANUAL) | WASHING | — | IDLE | 用户主动中止 |
| WashSessionAborted(CRITICAL) | WASHING | — | EXCEPTION | 严重故障中止 |
| WashSessionAborted(STEP_TIMEOUT) | WASHING | — | EXCEPTION | 步骤超时 |
| PostWashAssessmentCompleted | IDLE | enter_exception=true | EXCEPTION | MAJOR 阻断下次服务（BR-14） |
| SelfCheckCompleted | SELF_CHECK | — | 见 §8.2 | 按完成时故障状态决定 |
| AlarmTriggered(CRITICAL) | 非 WASHING / 非 RECOVERING | — | EXCEPTION | 非洗车态立即异常 |
| AlarmTriggered(CRITICAL) | WASHING | — | （不变） | 由 WashSession abort 后确认 |
| AlarmTriggered(CRITICAL) | RECOVERING | — | （不变） | recovery 结束时强制 EXCEPTION |
| EStopTriggered | 任意 | — | EXCEPTION | 置 `estop_active=true`；已在 EXCEPTION/RECOVERING 则幂等 |
| EStopCleared | 任意 | — | （不变） | 仅 `estop_active=false` |
| RecoveryCompleted(IDLE) | RECOVERING | — | IDLE | 恢复成功 |
| RecoveryCompleted(EXCEPTION) | RECOVERING | — | EXCEPTION | 恢复失败或超时 |

### 6.4 中止原因（wash_abort_cause_t）

`WashSessionAborted` 必须携带显式原因枚举，禁止用隐式 bool 区分转移路径：

| 枚举值 | 语义 | 模式落点 |
|--------|------|----------|
| `WASH_ABORT_MANUAL` | 用户/网关主动中止 | IDLE |
| `WASH_ABORT_CRITICAL` | CRITICAL 报警 / LOCKOUT | EXCEPTION |
| `WASH_ABORT_STEP_TIMEOUT` | 步骤超时 | EXCEPTION |
| `WASH_ABORT_INTERNAL` | 内部错误 | EXCEPTION |

`command_gateway` 传入 `WASH_ABORT_MANUAL`；`emergency_handler` 传入 `WASH_ABORT_CRITICAL`。

## 7. StartWash 两阶段确认

### 7.1 语义

`StartWash` 不允许命令到达即切模式；须等 WashSession 真正进入 RUNNING 后才确认 `WASHING`。

### 7.2 阶段规则

| 阶段 | 触发 | 行为 | 模式 |
|------|------|------|------|
| 1 | `op_mode_handle_command(StartWash)` | 校验 IDLE + service_enabled + estop 未激活；返回 ALLOWED；调度 worker | 保持 IDLE |
| 2 | worker `engine_start` 成功 | 发布 `EVT_WASH_SESSION_STARTED` → `op_mode_on_wash_session_started()` | IDLE → WASHING |

启动失败：模式保持 IDLE，向调用方返回错误，**不**发布模式变更事件。RPC 回执 = worker 最终启动结果（等待超时 4.5s）。

### 7.3 约束

- `mode == WASHING` ⟺ 存在且仅存在一个 active WashSession（INV-01）
- worker 单次 load / manifest 校验；成功后**才**发布 `EVT_WASH_SESSION_STARTED`

## 8. 自检与恢复

### 8.1 Recovery（Recover）

**语义**：从 MANUAL / EXCEPTION 进入 RECOVERING，清除可清除报警并驱动机构到安全位置。

**约束**（BR-18、BR-19）：

- 进入 `RECOVERING` 后拒绝一切外部命令（BR-20）
- 急停报警由硬件决定，不得软件强制清除
- 并行驱动其余机构到安全位置；**龙门保持当前位置不动**
- 恢复过程中出现新 CRITICAL → 流程结束落 EXCEPTION
- 过程步骤不扩展运行模式枚举

**当前实现**：最小桩——仅 `alarm_core_reset_alarms()` 并按联锁态发布 `RecoveryCompleted`，不含并行归位。

### 8.2 SelfCheckCompleted 落点

落点**不依赖**从哪个模式进入，而依赖**完成时刻的故障状态**：

```text
SelfCheckCompleted 后：
  if 存在活跃 CRITICAL 报警 OR estop_active:
      → EXCEPTION
  else if 存在 blocks_next_service 的活跃 MAJOR:
      → EXCEPTION
  else:
      → IDLE
```

**当前实现**：最小桩——`self_check_service_start()` 仅根据 `estop_active` / 联锁态决定落点并立即发布完成事件，不含机构驱动。

## 9. 报警与运行模式协作

### 9.1 三条轴

| 轴 | 职责 | 模式转移 |
|------|------|----------|
| 报警等级 | 单条故障严重程度 | 见下表 |
| 安全姿态 | 活跃报警聚合 | 不直接改运行模式 |
| 运行模式 | 命令权限与业务阶段 | 本规格主体 |

### 9.2 报警等级 → 模式策略

| 等级 | WASHING 中 | 非 WASHING 中 |
|------|------------|---------------|
| CRITICAL | WashSession abort → Aborted(CRITICAL) | → EXCEPTION |
| MAJOR | 继续会话，记录 journal | 不立即改模式；会话后 PostWash 评估 |
| MINOR | 仅记录上报 | 仅记录上报 |

### 9.3 急停与 CRITICAL 分离

| 路径 | 事件 | 行为 | 触碰 estop_active |
|------|------|------|-------------------|
| 硬件急停（主） | `EVT_HW_ESTOP_ON/OFF` | `op_mode_on_estop_triggered/cleared()` | 是 |
| 急停报警（辅） | `EVT_ALARM_TRIGGERED/CLEARED(ALARM_ESTOP)` | 同上（幂等冗余） | 是 |
| 一般 CRITICAL | `EVT_SAFETY_LOCKOUT` | `op_mode_on_critical_alarm()` | **否** |

一般 CRITICAL（堵转、通信中断等）**不得**误置 `estop_active`，否则 Recover / StartSelfCheck 被错误拒绝。

## 10. 急停双通道（EStop）

### 10.1 语义

硬件急停分两条通道：**热路径**在毫秒级发出动力切断指令；**延后路径**在事件分发线程完成领域状态收敛与总线 flush。

≤5ms 目标 = 动力切断指令已发出（DO 缓冲 + VFD cutoff），**非**全域状态收敛。

### 10.2 触发与清除

**触发（estop = active）**：

| 序号 | 执行者 | 动作 |
|------|--------|------|
| ① | `safety_thread`（SCHED_FIFO，5ms 轮询） | `safety_cutout_execute()` → 发布 `EVT_HW_ESTOP_ON` |
| ② | `op_mode_bridge` | `op_mode_on_estop_triggered()` → EXCEPTION |
| ② | `emergency_handler` | `safety_deferred_stop()` |
| ③ | `sensor_poll`（~30ms） | `alarm_core` 记录 ALARM_ESTOP（诊断冗余） |

**清除（estop = inactive）**：

| 序号 | 执行者 | 动作 |
|------|--------|------|
| ① | `safety_thread` | 发布 `EVT_HW_ESTOP_OFF` |
| ② | `op_mode_bridge` | `op_mode_on_estop_cleared()` → 仅 estop_active=false |
| ② | `emergency_handler` | 安全归位（刷子回零） |
| ③ | `sensor_poll` | 清除 ALARM_ESTOP |

### 10.3 热路径约束

`safety_cutout_execute()`（项目层强符号，默认弱实现）**允许**：

- 关键运动/水路 DO：`do_set(false)`，不 flush
- 电机 `driver.cutoff()`（VFD stop + 继电器关断）
- `water_emergency_off()`：`atomic` 无锁请求

**禁止**：领域 mutex、`flush_outputs_now`、`water_all_off`、`project_assert_safe_outputs`。

### 10.4 延后路径约束

`safety_deferred_stop()`（项目层强符号）**允许**：

- `gantry_stop` / `brush_stop_all` / `water_all_off`
- `project_assert_safe_outputs()`（含 flush）

### 10.5 LOCKOUT 与急停共存

`EVT_SAFETY_LOCKOUT`（非急停 CRITICAL 聚合）：

- `wash_orchestrator_abort(WASH_ABORT_CRITICAL)`
- 若 `hw_estop_port_is_active()`：推迟安全归位到 `EVT_HW_ESTOP_OFF`
- 否则：立即安全归位

> **示例（M8，仅供参考）**  
> 热路径关键 DO：龙门/刷子正反转与高速、风机启动、全部水路阀、水泵/潜水泵、侧刷/顶刷动作、顶刷升降、电动推杆。  
> 绑定文件：`m8_safety_cutout.c`（热路径）、`m8_safety_deferred.c`（延后路径）、`m8_hw_estop.c`（原始 DI）。

## 11. 对外投影（Projection）

### 11.1 dev_ctx 快照字段

| 字段 | 来源 |
|------|------|
| `operational_mode` | `mode_projection` ← `EVT_OP_MODE_CHANGED` |
| `service_enabled` | `mode_projection` ← `EVT_OP_MODE_CONTEXT_SYNC` |
| `estop_active` | `mode_projection` ← `EVT_OP_MODE_CONTEXT_SYNC` |
| `safety_state` / `has_alarm` / `alarm_code` | `safety_supervisor`（不变） |
| `wash_mode` / `gantry_pos` | 洗车服务（不变） |

### 11.2 必须可观测的输出

| 输出 | 内容 |
|------|------|
| `CommandRejected` | command_type + reason + current_mode |
| `OperationalModeChanged` | from_mode + to_mode |
| `inject` 同步返回值 | ALLOWED / DENIED 即时反馈 |

## 12. 完整交互示例

> **示例（标准洗车 + 急停，仅供参考）**

```text
[初始] mode=IDLE, service_enabled=true, estop_active=false

1. 云端 StartWash
   → command_gateway: ALLOWED（仍为 IDLE）
   → wash_orchestrator: worker load + engine_start 成功
   → EVT_WASH_SESSION_STARTED → mode=WASHING

2. 洗车中 CRITICAL 报警（堵转，非急停）
   → EVT_SAFETY_LOCKOUT → wash_abort(CRITICAL) → mode=EXCEPTION
   → estop_active 保持 false

3. 维护人员 EnterManual → DENIED（EXCEPTION 不允许）
   → StartSelfCheck（estop 未激活）→ ALLOWED → mode=SELF_CHECK
   → 自检完成，故障仍在 → mode=EXCEPTION

4. Recover（estop 未激活）→ mode=RECOVERING → RecoveryCompleted(IDLE) → mode=IDLE

5. 洗车中按下硬件急停
   → safety_thread: safety_cutout_execute + EVT_HW_ESTOP_ON
   → mode=EXCEPTION, estop_active=true
   → emergency_handler: safety_deferred_stop（延后 flush）

6. 释放急停
   → EVT_HW_ESTOP_OFF → estop_active=false（mode 仍为 EXCEPTION）
   → emergency_handler: 刷子安全归位
   → 须 Recover 或故障消除后才能回 IDLE
```

## 13. 实现职责边界

运行模式领域声明「要什么」，代码负责「怎么协调」。

### 13.1 固化在实现中

| 职责 | 说明 |
|------|------|
| 6 态枚举与命令矩阵 | 表驱动，禁止散落 if-handler |
| 转移表解释器 | 指令触发 + 事件触发统一入口 |
| 单写者零锁模型 | `OperationalMode` 仅 `event_dispatch` 写入 |
| StartWash 两阶段 | 启动失败保持 IDLE |
| `wash_abort_cause_t` 显式编码 | 禁止隐式 bool 区分转移 |
| 急停/CRITICAL 分离 | `estop_active` 只由急停路径维护 |
| 热路径/延后路径分工 | 热路径禁止 flush 与领域 mutex |
| RPC 代际槽保护 | 防止并发 inject 覆盖回执 |

### 13.2 由项目层决定

| 职责 | 载体 |
|------|------|
| 急停 DI 极性与读取方式 | `hw_estop_port` 强符号（如 `m8_hw_estop.c`） |
| 热路径关键 DO 列表 | `safety_cutout_execute` 强符号（如 `m8_safety_cutout.c`） |
| 延后停机与安全输出 flush | `safety_deferred_stop` 强符号（如 `m8_safety_deferred.c`） |
| 急停报警码识别 | `op_mode_alarm_port_is_estop` 强符号 |
| recovery / self_check 机构驱动 | 应用服务项目扩展 |

实现不得硬编码机型分支；同一逻辑只依赖 ports 弱符号 + bindings 强符号覆盖。

### 13.3 代码落位（简要）

| 层 | 关键文件 |
|----|----------|
| domain | `operational_mode.{h,c}`、`op_mode_types.h` |
| application | `command_gateway.c`、`op_mode_bridge.c`、`mode_projection.c`、`safety_deferred_stop.c`、`wash_orchestrator.c`、`emergency_handler.c`、`recovery_service.c`、`self_check_service.c` |
| runtime | `safety_thread.c`、`device_safety_actuator.c` |
| ports | `hw_estop_port`、`safety_cutout_port`、`op_mode_alarm_port`、`command_port.h` |
